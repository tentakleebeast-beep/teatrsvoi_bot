# Прототипы Mini App

Здесь остаётся **одна** вещь — эталон текущей дизайн-системы. Всё остальное, на чём
строилась переделка (Ш-1…Ш-10 закрыты), перенесено в `docs/archive/prototypes/`.

| Файл | Статус |
|---|---|
| `ux2-mini-app.html` | **Действует.** Эталон дизайн-системы v2: токены, компоненты, раскладки экранов. Сверять новый экран с ним и с `docs/development/91-design-system.md`. |

## Чего здесь больше нет

`chat-menu.html`, `org-miniapp.html`, `telegram-miniapp.html`, `screens/*.png` и
`82-navigation-bottom-tabs.html` — макеты до переделки. Они лежат в
`docs/archive/prototypes/` и на них не опираются: хаб с плитками заменён четырьмя
нижними вкладками (`docs/development/92-navigation-model.md`), эмодзи в интерфейсе
запрещены (`docs/development/91-design-system.md` §2).

## Правило

1. Прототип, который перестал быть эталоном, переносится в `docs/archive/prototypes/`
   с пометкой в первой строке HTML-комментарием: `<!-- Архив. Заменён: ... -->`.
2. Живой прототип должен быть один (или явно перечислен в таблице выше), иначе новый
   человек не понимает, какой из них правда.
3. Эталон дизайна — документ, а не макет: при расхождении между `ux2-mini-app.html`
   и `docs/development/91-design-system.md` прав макет приводится к документу.
   Обратное (менять документ под макет) — решение заказчика, а не агента.
