# Прототипы Mini App

**Действующих макетов здесь нет.** 17.11.2026 `ux2-mini-app.html` перенесён в
`docs/archive/prototypes/`: он разошёлся с кодом — 25 экранов против 36, свои имена
классов (`row`, `btn`, `card`) вместо `.ui-*` и своя палитра (`--bg`, `--accent`) вместо
`--ui-*`. Макет, который «похож на систему», но собран не на её классах, эталоном быть
не может: сверять новый экран по нему — значит копировать расхождение.

## Где теперь эталон

| Что | Где |
|---|---|
| Токены и компоненты | `services/tool-api/app/static/webapp-ui.css` + справочник `/webapp/ui` (экран в приложении, а не файл) |
| Правила вида | `docs/development/91-design-system.md` |
| Все экраны как есть | `docs/reports/171-screens-atlas.html` — 36 снимков со стенда |
| Переходы между экранами | `docs/architecture/170-transition-graph.md` — граф собирается скриптом |

Эталон — код приложения и документ, а не картинка. При расхождении макета и
`docs/development/91` прав макет; менять документ под макет — решение заказчика, а не агента.

## Правило

1. Новый макет живёт рядом со своим документом: `docs/<группа>/<номер>-mockups/` с README
   (что показывает, по какому документу) — как `docs/development/162-mockups/`.
2. Макет, переставший быть актуальным, переносится в `docs/archive/prototypes/` с пометкой
   в первой строке HTML-комментарием: `<!-- Архив. Заменён: ... -->`. Не удаляется: по нему
   восстанавливают, почему решение было таким.
3. Живой макет в этой папке — только если он один и назван в таблице выше; иначе новый
   человек не понимает, какой из них правда.
