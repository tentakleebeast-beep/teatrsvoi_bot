## v0.8.0 — 08.11.2026

### Добавлено

- Роль «педагог» (`master`): права, дисциплины, чат и Mini App. Роль получает семь
  возможностей (`schedule.read.all`, `schedule.availability.self`, `schedule.slots`,
  `schedule.write`, `notes.write`, `files.access`, `participants.view`), связь с
  дисциплиной через `participant_discipline.relation='teacher'` и попадает в состав
  тренинга. Деньги, рассылка и админ-панель роли не даются (Э1,
  `docs/architecture/140`).
- Миграция `db/init/061_master_role.sql`: роль `master` в `participant` и
  `participant_role`, семь строк `rbac_role_capability`, справочник
  `v_participant_disciplines` и проверка `v_master_without_discipline`. Идемпотентна.
- Дизайн-ревью 30 экранов Mini App: `scripts/ui_review.py` (инвентарь из кода,
  А1–А10, JSON и Markdown), отчёт `docs/reports/142`, 53 снимка в
  `docs/reports/screens/` (Э2, `t_1d9df2f8`).

### Изменено

- Документация: регистрация приведена к коду — код кнопкой, роль `student` снята из
  документа (`docs/13`); роль `master` описана в `docs/architecture/140`; правила
  экранов и прав — `docs/91`, `docs/92`; инвентарь действий пересобран
  (`docs/reports/117`).
- Экран «Слоты»: 403 от `/webapp/slots/people` и `/webapp/slots/find` теперь говорит
  о праве, а не о сети: форма поиска скрыта, текст объясняет, у кого поиск есть.
- Экран «Деньги: операции»: без `budget.write` форма не рисуется, вместо неё —
  «Операции записывает организатор» и где смотреть записанное.
- Экран «Сверка листов»: право спрашивает `/webapp/nav`; без `budget.import` кнопка
  «Проверить» и счётчики скрыты, вместо них — слова о том, кто ведёт сверку.
- Экран «Рассылка»: 403 отличается от сбоя сети, форма и кнопка скрыты, текст —
  «Рассылка доступна администратору».
- Экран «Обратная связь»: `can_send` приходит данными из `/webapp/feedback/mine`;
  без `feedback.send` форма скрыта, состояние — «Обращения принимает организатор»;
  `POST /webapp/feedback` проверяет право на сервере.
- Экран «Заявки»: у роли без `participants.view` право проверяется до пустого
  состояния, «Принять» больше не главная кнопка в каждой строке — одна главная на
  экран.
- Шапка раздела: подпись вкладки больше не перетирает «‹» — селектор ограничен
  `.ui-tabbar`.

### Исправлено

- `/webapp/slots`, `/webapp/tx`, `/webapp/reconcile`, `/webapp/broadcast`,
  `/webapp/feedback`, `/webapp/admin/pending` и подпись вкладки: ложные сообщения о
  сети и формы без права убраны, отказы объясняются словами.
- Смоук и сверка по требованиям Э2: полный гейт зелёный (ruff, pytest 2542 passed,
  браузерные 304 passed, инварианты, реестры, deadcode, карты).

Схема БД: Alembic-голова — `061_master_role`. Миграция 062 (`files_studio_access`)
в релиз не входит: карта 16 ещё в ревью. Выкат требует накатить
`db/init/061_master_role.sql` до рестарта (repair-schema.yml).

## v0.7.0 — 08.11.2026

### Добавлено

- Сопоставление «имя в файле → человек» берётся из данных, а не из кода: `person_alias`,
  `person_key` и `display_name` из БД, а никнеймы, которых в БД ещё нет, — из локального
  `config/participant-names.yaml` (в git только пример). Импорт расписания, сверка
  занятости и разбор бюджета пользуются одним источником (`services/tool-api/app/participant_names.py`,
  `scripts/_people.py`).
- Сторож выгрузок рядом с отчётами: отчёт с дампом данных не попадёт в публикуемое дерево
  молча (план 129, Ш-01).

### Изменено

- Публикуемое дерево обезличено: имена участников, chat_id, адрес Google SA и календарные
  id заменены плейсхолдерами, дампы данных выведены в приватную историю (Ш-02, Ш-03).
- Витрина репозитория: README с нуля, LICENSE MIT, SECURITY (Ш-07).
- `docker-compose.yml`: том `gardata` создаёт compose с фиксированным именем, `external: true`
  снят — первый `docker compose up` на чистой машине больше не падает с «external volume
  not found». Обратная сторона: `docker compose down -v` теперь удаляет и этот том.
- Прод-операции живут только в приватном репозитории: `deploy.yml` есть лишь там,
  в публичном срезе остаётся `tests.yml`.

### Исправлено

- Подсказки категории бюджета по фамилии больше не зашиты в код (в обезличенном дереве они
  указывали в пустоту) — приходят из `category_hints` локального конфига.
- Вставка алиаса не падает на схеме без уникального индекса по `alias`.

Схема БД не меняется: Alembic-голова та же — `060_participant_role_revoked`. Обязательный шаг
выпуска — положить `config/participant-names.yaml` на сервер до рестарта: без `category_hints`
строки вида «5000 <фамилия>» перестанут попадать в «Гонорары и доли».

## v0.5.0 — 04.11.2026

### Добавлено

- Mini App, экран «Ещё»: строки раздела «Личное» приходят данными из `/webapp/home/data`
  (t_6d1789bb) — новый раздел больше не требует правки оболочки.
- Архив папки: потолок размера ZIP — `ZIP_MAX_BYTES` (по умолчанию 100 МБ). Выше потолка
  отказ `folder_zip_too_large` с текстом «скачивайте по файлам»; раньше папка на 200 МБ
  занимала 200 МБ в `/tmp` сервера.
- Схема БД: 053 — статья «Прочее (доход)» (свободный текст «получила 15000» больше не падает
  в расходную статью); 054 — корни общих папок и автоматические папки спектаклей на триггере базы.
- Служебное, не для участников: уведомления владельцу через боевого бота; диагностика
  показывает, куда Caddy проксирует `/webapp`, и все обращения за 20 минут; аудит строк
  бюджета и занятости на проде; чтение списка участников из базы для маппинга.

### Изменено

- Бюджет: второго подтверждения крупных сумм больше нет — крупная сумма идёт тем же путём,
  что обычная; бейдж и метки подтверждения убраны из интерфейса и подсказок админа.
- Файлы: квота личного места проверяется тем же запросом, что пишет (`insert ... select`
  плюс `for update` на строке участника) — два одновременных подтверждения больше не
  превышают место вдвоём.
- Mini App: один реестр разделов вместо пяти копий; поведение экранов то же.
- Скрипты: одна функция времени Самары в `_cli` вместо четырёх копий; базовая линия
  мёртвого кода 30 → 25 ключей.
- Бот: отказ tool-api на `/zip` доходит человеку словами сервера (413 → «скачивайте
  по файлам»), а не «папка пуста или недоступна».

### Исправлено

- Mini App: баннер «Сайт недоступен» больше не снимается ответом соседнего запроса
  (маяк `/webapp/boot`, тихий вход `/webapp/auth`). При 5xx и обрыве он остаётся на экране,
  «Повторить» — по нажатию. Это и был красный CI на `webapp` и `webapp-webkit`.
- Mini App: маяк `/webapp/boot` пишет поля одной строкой — переводы строк из запроса
  больше не рвут запись.
- Файлы: `Content-Disposition` собирается одним помощником во всех четырёх местах —
  имена с кавычками и переводами строк не ломают скачивание.
- БД: номера миграций 046/047 были заняты дважды — перенумерованы в 053/054, порядок
  применения по имени файла восстановлен.
- На сервере: участники печатаются по фактическим колонкам (`aliases` нет), дамп
  участников — SQL-файлом.

### Схема и совместимость

- Две миграции, обе аддитивные и идемпотентные: 053 (`insert ... where not exists`),
  054 (`create table if not exists` плюс триггер). Код v0.4.4 на новой схеме работает,
  поэтому откат предыдущим тегом базу не ломает.
- API обратно совместим, новых обязательных полей нет. Появилась одна переменная
  окружения `ZIP_MAX_BYTES` — необязательная, по умолчанию 100 МБ.
