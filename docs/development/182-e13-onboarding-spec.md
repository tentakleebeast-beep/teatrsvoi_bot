# 182. Онбординг E13: шаги, тексты и судьба `pending` (E13-2, спецификация)

Карта `t_0e5bafcf`. Основание — `docs/development/181` (ветка `wt/e13-onboarding-design`,
голова `42adcc0`, где V-116 решён вариантом «б»: код приглашения персональный).
База кода — та же голова. Исполнитель — E13-3 (`t_d1fe8a22`).

Документ доводит решения 181 до постановки: дословные реплики, точные пути и строки,
что удаляется, чем проверяется. Продуктовых решений сверх 181 здесь два, и оба названы
явно: §3 (тексты 181 §5 в части шага «выберите себя» устарели после V-116 и переписаны
дословно) и §7 (два вопроса владельцу, без ответа на которые админская половина
последовательности не сходится).

## 0. Что и зачем

Замер в карте: из 15 выпущенных кодов введены 7; знакомство заполнено у 2 из 12
и ни у кого полностью; 3 записи висят в `pending` и не могут войти. То есть люди
доходят до бота и отваливаются на девяти вопросах и на ожидании подтверждения.
Меняем три вещи: вход укорачивается до «код → знакомство из 2–3 вопросов → меню»,
заявок нет, оба текста (короткая инструкция и памятка `/help`) говорят правду о шагах.

## 1. Последовательность: что говорит бот на каждом шаге

### 1.1. Веток входа теперь две, а не три

Карта называла три ветки («педагог», «человек уже в базе», «новичок»). После решения
V-116 веток две, потому что запись человека существует **до** кода: код выписан на
конкретного человека (`invite_code.participant_id`), и «выбирать себя из списка»
и «называть себя» больше не нужно никому.

| Ветка | Условие | Что происходит |
|---|---|---|
| педагог без дисциплины | `participant.role = 'master'` и в `participant_discipline` нет строк | реплика о дисциплине, две кнопки, потом привязка |
| любой другой человек | запись есть и в ней уже всё, что нужно | привязка и знакомство сразу |
| повторный `/start` | `tg_chat_id` уже привязан | меню, знакомство не начинается |
| старый код | `invite_code.participant_id is null` | отказ с текстом «Этот код больше не действует…» (§4.4) |

## 2. `intro.py`: три обязательных шага и шесть за кнопкой

### 2.1. Два плана вместо одного

Сейчас `STEPS` — девять полей (`intro.py:20-21`), `build_plan` (`:137-156`) собирает
из них список «что спросить», и знакомство стартует **после** меню.

```python
#: Знакомство при входе: без этого человек не получает короткого имени.
ENTRY_FIELDS = ("name", "alias", "phone")
#: Дозаполнение по кнопке: всё необязательное.
FILL_FIELDS = ("birthday", "travel", "plays", "roles", "trainings", "manifest")


def build_entry_plan(profile: dict | None) -> list[str]:
    """Имя — если в записи одно слово; короткое имя — всегда; телефон — если пуст."""
    profile = profile or {}
    plan = []
    if len(" ".join(str(profile.get("name") or "").split()).split()) < 2:
        plan.append("name")
    plan.append("alias")
    if not profile.get("phone"):
        plan.append("phone")
    return plan


def build_fill_plan(profile: dict | None) -> list[str]:
    """Только пустые необязательные поля; заполненное не переспрашиваем."""
    profile = profile or {}
    empty = {
        "birthday": not profile.get("birth_date"),
        "travel": profile.get("travel_minutes") in (None, 0),
        "plays": not str(profile.get("plays") or "").strip(),
        "roles": not str(profile.get("roles_note") or "").strip(),
        "trainings": not str(profile.get("interests") or "").strip(),
        "manifest": not str(profile.get("ai_manifest") or "").strip(),
    }
    return [step for step in FILL_FIELDS if empty[step]]
```

Ключи профиля — ответ `GET /tools/profile/me` (`people.py:212-243`): `name`, `phone`
(пустая строка — нет телефона), `birth_date`, `travel_minutes`, `plays`, `roles_note`,
`interests`, `ai_manifest`. `STEPS` и `build_plan` удаляются; `next_step`, `question`,
`parse_step`, `build_patch`, `summary`, `RETRY`, `LABELS`, `FIELD`, `SKIP_WORDS` не меняются.

### 2.2. Короткое имя обязательно только при входе

`alias` в плане входа обязателен (181 §3.2, строка 6): на шаге `Intro.alias` кнопки
«Пропустить» нет, а ответ из `SKIP_WORDS` (`intro.py:91-94`) не пропускает шаг вперёд,
а повторяет вопрос: `Не понял имя. Напишите одно слово — как вас называть коротко.`
(`RETRY["alias"]`, `intro.py:45`). Технически это параметр `intro_ask(..., skippable=False)`
в `routers/intro.py:19-21`; в плане дозаполнения `alias` не встречается вовсе.

Выход из диалога остаётся всегда: любая кнопка меню (`keyboards.MENU_SURFACE`)
снимает состояние (`routers/intro.py:58-62`).

## 3. Два текста, дословно

Оба — константы, реализация их не сочиняет. Ниже — эталон; тест сверяет с ним посимвольно
(§6.2). В текстах нет `{`/`}`, эмодзи и разметки: сборка склеивает части `+`, а не `.format`.

### 3.1. Короткая инструкция (уходит в чат при выпуске кода)

```text
Театр-студия «СВОИ» — бот @teartsvoi_bot. Как начать

1. Код приглашения
Код выдаёт администратор: 8 символов, у каждого свой, вход по нему один, действует 7 дней. Код выписан на ваше имя: по нему открывается ваша запись, поэтому не передавайте его другим.

2. Откройте бота
Откройте @teartsvoi_bot и нажмите «Запустить». Бот попросит код — отправьте его одним сообщением. Если вы педагог, бот сначала предложит выбрать дисциплину: «Актёрское мастерство» или «Музыка».

3. Ответьте на знакомство
Как называть вас в боте коротко и телефон (имя бот спросит, только если в записи одно слово). Телефон можно пропустить. Потом бот покажет сводку — нажмите «Записать».

4. Готово: бот пришлёт меню
Кнопка «Меню» слева от поля ввода открывает приложение студии: внизу четыре вкладки — «Главная», «Время», «Деньги», и четвёртая «Ещё» (у администратора, организатора и педагога она называется «Управление»).

Позже можно дозаполнить профиль: день рождения, дорогу, спектакли, роли, тренинги, заметку помощнику — «Профиль» → «Дозаполнить профиль». Ночью бот молчит: тихие часы по умолчанию с 20:00 до 08:00, свои — «Главная» → «Личное» → «Уведомления» или командой /quiet 21:00-09:00. Если код не подошёл или бот не узнаёт вас — напишите администратору.
```

```text
1. Код приглашения
Код выдаёт администратор: 8 символов, у каждого свой, действует 7 дней, вход по нему один. Код выписан на ваше имя: по нему открывается ваша запись. Откройте @teartsvoi_bot, нажмите «Запустить» и отправьте код одним сообщением.
Если бот ответил не «код принят», причина в его словах:
— «Код не найден. Проверьте написание.» — опечатка; букв I, O и цифр 0, 1 в кодах не бывает.
— «Код устарел — попросите новый.» — прошло больше 7 дней.
— «Этот код уже использован.» — по нему уже вошли; нужен новый.
— «Этот код больше не действует — попросите администратора выпустить новый.» — код выпущен до перехода на персональные коды.
— «Слишком много попыток ввода кода. Попробуйте через час.» — три ошибки за час.
Роль бот не спрашивает: она стоит в вашей записи, её назначает администратор. Код администратора кодом не выпускается.

2. Повторный вход
Повторный /start сразу открывает меню: бот узнаёт вас по Telegram. Заново пройти знакомство — /intro.

3. Если вы педагог
Персональный код педагога сначала спрашивает дисциплину: «Актёрское мастерство» или «Музыка». Другую дисциплину ставит администратор в приложении: «Управление» → «Люди» → карточка человека → «Дисциплины».

4. Знакомство
Доступ открывается сразу после ввода кода: заявок нет и ждать нечего. Дальше — короткое знакомство: имя (если в записи одно слово), как называть вас коротко, телефон. Телефон видят только вы и сотрудники студии с доступом к составу — администратор, организатор, педагоги. Телефон можно пропустить; бот покажет сводку и запишет только после «Записать».
Остальное — день рождения, дорогу до студии, спектакли, роли, тренинги, заметку помощнику — можно дозаполнить позже: «Профиль» → «Дозаполнить профиль». Переделать знакомство — /intro.

5. Приложение
Кнопка «Меню» слева от поля ввода открывает приложение студии. Внизу четыре вкладки: «Главная», «Время», «Деньги» и четвёртая — «Ещё»; у администратора, организатора и педагога она называется «Управление».
Ночью бот молчит: тихие часы по умолчанию 20:00–08:00. Свои часы — «Главная» → «Личное» → «Уведомления» (общие часы студии у админа — ещё и «Управление» → «Уведомления») или командой /quiet 21:00-09:00, отключить — /quiet выкл.

6. Если что-то не работает
Обращение: «Помощь» → «Обратная связь» → «Не работает» — оно уходит администратору.
Если не приходит код или бот не узнаёт вас — напишите администратору студии.
```

### 4.2. Три заявки на проде: миграции данных нет

Скопом перевести `pending` в `active` — выдать доступ трём неизвестным записям без
проверки. Порядок:

1. до выката админ открывает «Заявки» (экран ещё есть) и по каждой записи решает:
   «Подтвердить» → `active` или «Отклонить» → архив. Три записи — три нажатия;
2. перед тегом — проверка `select count(*) from participant where status = 'pending'`
   = 0; это пункт чек-листа релиза, а не «потом», потому что после выката экрана нет;
3. если запись всё же осталась `pending`: админ выпускает ей персональный код, и
   привязка переводит её в `active` (`attach` ставит `status='active'`) — это и есть
   подтверждение, выраженное выпуском кода. Отдельного «подтвердить» не остаётся.

### 4.3. Персональный код: схема, API, старые коды

Миграция `db/init/069_personal_invite_code.sql` (одна на оба дела; реестр ревизий
65 → 66, голова `069`; ревизия — `scripts/gen_alembic_revisions.py`):

```sql
-- 069: код приглашения персональный + право registration.approve снимается.
-- Откат: alter table invite_code drop column participant_id; insert гранта обратно
-- (см. 008:63 для admin) — только вручную, автооткат данные не вернёт.
begin;
alter table invite_code add column if not exists participant_id bigint
  references participant(id) on delete set null;
create index if not exists invite_code_participant_idx on invite_code (participant_id);
delete from rbac_role_capability where capability = 'registration.approve';
commit;
```

`invite_code.role` и `discipline_code` **не** удаляются (на них смотрят старые строки
и аудит), но новые коды пишут `role` из записи, а `discipline_code` не пишут.

API выпуска (оба входа — экран и чат, если он останется по V-118):

- `InviteIn` (`api/admin.py:31-37`): вместо `role`/`discipline_code` — `participant_id: int`;
  `max_uses` принудительно 1 (персональный код одноразовый); `ttl_days` как есть;
  запись должна существовать, не иметь `tg_chat_id`, не быть `archived`/`blocked`;
  роль `admin` кодом не выдаётся (`admin.py:44-46` остаётся правилом, проверяется по записи);
  ответ — как сейчас: `code`, `expires_at`, плюс `participant_id` и `display_name`;
- `list_invites` (`:66-96`) отдаёт в строке `participant_id` и `display_name` — экран
  показывает, на кого выписан код;
- экран «Приглашения» (`pages/admin_invites.py`) получает выбор человека вместо выбора
  роли: поиск по людям без Telegram (тот же `rank`/`person_match`, что у `_search_candidates`),
  выбранный человек → `{participant_id: id, ttl_days: 7}`; в шторке кода — имя человека
  и роль; перевыпуск для того же человека разрешён (старый код станет недействительным
  сам: вход один).

Старые коды (`participant_id is null`): приниматься перестают (`code_not_personal`,
§1.3). Миграция не может выдумать владельца, поэтому в чек-лист релиза входит строка:
`update invite_code set expires_at = now() where participant_id is null and uses < max_uses`
— на замере в карте таких не больше восьми, админ перевыпустит.

### 4.4. Что осталось и названо

- **Утёкший персональный код** по-прежнему даёт вход — но теперь в запись того человека,
  на кого код выписан, а не в пустую запись с вымышленным именем. Чужой видит расписание
  и взносы этого человека. Видно и отзывается: `invite_code.used_by`,
  `participant.invite_code_id` в «Люди» (`admin.py:416-418`), архив/блокировка
  (`core.py:476-481`). Тексты (§3) поэтому не обещают «чужой код не подойдёт», а просят
  не передавать свой.
- **Дисциплина педагога**: если у записи её нет, спрашиваем на входе (шаг 3); если есть —
  не спрашиваем. Новых дисциплин не заводим (`keyboards.py:280-290` — две кнопки).

После V-116 запись человека существует **до** кода, а завести её негде: единственный
путь «напишите фамилию и имя» удаляется (§1.4), `POST /tools/participants/register`
удаляется вместе с ним; в Mini App «Люди» (`pages/admin_people.py`) карточка только
читается и правится, создания нет; `INSERT INTO participant` в коде остаётся только
у `bootstrap` админа (`admin.py:113-136`) и в одноразовых скриптах
(`scripts/import_finance.py`, `scripts/import_students_schedule.py`). То есть новичка
неоткуда взять — и это дефект дизайна, а не деталь реализации.

Варианты:

- **(а) экран «Приглашения» заводит человека** — в форме выпуска рядом с поиском кнопка
  «Человека нет в списке» → поля «Фамилия Имя» и роль → запись создаётся без Telegram
  (`status='active'`, `drive_folder` как у кандидатов) и код выписывается на неё.
  Один экран, ответ владельца «выбирает человека» расширяется на «или заводит»;
  +0,5 дня, `pages/admin_invites.py` + `create_invite`.
- **(б) раздел «Люди» получает «Добавить человека»** — создание отдельно от приглашений,
  приглашения только выбирают из списка. Чище по смыслу, но это второй новый элемент
  интерфейса (граница карты — «без новых экранов»); +0,5 дня.
- **(в) создание остаётся в боте у админа** — команда вида `/add Фамилия Имя роль`
  (+0,25 дня, новых экранов нет), но админская команда вне Mini App и вне меню —
  её никто не найдёт.

Рекомендую **(а)**: новичок и код появляются в одном действии, второго экрана нет.

### 7.2. V-118 — выпуск кода из чата при персональных кодах

Сегодня код выпускается и из чата: пункт панели «Выпустить инвайт-код»
(`keyboards.panel_rows`, `menu.py:340`) → `admin_router.send_invite` (`routers/admin.py:64`)
→ кнопки роли (`inv:role:*`, `:625`) → `POST /admin/invite {role}`. Роль без человека
не выпускается: персональный код требует выбора записи, а в чате её выбирать негде.

- **(а) убрать пункт из чата** — коды только в Mini App, где появится выбор человека
  (+0,1 дня; минус: админ, живущий в чате, теряет действие);
- **(б) в чате список людей без Telegram** → нажатие → код (0,5 дня: новое состояние
  и клавиатура, зато паритет с экраном);
- **(в) оставить как есть** — невозможно: `role` без человека противоречит §4.3.

Рекомендую **(а)** до первой обратной связи: экран уже есть, а чат — второй источник
одного действия.
