# 70. Препятствия: где агенту нужен человек

Журнал ситуаций, которые агент не может или не должен решать сам: правило мешает работе,
окружение не пускает, данные расходятся, нет доступа, нужно решение заказчика.
Ведёт агент сам; решение принимает и называет человек, агент записывает его дословно.

Связанные реестры: уроки — `docs/development/69-lessons.md`,
намерения — `docs/development/71-intents.md`. Проверка — `scripts/check_registers.py`.

---

## 1. Правила ведения

1. **Расхождение — сюда, а не в «подкрутку».** Если факты спорят друг с другом
   (код против документа, файл против БД), агент записывает препятствие и ничего не меняет
   в данных, пока человек не ответит.
2. **«Что пробовал» обязательно по смыслу:** что агент уже проверил, чтобы человек
   не повторял ту же работу.
3. **«Что нужно от человека» — один конкретный вопрос или действие.**
4. Закрывает запись агент, когда человек ответил: статус «решено» или «отклонено» и
   решение — с датой и, если есть, коммитом или файлом в обратных кавычках.
5. Если из препятствия вырос урок — ссылка на L-NNN в поле «Решение».

| Тип | Пример |
|---|---|
| правило мешает | инвариант или правило процесса не даёт сделать нужное |
| окружение | права macOS, упавший Docker, недоступный сервис |
| данные расходятся | итог файла не равен сумме строк; документ спорит с кодом |
| нет доступа | нет прав на календарь, таблицу, сервер |
| нужно решение | продуктовый вопрос к заказчику |

| Статус | Что требует проверка |
|---|---|
| открыто | поле «Решение» пустое (`—`) |
| решено | решение записано |
| отклонено | записано, почему не делаем |
