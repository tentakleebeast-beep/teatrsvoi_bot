# 151. Скачивание одного файла и «Скачать архивом» в Mini App (Б1, дизайн)

**Дата:** 09.11.2026
**Карта:** `t_668fbbdd` (Б1, изучение и дизайн). Дальше — спецификация, затем код.
**Ветка:** `wt/b1-download`, в `main` не слита.
**Область:** экран папки (`pages/files_folder.py`), выдача ссылки на один файл,
маршрут архива (`api/files.py`), поведение страницы при скачивании.
**Границы карты:** код не пишем, права не меняем, `folders.tree` не трогаем,
темы А (просмотр) и В (сетка) не трогаем.

---

## 1. Что и зачем

Два дефекта в одном месте, оба — на экране папки `/webapp/folder?id=N`.

1. **Чтобы скачать один файл, человек качает архив всей папки.** На экране папки
   единственное действие — «Скачать архивом» (`pages/files_folder.py:32`). Скачивания
   одного файла нет ни в строке списка, ни на экране файла. Владелец нажал его на папке
   из одного pdf — получил архив из одного файла.
2. **«Скачать архивом» уводит Mini App в чёрный экран, бот перестаёт отвечать**
   (скриншот 2; в карточке время 05.11 05:09 — по логу это 09.11 05:08:59, см. §2.2).

Обе беды — от одного решения: страница забирает архив `fetch`-ом в память и отдаёт
браузеру `blob:`-ссылку (`pages/files_folder.py:168–190`). Для WKWebView в Telegram это
не скачивание, а переход страницы на `blob:` — экран остаётся пустым.

Цель: скачивание одного файла без архива; архив — только когда он правда нужен;
нажатие не должно уводить страницу.

### 2.1. Что делает страница сейчас

`pages/files_folder.py:168–190`, функция `download()`:

```js
fetch("/webapp/folder/" + folderId + "/zip")
  .then(r => r.ok ? r.blob() : refusalText(r)...)
  .then(blob => { var link = document.createElement("a");
                  link.href = URL.createObjectURL(blob);
                  link.download = "папка-" + folderId + ".zip";
```

Ссылка живёт в памяти страницы, в разметку не вставляется. Помощника скачивания в

`tg` на странице есть (`layout.py` подключает SDK на каждой странице).

### 2.3. Опыт: что делает этот код в настоящем WKWebView с политикой Telegram

Страница повторяет `download()` один-в-один (fetch → blob → `a.click()`), сервер отдаёт
zip 1 МБ с `Content-Disposition: attachment`. WKWebView 390×844, политика навигации —
как в Telegram: разрешено всё, кроме `telegram.me` / `telegra.ph`.

Результат (`wkwebview_probe.swift`, 4.5 с):

```json
{ "webview_url": "blob:http://127.0.0.1:8792/85d232e3-…",
  "page_state": "{\"done\":false,\"blob\":0,\"err\":\"\",\"text\":\"\",\"html\":0}",
  "page_title": "", "with_download_attr": true }
```

Страница ушла на `blob:`-адрес, в ней **пусто** (`text`, `html` — ноль, заголовка нет).
Скачивания не произошло: файла нет, диалога сохранения нет. На светлой теме это белый
экран, на тёмной — чёрный; владелец видит чёрный.

Тот же опыт с **прямым переходом** на URL архива, без `blob:` (`location.href =
'/zip?mb=2'`): `webview_url: http://…/zip?mb=2`, `page_title: ""`, `mean_brightness: 1`,
`page_state_error: "A JavaScript exception occurred"` — страница снова пустая. Значит и
прямой переход внутри webview не скачивает: браузерная навигация верхнего уровня в
WKWebView умеет только показать документ, а zip показать нечем. Скачивает только
внешний браузер, куда ведёт `openLink`.

### 2.4. Исходник клиента Telegram-iOS: blob — это переход, а не скачивание

`submodules/WebUI/Sources/WebAppController.swift` (скачан из GitHub, 4 396 строк):

- `decidePolicyFor navigationResponse` (`:701–707`) — `.download` ставится **только**
  для файла с расширением `.pkpass`; всё остальное — `.allow`, то есть грузится в тот же
  webview;
- `decidePolicyFor navigationAction` (`:761–771`) — отменяются только `telegram.me` и
  `telegra.ph`, остальное `.allow`; `blob:` проходит в webview и заменяет документ;
- скачивание по URL клиент умеет отдельным путём `web_app_request_file_download` →
  `downloadFile(url:fileName:)` (`:1852`, `:3011`), и он требует серверной проверки
  `bots.checkDownloadFileParams` (`TelegramCore/…/PreparedInlineMessages.swift:49`),
  то есть URL должен быть «своим» для бота — публичный адрес хранилища
  `https://files.<домен>` под эту проверку не попадает.

Вывод из исходника: **любая навигация верхнего уровня в webview, включая `blob:`, — это
не скачивание, а подмена страницы.** Значит `a.click()` с `blob:`-адресом физически не
может ничего скачать в Telegram на iOS; он только убивает текущую страницу.

### 2.5. Оболочка рвёт запрос через 10 секунд

`static/webapp-shell.js:279–353`: `networkGuard` подменяет `window.fetch`, ставит
`AbortController` и `setTimeout(…, 10000)`, при обрыве — красный баннер «Сайт недоступен,
попробуйте ещё раз.» с «Повторить». Опыт `exp_shell_timeout.py` на настоящей странице
`/webapp/folder` и настоящей оболочке: архив 2 МБ, отдача 12 с → запрос оборван, на
экране баннер, файла нет (`zip_visible: true`, `banner_text: "Сайт недоступен…"`).
На медленной сети это второй, независимый путь к тому же результату — «нажал и ничего
не скачалось». 2.4 МБ на проде уложились в 0.57 с, поэтому у владельца сработал не
таймаут, а `blob:`-переход (§2.3).

### 2.6. Presigned-ссылка несёт `attachment`

`files_store.presigned_url` (`files_store.py:428–437`) ставит
`ResponseContentDisposition: attachment_header(name)`. Проверено на dev-хранилище
(`check_presign.py`, настоящий объект 1 169 163 Б):

```
status: 200
Content-Type: image/png
Content-Length: 1169163
Content-Disposition: attachment; filename="file.png"; filename*=UTF-8''Монолог%20Гамлета…
```

То есть готовая ссылка на один файл уже скачивает, а не открывает. Второй вид подписи —
`presigned_view_url` с `inline` — для просмотра.

### 2.7. Что уже есть в API

| Маршрут | Что отдаёт | Авторизация |
|---|---|---|
| `GET /webapp/files/{id}/view` (`api/files.py:662`) | presigned `inline`, 15 мин, аудит `file.view` | `webapp_actor`, `files.access` |
| `GET /webapp/folder/{id}/files` (`:502`) | список с `url` = presigned `attachment` на каждый файл | `webapp_actor`, `files.access` |
| `GET /webapp/folder/{id}/zip` (`:531`) | zip потоком, `Content-Length`, `attachment`; 413 `folder_zip_too_large` | `webapp_actor`, `files.access` |
| `POST /files/{id}/link` (`:149`) | presigned `attachment`, 15 мин, аудит `file.link` | `core.current` (сервисный токен, для бота) |

Ключевое: **ссылка на один файл с `attachment` уже выдаётся списком папки** — странице
не нужен новый маршрут, чтобы скачать один файл. Маршрут нужен только для свежей ссылки
по нажатию (подпись живёт 15 минут, а список открыт дольше).

### 2.8. Потолок архива

`DEFAULT_ZIP_MAX_BYTES = 100 * 1024 * 1024` (`settings.py:32`), в проде `ZIP_MAX_BYTES`
не задан — значит 100 МБ. `stream_folder_zip` собирает архив целиком во временный файл
(`files_store.py:800`) и при превышении бросает 413 с текстом «Архив больше N МБ —
скачивайте по файлам.» Отказ уже описан в каталоге (`docs/architecture/85:116`), и бот
его показывает словами (`tg-gateway/app/routers/files.py:515–530`).

## 3. Причина чёрного экрана — подтверждённый факт

Цепочка, каждое звено замерено:

1. владелец нажимает «Скачать архивом» → страница делает `fetch` zip (§2.1);
2. сервер отвечает 200 и 2.4 МБ за 0.57 с (§2.2), в логе после этого — тишина;
3. страница получает `blob:` и зовёт `link.click()`;
4. в WKWebView это **навигация на `blob:`**, а не скачивание: документ заменяется пустым
   (§2.3 — `text:""`, `html:0`, `webview_url:"blob:…"`);
5. клиент Telegram такую навигацию не перехватывает: `.download` только для `.pkpass`
   (§2.4).

Итог: экран пустой (на тёмной теме — чёрный), оболочка (токен, баннер, «назад») вместе
со страницей уничтожена, поэтому «бот перестал реагировать». Это не падение Telegram и не
нагрузка на сервер — это наша страница, ушедшая на `blob:`.

**Чем это НЕ является** (проверено, чтобы не лечить не то): не таймаут оболочки (2.4 МБ
пришли за 0.57 с), не 413 (статус 200), не память сервера (ответ отдан), не права
(`files.access` есть, статус 200).

## 4. Решения

### D1. Скачивание одного файла — кнопка в строке папки и в просмотре

- **Экран папки** (`pages/files_folder.py`, строка трека): третья цель в строке —
  кнопка «Скачать» (иконка ↓, 44×44), рядом со стрелками порядка. Нажатие на неё
  гасит всплытие, строка при этом не открывает файл.
- **Экран файла** (тема А, `docs/development/150` §3 D4) — там уже задумана вторая
  кнопка «Скачать файл». Механизм общий, маршрут один; Б1 его не переделывает.
- **Почему в строке, а не только в просмотре:** владелец качает один файл из папки.
  Через просмотр — два нажатия (строка → «Скачать»); из строки — одно. Просмотр
  остаётся для «посмотреть», строка — для «забрать».

### D2. Способ — `openLink` на presigned `attachment`, без `blob:`

Порядок нажатия:

1. `GET /webapp/files/{id}/link` → свежая presigned-ссылка с `attachment` (15 минут);
2. `tg.openLink(url)` — SDK отдаёт URL клиенту, клиент открывает его браузером телефона
   (Safari/Chrome), браузер скачивает файл;
3. вне Telegram — `window.open(url, "_blank")`.

Обоснование фактами:

- `blob:` в webview не скачивает (§2.3, §2.4) — путь исключён;
- `openLink` в этом приложении уже работает: экран файла открывает так pdf и картинки
  (`pages/files_file.py:127`, `docs/development/150` §3 D4);
- ссылка уже несёт `attachment` (§2.6), поэтому браузер скачает, а не откроет;
- `WebApp.downloadFile` (Bot API 8.0) не берём: клиент требует серверной проверки
  `bots.checkDownloadFileParams` для «своего» URL бота (§2.4), а хранилище живёт на
  отдельном домене — проверка не пройдёт; плюс это версия 8.0+, которой у части людей нет.

Цена компромисса: человек уходит из Mini App в браузер телефона. Файл остаётся в
«Файлах»/«Загрузках» Safari — это и есть цель. Альтернатива «скачать внутри Mini App»
недоступна без отдельного домена под бота.

### D3. Архив — показывать условно, а не всегда

| Папка | «Скачать архивом» | Что делает человек |
|---|---|---|
| 0 файлов | нет (как сейчас) | — |
| 1 файл | **нет**; в строке «Скачать» | одно нажатие → файл |
| ≥ 2 файла | есть | архив одним нажатием |
| ≥ 2 файла, сумма > 100 МБ | нет; строка «Архив больше 100 МБ — скачивайте по файлам» | по файлу из строки |

Почему так:

- папка из одного файла — архив бессмысленен: это ровно тот же файл плюс обёртка;
- сумма размеров уже известна странице из `GET /webapp/folder/{id}/files`
  (`size_bytes` каждого файла) — предупредить можно до запроса, без 413;
- серверный 413 остаётся: страница может ошибиться (файл заменили между запросами),
  и отказ должен быть словами, а не чёрным экраном.

### D4. Механизм архива — тоже `openLink`, а не `fetch`

Архив нельзя отдать браузеру прямой ссылкой на `/webapp/folder/{id}/zip`: маршрут
требует заголовка авторизации с токеном, а `openLink` открывает URL без заголовка. Поэтому
прямая навигация на zip без токена вернёт 401.

Два честных варианта, оба без нового расширения прав:

- **(а) архив уходит в чат.** `POST /webapp/folder/{id}/zip` → сервер сам отправляет
  архив боту в чат (`sendDocument`; этот путь уже работает командой `/zip`,
  `tg-gateway/app/routers/files.py:536–568`). Страница показывает «Архив отправлен в
  чат», человек забирает файл из чата. Ничего не ломается, токен в URL не попадает.
- **(б) одноразовая подписанная ссылка.** `POST /webapp/folder/{id}/zip` возвращает
  `{url, expires_in}` — ссылку с одноразовым токеном на 5 минут; `GET /webapp/folder/
  {id}/zip?t=…` принимает либо `Bearer`, либо этот токен. `openLink` открывает ссылку,
  браузер скачивает. Минус: токен попадает в query, а Caddy пишет `uri` целиком в лог.

**Рекомендую (а):** он не расширяет поверхность авторизации и переиспользует уже
существующий путь бота. Вариант (б) — если владелец хочет, чтобы архив скачивался
именно из Mini App, а не приходил в чат.

### D5. Что не трогаем

- Права: `files.access` и `_webapp_require` остаются как есть; новых прав нет.
- `folders.tree` не трогаем.
- Тему А (экран файла) не переделываем: «Скачать файл» там уже задумана (150 §3 D4),
  Б1 только даёт общий механизм.
- Тему В (сетка) не трогаем.
- Оболочку `webapp-shell.js` не трогаем: 10-секундный сторож остаётся; после D2 он
  перестаёт мешать, потому что zip больше не тянется `fetch`-ом в память.

## 5. Контракт (дизайн; код — следующая карта)

### 5.1. Ссылка на один файл

```
GET /webapp/files/{file_id}/link
    webapp_actor, files.access
    → { ok: true, url, expires_in: 900, name, size_bytes }
    → 404 file_not_found / file_not_uploaded
    → 410 file_cold_missing
```

Правило видимости — то же, что у `view` (`files_store.file_for_reader`), аудит
`file.link` с `via: "webapp"`. Ключ объекта наружу не отдаётся. Холодный файл
возвращается в горячий бакет перед выдачей (`cold.restore`).

### 5.2. Архив — вариант (а), рекомендованный

```
POST /webapp/folder/{id}/zip
    webapp_actor, files.access
    → { ok: true, sent: true, count, size_bytes }
    → 413 folder_zip_too_large   (тот же потолок, тот же текст)
    → 409 folder_empty
```

Сервер собирает архив и отправляет боту в чат тем же путём, что `/zip`.

### 5.3. Если владелец выберет (б)

```
POST /webapp/folder/{id}/zip  → { ok: true, url, expires_in: 300 }
GET  /webapp/folder/{id}/zip?t=<token>  → 200 zip / 401 / 413
```

Токен — одноразовый, 5 минут, подписан `WEBAPP_SECRET`, содержит `chat_id` и `folder_id`;
права проверяются те же, что у `Bearer`. Токен из query не пишется в аудит и в логи
приложения (Caddy пишет — это остаточный риск, принять или нет — вопрос владельцу).

### 6.2. Чего не происходит

- страница не уходит на `blob:` и не заменяется пустым документом;
- `fetch` архива в память не делается вовсе — значит 10-секундный сторож оболочки
  не может оборвать скачивание;
- ни одна цель в строке не меньше 44 px, высота строки 69/87 px не меняется.

## 7. Критерии приёмки (для спецификации)

К1. Экран папки: у каждой строки есть «Скачать» (44×44); нажатие не открывает файл и не
уводит страницу (проверка: `location.pathname` не меняется, `document` не пустой).

К2. Один файл: нажатие «Скачать» → `GET /webapp/files/{id}/link` → 200 → `openLink(url)`
(в стенде — `window.open`); в ответе `Content-Disposition: attachment`; второго запроса
`/zip` нет.

К3. Папка из одного файла: кнопки «Скачать архивом» нет вовсе (замер DOM).

К4. Папка из трёх файлов: кнопка есть; нажатие не создаёт `blob:` (замер: ни одного
`URL.createObjectURL` за сценарий), страница остаётся на месте.

К5. Сумма файлов > 100 МБ: кнопки архива нет, есть пояснение; каждая строка качает

## 8. Цена и риск

| Работа | Часы | Риск |
|---|---|---|
| `GET /webapp/files/{id}/link` + тесты | 2–3 | низкий: копия `view` с другой подписью |
| Кнопка «Скачать» в строке папки + замеры 390×844 | 2 | средний: место в строке при длинных именах |
| Архив вариант (а): `POST …/zip` → бот в чат + тесты | 2–3 | средний: зависимость от доставки бота |
| Архив вариант (б): одноразовый токен + тесты | 3–4 | выше: токен в query и в логе Caddy |
| Убрать `fetch`+`blob` со страницы | 0.5 | низкий |

Итого по рекомендации (D1–D4, вариант а): **6–8 часов** плюс живая проверка на iPhone.
