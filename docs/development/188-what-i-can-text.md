Что в этом не так (все четыре факта проверены чтением кода, не на глаз):

1. **Ответ — это меню, а не умения.** Строка `· {пункт} — {описание}` повторяет кнопку и её
   подпись. Пункт «Что умею» попадает в собственный ответ: `· Что умею — этот список`.
2. **Механика вместо пользы.** `· Участники — список людей; нажатие открывает профиль и тариф`,
   `· Мой профиль — анкета в окне`, `· Знакомство — дозаполнить день рождения, дорогу,
   спектакли, роли, тренинги, заметку помощнику` (103 знака). Первые два говорят, что
   произойдёт с экраном, а не что человек получит.
3. **Пустые обещания.** `· Админ-панель — участники, права, архив, бюджет, аудит, лист
   бюджета` перечисляет содержимое двери; `· Справка — подробная инструкция по вашей роли`
   дублирует название.
4. **Переопределения из конфига не работают.** Ключи `menu:` в `config/ui-texts.yaml` —
   `Расход`, `Доход`, `Найти окна`, `Мой профиль` — не совпадают ни с одной подписью
   `MENU_GROUPS` (`Расход и доход`, `Поиск окон`, …), поэтому правка файла ни на что не влияет
   уже сейчас. Это отдельная находка (§6, V-119).

**Про пункт «переход в люди из агента».** Такой строки в дереве нет: `git grep -i` по
`services/`, `config/`, `bot/` на `main` и на всех 30+ ветках и `refs/remotes` не находит ни
«переход в люди», ни «перейти к людям», ни «к человеку». Значит формулировка пришла не из
`MENU_HELP` — либо это ответ модели на свободный вопрос (у неё нет нашего списка), либо другая
сборка на стенде. Закрываем пункт не точечным удалением строки, а правилом: в ответе не
бывает механики, переходов и служебных слов (§3), и это проверяет тест (§5.4). Отдельный
вопрос о том, ограничивать ли свободный ответ модели, — V-120.

## 2. Решение

Ответ собирается не из меню, а из **таблицы «право → одна строка»** (`CAP_LINES`) с фильтром
по правам человека. Следствия:

- у роли не может появиться строка о праве, которого у неё нет, — фильтр и есть отбор;
- не может появиться строка о переходе или механике: в таблице таких строк нет, а тест
  запрещает служебные слова (§5.4);
- меню меняется — ответ не меняется; права меняются — ответ меняется сам;
- порядок один для всех и задан частотой (см. ниже), поэтому ответ читается сверху вниз
  «что делаю чаще всего → что реже».

Порядок — от частого к редкому, основание: `docs/development/93-cjm.md` §0 (актёр отмечает
занятость 1–2 раза в неделю, взносы — раз в неделю; организатор пишет трату ежедневно; админ
смотрит «что требует решения» утром и вечером) и шаги сценариев §1–§6. Поэтому первые четыре
строки — занятость, расписание, взносы, окна; управленческие — в конце.

Формат ответа:

```
Что умею:
· Отметить, когда свободен: дни и часы
...
(пустая строка)
Можно и словами: «что у меня завтра»
```

Заголовок и последняя строка — не возможности: это рамка (тест проверяет только строки `· `).
Групп и подзаголовков нет: они и создавали ощущение меню.

### 5.2. `services/tg-gateway/app/keyboards.py`

`help_text` (строки 223–247) заменяется целиком — отбор по правам, без групп и без `menu_groups`:

```python
def help_text(caps: list[str], ui_texts: dict | None = None) -> str:
    """Что умею — одна строка на право, порядок от частого к редкому (188).

    Строка видна, если её право есть у человека: набор строк не может разойтись
    с матрицей прав, а механики («нажатие», «окно», «переход») здесь нет вовсе.
    Подписи правятся в `config/ui-texts.yaml` (блок `capabilities`), умолчания — в
    `texts.CAP_LINES`: правка текста не требует релиза.
    """
    overrides = (ui_texts or {}).get("capabilities") or {}
    lines = [texts.HELP_TITLE]
    for code, default in texts.CAP_LINES:
        if code and not core.has(caps, code):
            continue
        lines.append("· " + (overrides.get(code) or default))
    footer = ((ui_texts or {}).get("help") or {}).get("free_text") or texts.HELP_FOOTER
    if footer:
        lines += ["", footer]
    return "\n".join(lines)
```

`menu_groups` не трогаем — она остаётся для меню и подменю. `MENU_HELP` после этого не
читает никто.

### 5.4. Тест-сторож: `tests/unit/test_help_capabilities.py`

`tests/unit/test_help_exhaustive.py` (проверял паритет меню и `MENU_HELP`) удаляется — его
предмет исчез. Новый файл, шесть проверок:

1. **каждая строка имеет право:** каждое непустое право из `CAP_LINES` есть в
   `rbac_capability` (читается из `db/init/008_rbac_capabilities.sql` либо из фикстуры прав
   ролей — как в `tests/unit/test_gateway_menu_rights.py`); пустое право разрешено ровно одной
   строке — анкете.
2. **все права разобраны:** множество прав всех четырёх ролей равно
   `{права из CAP_LINES} | CAP_LINES_SKIP`. Новое право в матрице без строки и без записи в
   `CAP_LINES_SKIP` роняет тест — молча не появится и молча не пропадёт.
3. **ни одной чужой строки:** для каждой роли каждый показанный код права входит в набор прав
   роли; для ролей admin/org/master/troupe ответ сверяется целиком с текстами §4 (дословно).
4. **нет механики:** в ответе любой роли нет слов «агент», «переход», «инструмент», «нажатие»,
