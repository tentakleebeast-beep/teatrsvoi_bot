# 12. Поведение бота: манифесты, формы, квоты, границы настройки

> **n8n выведен из контура (V-026, 01.11.2026).** Где ниже n8n назван частью контура или
> источником разбора свободного текста, читать: `POST /tools/route` в tool-api
> (`services/tool-api/app/router_llm.py`); воркфлоу, публичный вебхук и переменные `N8N_*`
> удалены из деплоя. История контрактов — `docs/archive/29-n8n-scenarios.md`.

Отвечает на вопрос «где что живёт»: что настраивается в Telegram, что в коде, что в `.md`.

---

## 1. Компоненты и ответственность

```
Telegram
   │ update
   ▼
tg-gateway (aiogram)  ← «руки»: сообщения, кнопки, формы, файлы, состояние шага
   │ intent/форма + контекст
   ▼
tool-api (FastAPI)    ← «правила»: права, данные, квоты, аудит, идемпотентность
   │ tool-вызовы
   ▼
n8n (сценарии + LLM)  ← «речь»: понимание свободного текста, формулировка ответа
   │
   ▼
Postgres / Google Sheets / Calendar / OpenRouter
```

| Компонент | Отвечает | Не имеет права |
|---|---|---|
| `tg-gateway` | формы, кнопки, FSM, файлы, отправка | решать про данные, ходить в Google |
| `tool-api` | RBAC, данные, квоты LLM, аудит, правила из `docs/architecture/11` | вести диалог, вызывать LLM |
| `n8n` | разбор свободного текста, генерация ответа, выбор инструмента | считать деньги, ходить в Postgres/Google напрямую |
| манифесты `.md` | тон, стиль, границы роли, личные настройки | содержать данные или цифры |

**Почему так:** формы и права должны работать без LLM (иначе бот встанет вместе с провайдером), а текст ответа должен меняться без деплоя кода (правится в n8n/манифестах).

## 2. Четырёхслойный манифест

Собирается на каждый запрос: `tool-api /tools/manifests/resolve` → готовый system prompt.

| Слой | Файл | Что задаёт | Может ли быть переопределён |
|---|---|---|---|
| 1 | `bot/manifests/SOUL.md` | роль бота, жёсткие запреты, приоритеты, границы | **нет** (запреты неизменяемы) |
| 2 | `bot/manifests/STYLE.md` | формат сообщений, длина, числа, даты, тон | только ужесточён ролью |
| 3 | `bot/manifests/roles/<role>.md` | возможности, табу, примеры для роли | личные настройки — в пределах роли |
| 4 | `bot/manifests/participants/<person_key>.md` | обращение, привычные формулировки (личных порогов нет — крупные суммы пишутся сразу, `docs/architecture/25` §4) | — |

Правила композиции:
1. Блок «Жёсткие запреты» из SOUL.md **всегда** последним в промпте — как напоминание.
2. Конфликт «роль vs личное» → личное побеждает **только** для стиля и предпочтений.
3. Конфликт «роль vs роль» невозможен: одна роль на человека, проверяется в `tool-api`.
4. Данные в промпт не попадают: только права, роль, формат и результат tool-вызовов.

Проверка композиции: `python scripts/compose_manifest.py --role org` (печатает промпт и хеш).

## 3. Формы: детерминированный вход

Каждый сценарий — это форма с известными полями. Форма не тратит токены и работает без LLM.

```
[расход]  Сумма: 3 000 ₽   Категория: Фото/видео   Дата: 28.10
          ✍️ Написать как удобно   [Записать] [Изменить] [Отмена]
```

### Правила форм
1. **Поля с дефолтами**: дата — сегодня, категория — по статье, способ — не указан.
2. **Свободный ввод всегда доступен** — кнопка «✍️ Написать как удобно» на каждом шаге.
   Свободный текст разбирает LLM, но результат приводится к **той же схеме формы**.
3. **Один экран = один шаг.** Максимум 4 кнопки.
4. **Черновик виден целиком** до записи; правка любого поля возвращает к форме, не к тексту.
5. **Форма → intent object** (одинаковый для обоих путей):

```json
{
  "intent": "budget.capture",
  "slots": {"amount": 3000, "category": "Фото/видео", "date": "2026-10-28",
            "counterparty": "Зайцев", "project": null},
  "missing": [], "confidence": 0.95,
  "source": "form | free_text"
}
```

6. Если LLM не смог — форма заполняется тем, что понял парсер правилами, остальное пусто и подсвечено.

### Обязательные формы MVP
| Сценарий | Поля формы |
|---|---|
| Расход / доход | сумма, статья, дата, проект, способ |
| Занятость | дата или диапазон, с/по, тип (занят/свободен/удобно) |
| Репетиция | дата, время, длительность, участники, место |
| Заметка | заголовок, текст, теги, проект |
| Поиск окон | длительность, участники, окно дат, ограничения |

## 4. Квоты AI на участника

### Модель
```
llm_policy (scope: role | participant)
  ├─ daily_requests, monthly_tokens, monthly_cost_rub
  ├─ model_allowlist, max_tokens_per_request
  └─ hard_stop (true) — при исчерпании бот переходит на формы без LLM
llm_usage (факт): participant, ts, model, tokens_in/out, cost_rub, request_id
```

Приоритет: `participant` → `role` → глобальный дефолт из `.env`.

### Учёт и остановка
1. Перед вызовом LLM `tool-api` проверяет остаток и **резервирует** оценку стоимости.
2. После ответа записывает фактические токены (из ответа OpenRouter).
3. Остаток = 0 → `hard_stop`: бот отвечает формами и шаблонами, LLM выключен для человека.
4. Раз в сутки агрегат сводится с биллингом OpenRouter (`/api/v1/generation`) — расхождение > 5% → алерт admin.

### Два способа жёстко ограничить деньги
| Способ | Плюс | Минус |
|---|---|---|
| Один ключ + внутренний учёт (рекомендую) | простая ротация, гибкие лимиты | лимит программный, при баге можно перерасходовать |
| Отдельный ключ OpenRouter на роль/человека | лимит на стороне провайдера, не обойти | много ключей, сложнее менять лимиты |

Решение: один ключ + внутренний учёт + `hard_stop`. Отдельные ключи заводим, если появится внешний подрядчик или платный доступ.

## 5. Что настраивается откуда

### 📱 Из Telegram и Mini App (данные, без деплоя)
- инвайт-коды и роли (admin)
- квоты AI по человеку/роли — настройка в админ-панели Mini App
- тихие часы и категории уведомлений: частные — в профиле Mini App, общие — в админ-панели
- справочник категорий и синонимов (`article_alias`) — дом «Управление → Разбор агента» в Mini App, чат — вход
- личные алиасы («Прачка» = аренда)
- состав участников, блокировка — Mini App «Люди», чат — вход

### 🧩 Код (не настраивается в чате)
- проверка прав и scope
- идемпотентность, аудит, hash-цепочка
- расчёт окон, дедупликация, реконсиляция с Sheets
- парсинг дат и сумм правилами
- квоты: резервирование и учёт
- формат intent object

### 📄 Манифесты `.md`
- характер, тон, стиль, структура ответа
- что роль может и чего не может **объяснить словами**
- примеры ответов (few-shot)
- личные предпочтения участника

### ❌ Не настраивается нигде
- жёсткие запреты (SOUL.md, слой 1)
- правило «факт только из tool-ответа»
- разделение доступа между людьми

## 6. Режим деградации

| Что упало | Поведение |
|---|---|
| LLM / OpenRouter | формы и простые команды работают, свободный текст → «не могу разобрать, заполните форму» |
| n8n | то же + `/notes`, `/schedule`, `/balance` по шаблонам |
| Google API | чтение из индекса с пометкой «данные на 19:40», запись откладывается в очередь |
| квота человека | формы + шаблоны, сообщение «лимит AI исчерпан, доступны формы» |
| Telegram | ничего не поделать, уведомления копятся и уходят после восстановления |
