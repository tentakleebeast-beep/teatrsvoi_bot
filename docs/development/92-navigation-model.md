# 86. Модель навигации Mini App

**Дата:** 31.10.2026
**Основано на:** разборе `docs/development/90-ui-review.md` (проблемы), дизайн-системе
`docs/development/91-design-system.md` (компоненты, вкладки).
**Заменяет модель хаба с плитками** из `docs/development/82` §3.2 в той части, что
касается входа в Mini App.

---

## 1. Решение и почему

**Четыре нижние вкладки, у четвёртой подпись зависит от роли:**

| Место | Актёр (в базе роль `troupe`) | Организатор / админ |
|---|---|---|
| 1 | Главная | Главная |
| 2 | **Время** | Время |
| 3 | Деньги | Деньги |
| 4 | **Ещё** (профиль, уведомления, обратная связь) | **Управление** (заявки, люди, деньги-настройки, система) |

Что это меняет по сравнению с хабом:

| Хаб из 82 | Вкладки |
|---|---|
| Первый экран — каталог из 13 плиток в 5 блоках | Первый экран — «что у меня сейчас»: требует внимания, ближайшее событие, два быстрых действия |
| Из любого экрана возврат только в хаб, затем поиск плитки | Переключение раздела — одно нажатие, положение вкладок не меняется |
| Нет счёта «сколько я нажимал» | До любого действия ≤ 2 нажатия от корня вкладки |
| Плитка = название + подсказка (мелкий текст) | Вкладка = одно слово, кнопка = глагол |

Почему не 5 вкладок: на 320 px пять подписей либо мельчают до 11 px (нарушает §2
дизайн-системы), либо обрезаются. Почему подпись 4-й меняется: позиция важнее слова —
мышца запоминает место; а слово должно называть работу, которую человек делает.
У актёра работы по людям и системе нет, и «Управление» для него было бы ложью.

**Словарь ролей.** В интерфейсе три роли и только эти три слова: **актёр** (тот, кого
в базе записывают ролью `troupe`, — студиец труппы), **организатор**, **админ**.
«Студиец», «труппа», «пользователь» в подписях не используются: роль в интерфейсе должна
совпадать со словом, которым люди называют себя вслух.

Почему не бургер: он прячет функции, и это уже происходило — админ-панель была
недоступна из Mini App (`84`, П-4).

## 2. Экраны вкладок

### 2.1. «Главная» — `/webapp/home`

Не каталог. Сверху вниз:

| Блок | Содержимое | Кому |
|---|---|---|
| Шапка | имя, роль словами, дата | все |
| **Требует внимания** | строки-действия со счётчиком: «2 заявки ждут решения», «1 обращение» — строки приходят из реестра разделов (`webapp_api.attention_rows`); строки про крупные суммы нет, счётчик снят 30.10.2026 (`docs/architecture/25` §4) | по правам; если пусто — блока нет |
| Сегодня | ближайшее событие (время, название, место) или «на сегодня событий нет» | все |
| Моя занятость | «На этой неделе отмечено 4 из 7 дней» + кнопка «Отметить» | все |
| Быстрые действия | 2 кнопки: «Отметить занятость», «Записать операцию» (по праву) | все / по праву |
| Долг | «Взносы за октябрь: осталось 3 000 ₽» (только если есть долг) | все |

Правила:

- никаких плиток-каталога: всё, что не входит в эти блоки, живёт во вкладках;
- блоки «Требует внимания» — это действия, а не статистика: нажатие ведёт сразу к объекту;
- ни одного эмодзи, ни одной служебной фразы.

### 2.2. «Время» — `/webapp/week`

Подпись вкладки — **«Время»** (решение заказчика 31.10.2026): это раздел, где живёт
время человека — своя неделя и сводка. Экран внутри называется «Занятость»: вкладка
отвечает на «где это лежит», экран — на «что я тут делаю».

Один экран занятости вместо трёх (`/days`, `/my/sheet`, `/schedule`).

Куда ведёт «Время»: вкладка — `/webapp/week`; кнопка «Открыть неделю» в чате ведёт на
старый `/webapp/days`, который отвечает `301` на `/webapp/week` (§3); «Сводка» —
`/webapp/week/summary`, «Сетка месяца» — `/webapp/week/month`, вход только со сводки.

```
‹ неделя ›   26 октября — 1 ноября        [Моя | Сводка]
┌──────────────────────────────────────┐
│ Пн 26   занят 12:00–15:00        ›   │
│ Вт 27   занят весь день          ›   │
│ Ср 28   не отмечено              ›   │
│ Чт 29   свободен с 18:00         ›   │
│ ...                                  │
└──────────────────────────────────────┘
Отмечено 4 из 7 дней
[Отметить сегодня]                  ← одно главное действие
```

- **Строка дня — карточка.** Нажатие открывает нижний лист `.ui-sheet` (§4).
- Переключение недель — `‹`/`›` в шапке, **не** горизонтальный скролл.
- Сохранение — сразу при закрытии листа, без кнопки «Сохранить неделю».
  Результат — `.ui-toast` с «Вернуть» (10 секунд).
- Шаблон недели — одна строка-действие внизу листа, а не четыре кнопки на экране:
  «Заполнить по шаблону» → лист с предпросмотром и кнопкой «Заполнить».
- Кнопка внизу недели — **«Сохранить шаблон недели»** (З8): сохраняет шаблон из текущей
  недели, а не отметки. Отметки дня пишутся автосохранением, кнопки «Сохранить день» нет.
- Сегмент «Сводка» (`schedule.read.all`) — `/webapp/week/summary`:
  список дней с числами «свободны 7 из 9, не отметились: Валерий, Сэм»,
  нажатие на день — список людей с состоянием словами. Кнопка «Найти окно» → `/webapp/slots`,
  строка «Сетка месяца» — `/webapp/week/month`.
- **Сетка месяца** `/webapp/week/month` (З9, FR-H9) — только чтение: люди в строках,
  дни в колонках, состояние словом. Источник — Google-таблица «Расписание студийцы»,
  база — вторая сторона: расхождение показано списком и не правится. Месяц листается
  неделями `‹`/`›` (тридцать колонок со словами на 390 px не помещаются, а
  горизонтального скролла в приложении нет). Правка дня живёт в листе дня (§4).
- Личного «часового» листа на 30 дней больше нет: гранулярность «час» сохраняется
  внутри листа дня (`с 18:00 до 23:00`), а не тридцатью колонками.

### 2.3. «Деньги» — `/webapp/money`

| Роль | Что видно | Главное действие |
|---|---|---|
| Студиец, студент | «Мои взносы»: сколько начислено, сколько внесено, остаток, история по месяцам | нет (вносит организатор) |
| Организатор | сегмент **Операции** (по умолчанию) и **Мои взносы** | «Записать операцию» → `/webapp/tx` |
| Админ | то же + **Бюджет** (итоги месяца, статьи, план/факт) | «Записать операцию» |

- Список операций: строки «дата · категория · сумма», сумма справа табличными цифрами,
  расход — со знаком минуса и смысловым цветом, но **словом** в подробностях («расход»).
- «Мои взносы» в чате (`/dues`) и на экране — один месяц и один текст: строки строит
  сервер (`services/shared/dues.py`), оба интерфейса печатают их как есть (FR-B7, Д12).
- Нажатие на операцию — лист с подробностями (статья, кто записал, лист записан/нет).
- Форма операции (`/webapp/tx`) без `budget.write` не рисуется: экран говорит словами
  «Операции записывает организатор» и не показывает ни полей, ни кнопки «Записать» —
  иначе отказ приходит после заполнения формы. Право приходит в `/webapp/home/data`
  (`can_record`), страница остаётся публичной константой (docs/91 принципы 8 и 9).
- «Сверка листов» — не вкладка денег, а действие в «Управление → Система»: это редкая
  процедура (раз в неделю), не ежедневная работа.

### 2.4. Четвёртая вкладка: «Ещё» / «Управление» — `/webapp/more`

Один экран, два блока. Верхний — только для орг/админа.

**Управление** (орг/админ). Порядок строк — порядок реестра разделов
(`services/tool-api/app/webapp.py:SECTIONS`, §10), а не отдельный список:

| Строка | Право | Счётчик |
|---|---|---|
| Заявки | `registration.approve` | число pending |
| Люди | `participants.view` | всего активных |
| Приглашения | `registration.code.issue` | — |
| Права | `participants.manage` | — |
| Архив | `participants.manage` | — |
| Обращения | `feedback.triage` | число новых |
| Аудит | `audit.view` | — |
| Рассылка | `notify.send` (только у админа, П-6) | — |
| Сверка листов | `budget.import` | — |
| Сервисы | `admin.panel` | состояние: работают / внимание |
| Разбор агента | `admin.panel` | — |
| Общие уведомления | `admin.panel` | — |

«Разбор агента» — журнал последних сессий агента (вопрос, шаги, ответ, цена) и место, где
живёт словарь категорий: очередь новых имён (`category_candidate`) сейчас разбирает
`scripts/intent_report.py`, кнопки утверждения в экране ещё нет (Д9, Д10 в
`docs/architecture/25` §9.4). Лимиты AI человеку или роли (О6, FR-E6) обещаны тому же разделу,
но экрана и маршрута записи у них пока нет: политика лежит в таблице `llm_policy`. Это долг,
а не исключение из правила «дом + вход».

«Люди» — не только список: нажатие на человека открывает карточку с ролями, тарифом,
занятостью и долгом (FR-A10). Правка прав и тарифа живёт в той же карточке.
Начисление взносов — вложенный экран «Люди → Взносы» (`/webapp/admin/t/dues`, право
`budget.write`): кнопка «Начислить за месяц» с подтверждением и тарифы людей. Строки
в «Управлении» у него нет — вход с экрана «Люди», а бюджетное право не делает вкладку
управленческой (FR-B7, Д6/Д8).

**Личное** (все):

| Строка | Что |
|---|---|
| Профиль | анкета: имя, короткие имена, роли по спектаклям, время в пути |
| Уведомления | три типа событий и тихие часы; частные значения важнее общих |
| Заметки | личные и общие заметки: текст и теги; экран `/webapp/notes`, в чате — `/note` с подтверждением (кириллический алиас `/заметка` работает, но в меню его нет) |
| Обратная связь | отправить и посмотреть свои сообщения |
| Что умею | короткая справка (вместо раздела «Помощь» в чате) |

Экран «Обратная связь» (`/webapp/feedback`) без `feedback.send` не рисует ни тем
обращения, ни поля комментария, ни кнопки «Отправить» — состояние сказано словами
«Обращения принимает организатор». Права нет у мастера (`db/init/031`, `db/init/061`),
поэтому форма отдаётся скрытой и показывается только по явному `can_send` из
`/webapp/feedback/mine`; страница остаётся публичной константой, а `POST /webapp/feedback`
проверяет то же право на сервере (docs/91 принципы 9 и Б3, карта t_4f0c64d6).

Раздел «Права» перестаёт дублировать «Люди»: там только матрица роль → возможности
(чтение) и выдача точечных возможностей человеку через поиск.

### 2.5. «Сервисы» — `/webapp/services` (только админ)

Страница отвечает на вопрос «бот и мини-приложение вообще работают?» без терминала.

```
Всё работает                          5 из 6
Проверено 31 октября, 09:40 · каждые 5 минут

Бот                 tg-gateway · работает 4 дня        работает
Мини-приложение     tool-api · ответ 120 мс            работает
База данных         Postgres · 96 операций             работает
Разбор текста       роутер tool-api · ответ 09:38      работает
Календарь           Google · запись 30 октября         медленно
Таблица бюджета     Sheets · 1 строка не записана      внимание
```

Правила:

* состояние — **словом** («работает», «медленно», «внимание», «недоступен»), цвет только
  помогает; никаких графиков и процентов;
* у каждой строки видно, **когда проверяли** и на чём основан вывод (время ответа,
  последняя запись в лист, число незаписанных строк);
* «Проверить снова» запускает проверку и показывает, что она идёт;
* данных по правам нет: страница видна только с `admin.panel`, остальным её нет
  в списке «Управления» и сервер не отдаёт адрес.

Источник — те же проверки, что у `/health` и `scripts/check_services.py`, плюс состояние
очереди записи в лист; отдельного мониторинга не заводим.

## 3. Карта адресов

Старые адреса не ломаются: они отвечают редиректом на новый (301) — ссылки в боте,
в закладках и в чате живут дальше.

| Было | Стало | Тип |
|---|---|---|
| `/webapp/home` | `/webapp/home` (новое содержание) | тот же |
| `/webapp/days` | `/webapp/week` | редирект |
| `/webapp/my/sheet` | `/webapp/week` | редирект (часовой лист ушёл в лист дня) |
| `/webapp/schedule` (сетка месяца) | `/webapp/week/summary` (сам месяц — `/webapp/week/month`, вход со сводки) | редирект |
| `/webapp/search` (поиск людей) | `/webapp/admin/people` (поле поиска сверху) | редирект |
| `/webapp/dues` | `/webapp/dues` — «Мои взносы» как отдельный экран | тот же |
| `/webapp/slots` | `/webapp/slots` (вход из «Время → Сводка» и из чата) | тот же |
| `/webapp/tx` | `/webapp/tx` (вход из «Деньги» и из чата) | тот же |
| `/webapp` | `/webapp` — анкета | тот же |
| `/webapp/notifications`, `/webapp/feedback` | те же | те же |
| `/webapp/admin/t/{tab}` | `/webapp/admin/{tab}` | редирект, лента вкладок убрана |
| `/webapp/broadcast`, `/webapp/reconcile` | те же | те же |
| — | `/webapp/money`, `/webapp/more` | новые |

`/webapp/ui` остаётся справочником системы и доступен по прямой ссылке.

## 4. Лист дня занятия (вместо сетки)

Нажатие на строку дня открывает `.ui-sheet`:

```
        ▁▁▁
Занятость: суббота, 31 октября
[ Свободен весь день ]
[ Занят весь день    ]
[ Указать часы       ]

  с  [18:00]  до  [23:00]
  [После 18:00] [До 15:00] [Весь день]

Комментарий (необязательно)
[______________________]

[Отмена]            [Сохранить]
```

- Три состояния — три крупные строки-радио, а не 16 клеток.
- Часы — `.ui-range` (дизайн-система §4.5), шаг 30 минут, чипы-заготовки.
- Сохранение — сразу после «Сохранить»; лист закрывается; внизу `.ui-toast`
  «Сохранено: занят с 18:00 до 23:00 · Вернуть».
- Ошибки (конец раньше начала) — в листе, под полями, словами.

Почему лист, а не экран: день — одна мысль, экран для неё слишком велик, а
возвращаться к неделе надо сразу.

## 5. Админка без горизонтального скролла

| Было (`82` §9) | Стало |
|---|---|
| Лента вкладок с горизонтальной прокруткой | Вертикальный список разделов в «Управление» |
| Таблица «Имя / Роли / Статус / Действия» в 4+ колонки | Список строк: имя (16 px), под ним роли и статус (13 px), сумма справа; нажатие раскрывает подробности и действия |
| Действия в строке таблицы: select + input + 2 кнопки | Лист человека: роли, тариф, права, архив — по одной мысли на строку |
| «Действия проверяются на сервере теми же правами…» | Убрано: это фраза для разработчика |
| Счётчики только в хабе | Счётчики в строках «Управление» и на «Главной» |

Списки длиннее 20 строк — страницы по 20 с «Показать ещё», а не бесконечная простыня.

## 6. Возврат и «назад»

| Ситуация | Поведение |
|---|---|
| Экран вкладки | `BackButton` скрыт; выход — закрыть Mini App |
| Вложенный экран | `BackButton` и `‹` в шапке ведут на родителя (не всегда на «Главную») |
| Нижний лист | `BackButton` закрывает лист, а не экран |
| После сохранения | остаёмся на месте, показываем `.ui-toast` |
| После редиректа старого адреса | `history.replaceState`, чтобы «назад» не вернул в редирект |

| Личное: заметки | ✓ | ✓ | ✓ |

Права по-прежнему считаются на сервере; вкладка «Ещё»/«Управление» меняет подпись
по наличию хотя бы одного права из блока «Управление».

Прямой заход не по адресу (закладка, старая ссылка, роль без права) экран объясняет
словами с адресатом, а не оставляет кнопку, которая ответит 403: строку сводки
занятости прячет признак `summary` из `/webapp/nav`, кнопку «Проверить» на сверке
листов — признак `reconcile` («Сверку ведёт организатор», отчёт 142 §3 строка 10).

Две строки матрицы держатся не ролью, а решением владельца: рассылка (`notify.send`)
выдана только админу (П-6, `docs/reports/124` §1), файлы студии — только админу
(П-7, §9.1). Организатору они не показываются ни в чате, ни на экране; сами данные
закрыты тем же правом на сервере.

## 8. Чат и Mini App: одна терминология

| Мир | Название |

## 9. Файлы и папки (фича из `main`, переверстана 31.10.2026)

Экраны файлов пришли отдельной веткой работ (`docs/development/86-files-and-storage`)
и теперь живут на дизайн-системе v2: `/webapp/files` — место, загрузка и свои файлы,
`/webapp/folder?id=<номер>` — треки папки по порядку, проигрывание подряд, архив.
Разметка собрана каркасом `layout.page`, своих стилей — две строки (§7),
`<audio>` скрыт: играет строка списка, а не нативный плеер посреди экрана.

### 9.1. Кто видит

**Пока только администратор.** Правило держится в двух местах, оба — про данные
(решение П-7: файлы пока только у админа, права другим участникам — отдельной работой):

1. строку «Файлы студии» отдаёт `/webapp/home/data` в `more.personal`: запись `files`
   в реестре `app/webapp.py:SECTIONS` открыта по `admin.panel`. Страница — публичная
   константа, строку вставляет скрипт страницы уже после обмена `initData` на токен;
2. данные (`/webapp/files/*`, `/webapp/folder/*`) отвечают 403 без `admin.panel`.

Третьим местом был сам экран: получив 403 от `/webapp/files/list`, страница показывает
«Раздел для администратора» вместо пустого списка.

Спрятать кнопку и оставить открытым API — не защита. Когда файлы понадобятся актёрам,
снимаются ровно две проверки: `admin.panel` в записи реестра и `_admin_only` в маршрутах
данных.

Команды чата (`/files`, `/folders`, `/mkdir`, `/tag`, `/zip`, `/access`) закрываются тем же
`admin.panel`, что и экран: чат не второй интерфейс с другими правами (П-7, Ш-02).

Почему не серверная подстановка. До 31.10.2026 строку вставлял `home.with_files` в
разметку `/webapp/more`. После 05b7d2b страницы отдаются без `Authorization` — иначе
кнопка `web_app` получала 401, потому что Telegram не передаёт заголовок при навигации,
а токен приходит в `tg.initData` уже внутри страницы. Права на момент отдачи HTML
неизвестны, и вернуть подстановку — значит вернуть 401. `layout.with_caps` (подпись
вкладки в HTML) умер по той же причине и заменён запросом `/webapp/nav`. Поэтому строки
«Личного» идут тем же путём, что и «Управление»: реестр → ответ данных → отрисовка
на странице.

### 9.2. Место в навигации

«Ещё» → раздел «Личное» → **«Файлы студии»** — строка между «Профилем» и
«Уведомлениями»: это личный раздел, но не ежедневное действие, поэтому вкладку он
не занимает. Строку вставляет скрипт страницы после «Профиля», порядок тот же.
Шапка ведёт назад в «Ещё», из строки файла с папкой — в папку.

### 9.3. Что осталось

- Загрузка на iOS в WebView (`presign → PUT → commit`) не проверялась на живом
  телефоне: в стенде хранилища нет, интеграционные тесты файлов скипаются.
- Открыть раздел актёрам и организаторам — продуктовое решение, не техническое.

Правило на будущее: новая фича, приехавшая из другой ветки, получает вход в
навигации в том же коммите, где появляется её экран, — иначе экран есть, а люди
до него не доходят.

## 10. Один реестр разделов

**Решение:** «какой раздел видит человек с такой возможностью» описано в одном
месте — `services/tool-api/app/webapp.py`, кортеж `SECTIONS`. Запись реестра:

| Поле | Что значит |
|---|---|
| `key` | ключ раздела (он же имя маршрута экрана) |
| `caps` | возможности, любой из которых достаточно |
| `title` | название строки: «Заявки», «Люди», «Файлы студии» |
| `url` | адрес раздела |
| `caption` | подпись под названием |
| `group` | `management` (в «Управлении») или `personal` (в «Личном») |
| `count` | ключ счётчика для бейджа |
| `attention` | подпись в блоке «Требует внимания», пусто — раздел не сигналит |
| `page` | имя константы экрана в `app/pages/admin.py` — маршрут строится из записи |

**Что строится из реестра:**

| Место | Раньше | Теперь |
|---|---|---|
| Подпись 4-й вкладки (`layout.is_staff`) | отдельный список `MANAGEMENT_CAPS` | есть ли хоть один управленческий раздел |
| Список «Управление» (`api/webapp_api.py`) | 11 условий `if` с названиями и адресами | `management_rows` по реестру |
| Блок «Требует внимания» | два словаря в API | `attention_rows` по записям с `attention` |
| Строка «Файлы студии» (`api/webapp_api.py`) | HTML-константа `_FILES_ROW` и подстановка в разметку | `personal_rows` по записям группы `personal` → `more.personal` в ответе данных |
| Маршруты экранов (`pages/routes.py`) | словарь `ADMIN_TAB_PAGES` | `page_sections()` + `getattr(admin, section.page)` |

**Что реестр не делает.** Он отвечает только на вопрос «что показывать». Права на
данные проверяются на эндпоинтах и не ослабляются: скрытая строка — удобство, а не
защита. Адреса и экраны не переименовываются, редиректы со старых адресов остаются.

**`ADMIN_BLOCKS` остаётся отдельным.** Это блоки JSON-ответа панели **в чате**
(`/tools/admin/panel`): у них нет названий и адресов, свой порядок «как в панели
бота» и другая семантика — блок «заявки» открывает не только согласование, но и
`participants.manage`. Свести их к разделам Mini App значило бы либо поменять
поведение панели, либо завести поля «возможности для панели» и «порядок для панели»,
то есть вернуть ту же копию сбоку. `ADMIN_ACTIONS` — тоже не разделы: это действия,
каждое проверяется своим эндпоинтом.

**Как добавить раздел.** Одна запись в `SECTIONS` (для экрана — ещё и сама страница
в `pages/admin.py`). Проверяется тестом `tests/unit/test_webapp_sections.py`:
дописанная запись сразу появляется в «Управлении», в подписи вкладки и в маршрутах.
Тот же тест следит, чтобы в четырёх прежних файлах не завелась копия списка.
