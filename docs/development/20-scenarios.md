## S-01 Первый вход владельца
**Актор:** Виктор · **FR-A1** · **работает**

1. Отправляет `/start` боту.
2. `chat_id` совпадает с `ADMIN_CHAT_ID` → создаётся запись `admin`, статус `active`
   (`/admin/bootstrap`).
3. Ответ: имя, роли, число возможностей, главное меню кнопками.

**Ожидаемо:** доступ ко всему, вторая запись с тем же `chat_id` невозможна.

**Подтверждение:** код `start` и `bootstrap_admin`; автотеста на bootstrap нет. На первом
`/start` меню показывает «Возможностей: 1», потому что передаётся `["*"]`; после повторного
`/start` — 18.

## S-07 Расход через форму и права
**Актор:** актёр труппы · **FR-B1, A5** · **частично**

Кнопки «Расход» и «Доход» есть в постоянном меню у **всех** — меню статическое. Право
`budget.write` проверяется только на `POST /tools/budget/commit`: актёр пройдёт форму до конца,
но получит «Не удалось записать» (403). Отдельной кнопки «только для организатора» нет.

**Почему частично:** требование «остальным бот не показывает её в меню» не выполнено.

## S-08 Крупная трата
**Актор:** организатор · **FR-B5** · **снято 30.10.2026**

«перевели 350000 за ремонт помещения» → обычный черновик и обычная запись: расход 350 000 ₽
уходит в бюджет сразу, любой суммы.

**Почему снято:** расходы и доходы вносят только организаторы, второй подтверждающий никого
не защищает, а людей пугает и тормозит (`docs/architecture/25` §4). Предупреждения «Сумма выше
порога» в боте нет, флага `second_approval` нет ни в одной ветке разбора, очереди
`approval_request` тоже нет.

## Новые сценарии (27.10.2026)

### S-26. Окна для конкретных людей по ролям

```
«найди окна для Наташи и Сэма в Жизни насекомых на неделю»
→ «Кто участвует: Орлова Александра, Новиков Виктор
   1. вторник 24.11 19:00–21:00 (2 ч)
   2. среда 25.11 18:00–21:00 (3 ч)»
```
Роли разбираются по `person_alias` с привязкой к проекту (`docs/architecture/41`).
Если роль встречается в двух спектаклях и спектакль не назван — бот переспрашивает.

### S-27. Тренинг для максимального числа людей

```
«в какой день провести тренинг, чтобы пришло больше народу»
→ «Где больше всего свободных:
   1. сб 07.11 19:00 — свободны 7 из 9
   2. вс 08.11 12:00 — свободны 6 из 9»
```
Режим `max_free`: не требует «все свободны», ранжирует часы по числу свободных.

### S-28. Крупная трата пишется сразу (отменённое подтверждение)

```
«оплатили аренду 150000»
→ бот: «Записано: 150 000 ₽ · Аренда помещения · 31.10.2026.»
```

Подтверждение вторым администратором отменено 30.10.2026: операция пишется сразу, автор
и сумма остаются в аудите (`docs/archive/38-approvals.md` — история решения, `docs/reports/84` §2.4).

### S-29. Напоминание о незаполненной занятости

```
пятница 12:00 → «Неделя 23.11–29.11: отмечено 2 из 7 дней.
                  Крайний срок — пятница 18:00.»
```
Очередь `notification`, тихие часы 20:00–08:00, лимит 3 в час (`docs/infrastructure/36`).

### S-30. Пусто и свободно — разные вещи

```
файл: у человека зелёный весь ноябрь, пометка «Заполнено до: 30.11»
→ бот: «свободна весь месяц (по данным на 30.11)»
файл: зелёный, пометки нет
→ бот: «данных нет, надо подтвердить»
```
Правило в `docs/development/22` §7, чтение пометки — `parse_filled_until`.
