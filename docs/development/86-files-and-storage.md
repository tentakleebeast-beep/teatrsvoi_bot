## 0. Решение одной строкой

Текст, картинки и аудио живут в **Garage на VPS**, метаданные и права — в **Postgres**,
бот и Mini App кладут файлы по **presigned-ссылкам**, личные папки видит только владелец,
общие папки — дерево с корнями `Хозяйство / Соцсети / Спектакли / Документы`, музыка и шумы
спектакля живут **папками внутри спектакля**, агент раскладывает файлы **только с подтверждения**,
Google Drive остаётся **редактором офисных документов**.

---

## 1. Почему не Drive

`IDEA.md` §2.4 обещал персональные папки `TG_[chat_id]` на Google Drive. Это было невыполнимо
с самого начала:

| Факт | Следствие |
|---|---|
| Сервис-аккаунт не может создавать файлы (квота 0, `docs/infrastructure/09`) | Бот не может ни завести папку человеку, ни положить в неё файл |
| Drive — редактор, а не хранилище | Ссылки, версии, права и поиск в Drive не управляются ботом |
| Квота Drive — 15 ГБ на аккаунт человека | Аудио-библиотека спектакля некуда положить |

Что Drive делает хорошо и что там остаётся: таблицы и документы, **которые правят люди**
(«Расписание студийцев», «СВОИ 2025», финансы, контакты), см. `docs/development/14` §1.

**Три контура, одно правило:**

- **Drive — представление для людей.** Человек открывает, редактирует, печатает.
- **Garage — файлы как данные.** Бот хранит, находит, отдаёт, читает, раскладывает.
- **Postgres — истина о файлах:** что это, чьё, где лежит, кому видно, кто и когда трогал.

## 2. Факты, которые диктуют требования

| Ограничение | Значение | Что из него следует |
|---|---|---|
| Bot API: скачивание ботом | **20 МБ** ([core.telegram.org/bots/api](https://core.telegram.org/bots/api)) | Файл крупнее — только через Mini App |
| Bot API: отправка ботом | 50 МБ | Бот не может «вернуть» большой файл в чат |
| Диск VPS (`docs/infrastructure/75`) | 60 ГБ на Postgres + n8n + бэкапы + медиа | Под медиа реально **25–35 ГБ** |
| mp3 128 кбит/с | ≈ 1 МБ на минуту | 5-минутный трек ≈ 5 МБ, час записи ≈ 55 МБ |
| wav 16 бит / 44,1 кГц | ≈ 10 МБ на минуту | 5-минутный трек ≈ 50 МБ — уже «крупный файл» |
| Роли (`docs/architecture/02`) | `admin`, `org`, `troupe`, `student` | Права на общие папки — по ролям, без новых сущностей |

### 2.1 Арифметика, которую надо признать сразу

Выбрано «2 ГБ на человека». Активных людей 25–30 — это 50–60 ГБ против 25–35 ГБ доступных.
Квота на человека и физический потолок одновременно не выполняются.

Формулировка требования: **2 ГБ — верхняя граница на человека, действует и общий потолок.**
Что наступит раньше — то и останавливает. При 80% диска: алерт админу, предложение выгрузить
старое в холод, и только потом — расширение подписки. Квота без потолка — обещание, которое
система нарушит на 26-м человеке.

После уточнения сценария (музыка и шумы, а не многочасовые записи) 2 ГБ на человека — это
примерно **400 треков в mp3** или **40 в wav**. Для музыки спектакля хватает с запасом;
в wav — впритык, о чём предупреждаем при загрузке.

## 3. Принятые решения

| Ось | Решение | Следствие для кода |
|---|---|---|
| Где байты | **Garage на том же VPS** | Бэкап и диск — наша забота; код только под S3 API |
| Холод | **Второй том у того же провайдера**, расширение — докупкой подписки | Отдельный бакет на отдельном томе, не на том же диске |
| Типы в первом релизе | **текст, картинки, аудио** | Видео и архивы — явный отказ с понятным текстом |
| Аудио: сжатие | **Не сжимаем.** Читаем длительность и битрейт (`mutagen`), показываем размер | Нет перекодирования и потери качества; wav принимаем с предупреждением |
| Аудио: хранение | **«Плейлист» = папка внутри спектакля.** Отдельной сущности плейлиста нет | Дерево папок вместо двух таблиц; порядок — имя файла + `position` |
| Корни общих папок | **`Хозяйство`, `Соцсети`, `Спектакли`, `Документы`** (названия уточним при подключении сценариев) | Дерево произвольной глубины, корни — данные, не константы в коде |
| Кто создаёт общие папки | **`admin` и `org`** | Проверка на создание — по роли; удаление/переименование — admin или автор пустой папки |
| Кто видит личное | **только владелец**; админ — по явному запросу, с уведомлением владельцу и записью в аудит | Доступ к чужому файлу — событие аудита, а не свойство роли |
| Поиск | **Postgres FTS (русский) + теги**, без эмбеддингов | Правило «ML не используем» сохраняется |
| Теги | **Общий словарь** (справочник), не свободные строки у каждого | Таблица `tag`, поиск связный |
| Личные папки | **Бот создаёт автоматически** каждому участнику | Создание идемпотентно: при регистрации и при первом файле |
| Загрузка крупного | **Mini App → presigned PUT → Garage**, Telegram не участвует | Свой `telegram-bot-api` сервер не поднимаем |
| Квоты | 2 ГБ/чел (верхняя граница) + общий потолок + холод через 180 дней | Учёт места по человеку и по бакету |
| Автономность агента | **предлагает → человек подтверждает кнопкой** | Перемещение/переименование — черновик действия, не факт |
| Порядок | **1) хранилище и права, 2) аудио и папки спектаклей, 3) агент** | Каждый шаг заканчивается рабочим ботом |

### 3.1 Дерево папок: как это выглядит

```
Личное/<Имя>/                     ← создаёт бот каждому участнику
    Мои документы/  Фото/  Аудио/   ← «Мои», чтобы не путать с общим корнем

Общее/                            ← корни создаёт миграция 047, вложенность — admin и org
    Хозяйство/
    Соцсети/
    Документы/
    Спектакли/
        Пурга/                    ← папка привязана к project(kind='show')
            тексты/  партитуры/  заметки/  музыка/  шумы/
        Жизнь насекомых/ …
        Бунин/ …
```

Правила дерева:

1. **Глубина ≤ 5 уровней** — глубже никто не найдёт, а инвариант проверяется кодом.
2. **Папка может быть привязана к `project`** — тогда «материалы по спектаклю» собираются
   запросом, а не поиском по именам.
3. **Порядок треков** — числовой префикс в имени (`01 — выход Пьеро.mp3`) плюс `position`
   в `file_folder` для перетаскивания. Префикс важен: он переживает ZIP, флешку и чужой плеер.
4. **Пометка «выход Пьеро»** — часть имени файла, отдельного поля не заводим.

### 3.2 Что уже есть в БД и что с этим делаем

В `db/init/001_schema.sql` лежит заглушка, которую не использует ни один запрос
(только `TRUNCATE` в `scripts/reset_for_release.py`):

| Таблица | Что это сейчас | Решение |
|---|---|---|
| `file_object` (стр. 242) | `drive_file_id not null unique`, `uploaded_via in ('human_drive','human_telegram','bot')` | **Расширяем, не создаём заново:** `drive_file_id` → nullable, в `uploaded_via` добавляются `webapp` и `agent`, появляются `object_key`, `bucket`, `sha256`, `kind`, `deleted_at`, `cold_at` |
| `note` (стр. 228) | `title`, `body`, `tags text[]`, `scope`, `project_id` | **Остаётся как есть.** Заметка — не файл: она в БД и ищется FTS |
| `project` (стр. 65) | Спектакли и курсы (`show`/`course`/`training`) | К нему привязываются папки спектаклей |

Вывод: параллельную `storage_object` **не заводим** — иначе два источника истины о файлах.

### 3.3 Почему Garage, а не MinIO

Первая редакция этого документа рекомендовала MinIO. Решение пришлось поменять по факту,
а не по вкусу:

| Факт (проверено 29.10.2026) | Следствие |
|---|---|
| `docker pull minio/minio` → `pull access denied, repository does not exist` | MinIO удалил образы с Docker Hub в сентябре 2026 |
| `quay.io/minio/minio` с 24.09.2026 требует аутентификацию, анонимный pull → `unauthorized` | Второго публичного реестра нет |
| Комьюнити-версия осталась **только исходниками**, продукт переехал в коммерческий AIStor | Сборка из исходников, последний свободный релиз — с незакрытой уязвимостью CVSS 8.8 |

Проверено `docker pull` на машине разработки и живым прогоном:

| Образ | Доступность | Итог |
|---|---|---|
| `dxflrs/garage:v2.1.0` | OK (теги `v*`, `latest` нет) | **выбран** |
| `chrislusf/seaweedfs:latest` | OK | зрелый, но master + volume + filer + S3-шлюз — четыре компонента там, где хватает одного |
| `rustfs/rustfs:latest` | OK | проект 2025 года, истории и аудита мало |
| `minio/minio` | нет | снят с реестров |

Что важно для нас в S3-совместимости Garage (официальная таблица + живая проверка):
`PutObject`, `HeadObject`, `GetObject`, `ListObjectsV2`, multipart — есть; **presigned URL — есть**
(на них держится загрузка из Mini App, проверено: presigned PUT и GET возвращают 200).
Нет версионирования и ACL-политик: права у нас в Postgres, версионирование не требуется.
Есть `bucket set-quotas` — пригодится для общего потолка (FR-K15).

Отступление «код только под S3 API» (NFR-K6) именно это и окупило: смена провайдера — это
`STORAGE_ENDPOINT` в `.env`, а не переписывание загрузки.

### 3.4 Отступления от первой редакции требований

| Было | Стало | Почему |
|---|---|---|
| `ffprobe` для характеристик аудио | `mutagen` (чистый Python) | `ffprobe` — это пакет ffmpeg: +60–80 МБ в образ `tool-api` и установка на машине разработчика ради четырёх полей. Проверено на mp3, m4a, flac, ogg, wav: длительность и битрейт читаются, перекодирования нет |
| Плейлист — отдельная сущность | папка спектакля + числовой префикс имени | Решение заказчика (раунд 4): меньше сущностей, порядок переживает ZIP и флешку |
| Ссылка на файл одноразовая | 15 минут, без одноразовости | Presigned URL не умеет «один раз»; см. §9 п. 5 |

### 3.5 Кто видит файлы и что делает (Ш-08, V-039 (в))

Раздел «Файлы» — единственный дом, где до 04.11.2026 экран был закрыт, а чат открыт всем.
Правило П-7 (`docs/reports/124` §1) до 08.11.2026 было одно на весь дом: **файлы только
у администратора**, право — `admin.panel`. Решение владельца V-039 (в)
(`docs/reports/74-questions.md`) изменило это для экрана: **«Файлы студии» видят admin, org
и master**, право — `files.access`. Проверяется оно на сервере, а не спрятанной кнопкой;
роли без права экран отвечает словами («Раздел доступен администратору, организатору и
мастеру»), а не пустым списком (Б3). У `troupe` право снято миграцией
`062_files_studio_access.sql` — раньше оно лежало у него «на будущее».

Вход в раздел один — `files.access`; кого именно пускает **действие**, решает домен и
отвечает словами: `folders` — admin и org, `tags` и `file_access` — только admin. Чат
остаётся под `admin.panel` (П-7 не отменён для команд бота).

| Действие | Экран «Файлы» | Чат | Право | Обработчик |
|---|---|---|---|---|
| Ф1. Загрузить файл | `presign → PUT → commit` (`/webapp/files/*`) | присланный документ/фото/аудио → `/files/upload` | экран — `files.access`, чат — `admin.panel` | `files_store.upload_stream` → `save_committed` (один путь) |
| Ф2. Выдать доступ к личному файлу | блок «Доступ к файлу» (`/webapp/files/{id}/access`) | `/access <номер> <причина>` | вход `files.access`; выдаёт только `admin` — решает `file_access.request` | `file_access.request` |
| Ф2. Отозвать доступ | тот же блок (`.../access/revoke`) | `/revoke <номер>` | владелец файла или `admin` — решает `file_access.revoke` | `file_access.revoke` |
| Ф2. Кто открывал доступ | блок «Доступ к файлу» (`GET /webapp/files/{id}/access`) | `GET /files/{id}/access` | владелец файла или `admin` — общий `file_access.file_for_grants`; чужой закрытый файл — 404 | `file_access.grants_of` |
| Ф3. Утвердить тег | блок «Теги на утверждение» (`/webapp/tags/{id}/approve`) | `/tag-ok <номер>` | вход `files.access`; утверждает только `admin` — решает `tags.approve_tag` | `tags.approve_tag` |
| Ф4. Создать папку | «Папки» → «Создать папку» (путь через `/`) | `/mkdir Имя` или `/mkdir Спектакли/Пурга/шумы` | вход `files.access`; общие папки — `admin` и `org` (решает `folders.create`) | `folders.create` |
| Ф4. Переименовать папку | «Папки» → «Имя» | `/rename <номер> <имя>` | как у «Создать папку» | `folders.rename` |
| Ф4. Закрыть папку | «Папки» → «Закрыть» (два нажатия) | `/rmfolder <номер>` | как у «Создать папку» | `folders.remove` (файлы остаются) |
| Ф4. Порядок треков | стрелки на экране папки | `/order <номер> 3 1 2` | как у «Создать папку» | `folders.set_order` |
| Ф5. Скачать папку архивом | — (кнопка снята, V-052 а; по файлам — «Скачать» в строке) | `/zip <номер>` | чат — `admin.panel` | `files_store.stream_folder_zip` |
| Ф6. Открыть один файл | строка «Файлов» и «Папки» → `/webapp/file?id=N`; ссылка — `GET /webapp/files/{id}/view` | нет (чат отдаёт файл кнопкой `fl:<id>`) | `files.access` + видимость файла (`files_store.file_for_reader`) | `files_store.presigned_view_url`, `cold.restore`; аудит `file.view` |

**Ф6 — просмотр, а не прослушивание (А3, 09.11.2026).** До этой правки экран «Файлы» умел
только загружать и удалять: ни картинку, ни pdf в Mini App открыть было нельзя, а в папке
любая строка звала `play()` — pdf уходил в `<audio src>`, и человек «слушал» ноты. Теперь
вид файла решает поведение: `audio` играет (`<audio controls>`), `image` показывается
целиком в тёмной сцене, документ (pdf/docx/xlsx/pptx/odt/ods/rtf) и текст (.txt/.md/.csv)
показывают карточку и открываются в браузере телефона (`Telegram.WebApp.openLink`).
Внутри Mini App содержимое документов и текста не рендерится: офисных файлов webview не
показывает, а кодировку русских `.txt` страница не угадает (решение D4 в
`docs/development/150-miniapp-file-view.md`).

Ссылка на просмотр подписывается с `ResponseContentDisposition: inline` — по ней браузер
показывает файл, а не скачивает его; живёт 15 минут и выдаётся заново на каждое нажатие,
ключ объекта наружу не отдаётся. Холодный файл возвращается в горячий бакет до выдачи,
нет холодной копии — 410. Кто видит файл, решает один помощник `files_store.file_for_reader`:
свой файл, файл папки с `folder.scope='shared'` (FR-K10) или админ с активным грантом
(`as_admin: true`); чужой закрытый и несуществующий отвечают одинаково — 404 (FR-K8).
Скачивание одного файла — отдельная кнопка «Скачать» в строке папки и на экране файла:
она берёт `GET /webapp/files/{id}/link` (attachment-ссылка на 15 минут) и открывает её
браузером телефона через `openLink`; страница Mini App остаётся на месте (Б2, V-052/V-053).

Что это меняет по сравнению с прежним поведением:

* **Загрузка одна.** Раньше у бота (`save()`) и у Mini App (`save_committed()`) были два
  разных пути записи: дедупликация, квота, личная папка и разбор аудио жили в двух местах.
  Теперь `/files/upload` — обёртка: байты бота кладутся в хранилище и записываются тем же
  `save_committed`, отличается только `uploaded_via` (`human_telegram` / `webapp`).
* **Действия на экране, а не только в чате.** Доступ, тег и папки имели вход только в чате;
  `rename`, `delete` и `order` не звал никто — маршруты были сиротами. Экран и чат зовут
  один обработчик на действие, поэтому право и поведение не могут разъехаться.
* **Чат закрыт правом админ-панели.** `/files`, `/folders`, `/mkdir`, `/tag`, `/tag-ok`, `/tags`,
  `/zip`, `/access`, `/search`, кнопка файла и приём присланного документа
  отвечают «Файлы пока доступны только администратору» без права `admin.panel`.
* **`/revoke` — не исключение из П-7, а другая операция.** Отзыв не открывает файл,
  а закрывает чужой доступ к своему: право «владелец или админ» проверяет
  `file_access.revoke` (FR-K9 — владельцу уходит уведомление «Отозвать: /revoke N»,
  и обещание должно работать). Поэтому оболочка чата запрос пропускает, а отказ
  постороннему приходит словами tool-api: «Отозвать доступ может владелец файла».
  На экране отзыв идёт тем же входом `files.access`, что и остальной раздел; кого пускает
  отзыв, решает `file_access.revoke` (владелец или admin).
* **Участникам файлы не открыты** (V-039 (в)): ни экран, ни данные раздела. У роли `troupe`
  право `files.access` снято миграцией 062, и экран говорит об этом словами (Б3), а не
  пустым списком. Чат бота по-прежнему закрыт `admin.panel` (П-7).

## 4. Модель данных (эскиз)

```sql
-- расширение существующей file_object (миграция 046, db/init/046_files_folders.sql)
alter table file_object
  alter column drive_file_id drop not null,            -- файл может жить только в Garage
  add column if not exists object_key     text,        -- scope/uuid.ext, без ФИО и chat_id
  add column if not exists bucket         text,        -- svoi-private | svoi-shared | svoi-cold
  add column if not exists sha256         char(64),
  add column if not exists kind           text,        -- text | image | audio
  add column if not exists last_access_at timestamptz,
  add column if not exists deleted_at     timestamptz,
  add column if not exists cold_at        timestamptz,
  add column if not exists search_tsv     tsvector;

alter table file_object drop constraint if exists file_object_uploaded_via_check;
alter table file_object add constraint file_object_uploaded_via_check
  check (uploaded_via in ('human_drive','human_telegram','bot','webapp','agent'));

-- папки: дерево, личные создаёт бот, общие — admin и org
create table folder (
  id             bigserial primary key,
  scope          text not null check (scope in ('personal','shared')),
  participant_id bigint references participant(id),    -- null для общих
  parent_id      bigint references folder(id),
  project_id     bigint references project(id),        -- для «Спектакли/<Пурга>»
  name           text not null,                        -- 'музыка', 'шумы', 'Документы'
  path           text not null,                        -- 'Спектакли/Пурга/музыка'
  depth          int  not null default 1 check (depth between 1 and 5),
  created_by     bigint references participant(id),
  created_at     timestamptz not null default now(),
  deleted_at     timestamptz,
  unique (scope, participant_id, path)
);
-- инвариант: scope='shared' → participant_id is null; scope='personal' → not null

-- файл в папке; position — для перетаскивания, по умолчанию порядок по имени
create table file_folder (
  file_id   bigint not null references file_object(id) on delete cascade,
  folder_id bigint not null references folder(id) on delete cascade,
  position  int,                                       -- null = сортировать по name
  added_at  timestamptz not null default now(),
  primary key (file_id, folder_id)
);

-- теги: общий словарь, не свободные строки
create table tag (
  id         bigserial primary key,
  slug       text not null unique,                     -- 'rekvizit' — поиск и URL
  title      text not null unique,                     -- 'Реквизит' — как видит человек
  kind       text not null default 'topic',            -- topic | project | role
  status     text not null default 'approved',         -- approved | draft
  created_by bigint references participant(id),
  created_at timestamptz not null default now()
);
create table file_tag (
  file_id bigint not null references file_object(id) on delete cascade,
  tag_id  bigint not null references tag(id),
  primary key (file_id, tag_id)
);

-- извлечённый текст (FTS — по file_object.search_tsv, словарь russian)
create table file_text (
  file_id      bigint primary key references file_object(id) on delete cascade,
  body         text not null,
  lang         text,
  status       text not null default 'ok',             -- ok | text_unavailable
  extracted_at timestamptz not null default now()
);

-- аудио: без перекодирования, только чтение характеристик
create table file_audio (
  file_id      bigint primary key references file_object(id) on delete cascade,
  duration_sec int,
  bitrate_kbps int,
  format       text,                                   -- mp3 | wav | flac | ogg | m4a
  title        text,                                   -- из id3, если есть
  artist       text,
  probed_at    timestamptz
);

-- доступ админа к личному файлу: только по причине, только на один файл
create table access_grant (
  id          bigserial primary key,
  file_id     bigint not null references file_object(id),
  admin_id    bigint not null references participant(id),
  reason      text not null,
  notified_at timestamptz,
  expires_at  timestamptz,
  created_at  timestamptz not null default now()
);

-- черновики действий агента
create table agent_action (
  id             bigserial primary key,
  participant_id bigint not null references participant(id),
  file_id        bigint references file_object(id),
  kind           text not null,                        -- move|rename|tag|summarize|answer
  payload        jsonb not null,
  status         text not null default 'proposed',     -- proposed|applied|rejected|expired
  proposed_at    timestamptz not null default now(),
  resolved_at    timestamptz
);
```

### Правила модели

1. **`object_key` никогда не содержит ФИО или `chat_id`** — только `scope/uuid.ext`. Переименование
   человеком не трогает байты, меняется только `name`.
2. **Владелец — `participant_id` из БД, не `chat_id`.** Человек может сменить аккаунт Telegram;
   файлы остаются его (`person_key`, `docs/architecture/01`).
3. **Удаление мягкое.** `deleted_at` + ротация байтов по расписанию; «навсегда» — админ.
4. **Дедупликация по `sha256`.** Байты хранятся один раз: шум «дождь» в двух спектаклях — одна
   запись и две строки `file_folder`. Если тот же файл загрузил другой человек — своя строка
   (своя квота, своё удаление), байты общие.
5. **`note` не переезжает в `file_object`.** Заметка — текст в БД; файл — байты в Garage.
   Иначе два места для одной сущности, и половина записей «не находится».
6. **Плейлиста как сущности нет.** Он был бы второй иерархией параллельно папкам; музыка
   спектакля — это `Спектакли/<Спектакль>/музыка`, порядок — имя файла и `position`.

## 7. Краевые случаи

| Случай | Поведение |
|---|---|
| Файл уже есть у этого же человека (тот же `sha256`) | Байты не дублируются; «такой файл уже был — вот он» |
| Тот же файл загрузил другой человек | Своя строка (своя квота, своё удаление), байты общие |
| Диск заполнен при загрузке | Отказ до PUT, если места меньше размера файла; понятный текст, не 500 |
| Участник исключён из труппы | Файлы остаются, доступ по `participant_id` закрыт; админ решает — архив или удаление |
| Двое грузят один файл одновременно | Дедуп по `sha256` после загрузки, конфликта нет |
| Файл в холоде, просят ссылку | Восстановление по требованию, статус в ответе |
| Presigned-ссылка утекла | TTL 15 мин, привязка к `file_id` + `participant_id`, каждое использование — в аудит |
| Агент предложил папку, человек молчит | Предложение истекает, файл остаётся в «Без папки»; ничего не теряется |
| Битый или недокачанный файл | Проверка `size` и `sha256` при подтверждении; несовпадение — отказ, объект удаляется |
| Текст из PDF не извлёкся (скан) | `text_unavailable`, поиск по имени и тегам; OCR — отдельный шаг |
| Удаляют папку спектакля с музыкой | Файлы не удаляются, остаются в «Без папки»; до подтверждения — предупреждение с числом файлов |
| Трек лежит в двух спектаклях, переименовали | Меняется `name` файла — это один файл; предупреждение говорит, где ещё он лежит |
| Глубина папок дошла до 5 | Отказ «глубже нельзя», предложение положить файл в существующую папку |

## 9. Открытые вопросы

1. **Названия корней** — `Хозяйство`, `Соцсети`, `Спектакли`, `Документы` приняты как рабочая
   версия; окончательно решим при подключении сценариев (корни — данные, не код).
2. **Сколько ждёт черновик тега** до истечения — предложение: 14 дней, потом отклоняется сам.
   Не блокирует код, решается при реализации FR-K19.
3. **Удаление архивного проекта** (`project.status='archive'`) — папка спектакля остаётся
   доступной «на память» или уезжает в холод вместе с файлами? Решение понадобится к Ш-11.
4. **Текст сообщения как файл.** Просьба «сохрани это» приходит в бот свободным текстом, а тот же
   канал занят роутером (`docs/development/57`): фраза «сохрани в бота учёт реквизита» — это
   запрос на доработку, а не заметка. Пока не реализовано; вариант — только явная форма
   `/save <текст>` или «сохрани: …», а «сохрани …» остаётся роутеру. Решение к Ш-4.
5. **Публичный адрес хранилища.** Для загрузки из Mini App нужен `https://files.<домен>`
   с сертификатом (Caddy) и CORS с адресом Mini App. Пока домена нет, страница работает
   только на локальной машине (`127.0.0.1`), и с телефона ссылка не откроется. Это задача
   выката, а не кода.
6. **Одноразовость ссылки.** Требование FR-K7 говорит «одноразовую», сделано — TTL 15 минут.
   Presigned URL не умеет «один раз»: подпись действительна всё окно. Чтобы получить строго
   одно использование, нужен свой шлюз `/dl/<token>` (одноразовый токен в БД, отдача потоком)
   с публичным доменом. Домен появится вместе с Mini App (Ш-5) — тогда и решим: TTL достаточно
   или нужен токен.

## 10. Что не входит

- Видео и архивы на входе — отказ (лимиты и диск).
- Перекодирование аудио (сжатие wav→mp3) — сознательно не делаем.
- Отдельная сущность «плейлист» с ручным порядком вне папок — заменена папками (§3.1).
- Расшифровка аудио в текст и поиск по репликам — ML, отложено вместе с эмбеддингами.
- Семантический поиск, рекомендации, автотегирование без подтверждения — вне правила «ML не используем».
- Мобильный доступ к файлам вне Telegram и Mini App.
- Замена Google Drive для таблиц и документов, которые правят люди.
- Публичные ссылки на файлы и шаринг наружу — даже для общих папок.
