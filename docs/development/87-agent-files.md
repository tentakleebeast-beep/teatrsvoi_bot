## 1. Что требуется

Агент должен уметь три вещи, и все три — про файлы человека:

1. **Разложить:** «положу в `Спектакли/Пурга/музыка`» — предложение, человек подтверждает кнопкой.
2. **Выжимка:** короткое резюме документа рядом с файлом.
3. **Ответ по документу** — только с цитатой: фрагмент + имя файла. Нет фрагмента — «в файле этого нет».

Все три требуют одного: модель должна **вызывать инструменты**, а не только писать текст. Сегодня
её ответ — это текст, который бот пересылает человеку (`docs/development/14` §3, WF-01).

## 3. Две ветки

### Вариант A. Цикл в `tool-api` (function calling своими руками)

Модель получает список инструментов в запросе. Ответ с `tool_calls` → `tool-api` выполняет вызов
**в процессе** (те же функции, что обслуживают бота и Mini App) → результат возвращается модели →
и так до финального ответа (лимит 5 шагов, чтобы не зациклиться).

**Плюсы**

- права и владение проверяются **тем же кодом**, что и везде: `file_for_viewer`, `can_manage`;
- расход пишется в `llm_usage` там же, где считается квота — нет второго учёта;
- аудит каждого шага в `audit_event` (FR-L7) — одной транзакцией с действием;
- тесты без сети: фейковый провайдер отдаёт заготовленный `tool_calls`, проверяется и цикл, и отказ;
- всё в git и в CI: ruff, pytest, ревью.

**Минусы**

- надо написать сам цикл (~200 строк с обработкой ошибок и лимитом шагов);
- формат `tool_calls` у провайдеров слегка разный (OpenAI-совместимый у OpenRouter и ProxyAPI —
  один, но проверять надо);
- n8n-роутер остаётся для «поболтать», то есть два пути к модели, пока не сведём.

### Вариант B. Ветка агента в n8n (AI Agent node)

В n8n добавляется ветка: агент с инструментами, каждый инструмент — HTTP Request в `tool-api`.

**Плюсы**

- меньше кода в репозитории: цикл и ретраи — чужие;
- визуально видно, что происходит, правится без выката.

**Минусы**

- логика уезжает в n8n: в git попадает только скрипт-генератор, диффа по изменениям нет;
- инструменты — сетевые вызовы обратно в `tool-api`: второй контур авторизации, задержки,
  и ошибка на любом шаге выглядит как «модель затупила»;
- квоты и аудит придётся собирать из двух мест; двойной учёт токенов (n8n + `llm_usage`) гарантирован;
- тестов нет: JS-ноды в n8n покрываются только смоуком руками (`docs/archive/29-n8n-scenarios.md`);
- n8n на SQLite: потеря воркфлоу при сбое — известный долг (`docs/architecture/25`).

### Сравнение по цене

| Критерий | A: tool-api | B: n8n |
|---|---|---|
| Новый код | ~200–250 строк + тесты | JSON-воркфлоу + скрипт-генератор |
| Проверка прав | в процессе, переиспользует модули | по HTTP, надо дублировать токены |
| Учёт квот | один (`llm_usage`) | два (n8n + наш) |
| Аудит шагов | `audit_event` | частично, из нод |
| Тесты в CI | да, без сети | нет, только смоук |
| Ревью изменений | дифф в git | «а что поменяли в n8n?» |
| Скорость первого прогона | дольше | быстрее на демо |

**Рекомендация: A.** Причина не в эстетике: у нас уже есть три вещи, которые в B пришлось бы
дублировать — права на файлы, квоты и аудит. Дублирование прав в двух контурах рано или поздно
даёт дырку, а «модель затупила» вместо «403 от tool-api» — это отладка на неделю.

## 4. Что конкретно делаем в A

### Инструменты (по одному на требование)

| Инструмент | Что делает | Права |
|---|---|---|
| `list_files(folder_path?, query?)` | список своих файлов или поиск по слову | только свои + общие |
| `read_file(file_id, fragment?)` | текст документа или его фрагмент | `file_for_viewer` |
| `propose_move(file_id, folder_path)` | **черновик** перемещения в `agent_action` | `can_manage` папки |
| `answer(file_id, question)` | ответ с цитатами (Ш-13) | свои файлы |

### Правила, которые держит не модель, а код

1. **Перемещение — только черновик.** `propose_move` пишет `agent_action(status='proposed')`,
   применяется кнопкой; молчаливых перемещений нет (FR-L2).
2. **Удаления нет вообще.** Ни одного инструмента удаления (FR-L8).
3. **Цитата обязательна.** Ответ без `[фрагмент, file_id]` отбрасывается пост-валидатором и человек
   видит «в файле этого нет» (FR-L5, `docs/architecture/05` §3).
4. **Лимит шагов** — 5; исчерпан — «не разобрался за 5 шагов», без догадок.
5. **Квота проверяется до вызова модели**, расход пишется после каждого шага.
