## 4. Модель файла: два расположения

### D1. Расположение — колонка `storage`, а не вторая таблица

**Решение.** У файла ровно одно расположение, записанное в `file_object.storage`:

| Колонка | `garage` (байты у нас) | `drive` (ссылка) |
|---|---|---|
| `storage` | `'garage'` | `'drive'` |
| `object_key`, `bucket` | заполнены | `null` |
| `sha256`, `cold_at`, `last_access_at` | заполняются как сейчас | `null` (дедуплицировать и остужать нечего) |
| `drive_url` | `null` | канонический адрес Google |
| `drive_file_id` | `null` | id из адреса (уникален) |
| `drive_path` | `null` | путь папки в Drive на момент регистрации |
| `drive_mime` | `null` | MIME из Drive, если он известен |
| `size_bytes` | размер, проверенный по `head_object` | из Drive, если известен; иначе `null` |
| `uploaded_via` | `webapp` / `human_telegram` / `bot` | `human_drive` |

**Почему не отдельная таблица `drive_link`.** Тогда «список файлов», «поиск», «файл папки» и
«карточка файла» превращаются в объединение двух источников — ровно та ошибка, от которой
предостерегает `86` §3.2 («параллельную `storage_object` не заводим»). Один файл — одна строка,
одно место в списке, один поисковый индекс.

**Что даёт.** Поиск и список не знают, откуда файл; все различия собраны в двух местах —
выдача (§D7) и учёт места (§D9).

**Цена.** Пять новых колонок на таблице, которая в dev пуста (0 строк), и обязательная ветка
`storage` в каждом пути чтения. Если её забыть, ссылка Drive упадёт в проверке «файл не долетел
до хранилища» — так уже отвечает `webapp_file_view` на пустой `object_key`
(`api/files.py`, `code="file_not_uploaded"`).

**Инварианты (в спецификацию, миграция 071):**

- **F11.** `storage='garage'` ⇔ `object_key is not null and bucket is not null and drive_url is null`.
- **F12.** `storage='drive'` ⇒ `drive_url is not null and object_key is null and bucket is null
  and sha256 is null and cold_at is null and last_access_at is null`.

### D2. Описание пишет тот, кто загрузил

**Решение.** `file_object.description text`. Автор описания в первой версии — владелец строки
(`participant_id`), то есть загрузивший: отдельной колонки «кто написал» не заводим, пока не
ответила анкета (§6). Описание заполняется на том же экране, что и загрузка, и показывается
в карточке файла. Пустое описание допустимо — по умолчанию принято «по желанию с подсказкой»
(подтверждение владельца — V-122).

Для пачки файлов в одной загрузке — **одно описание на партию**, и его можно править у каждого
файла потом. Причина простая: пятьдесят файлов с пятьюдесятью описаниями не заполнит никто,
а партия обычно и есть «вот это» (комплект афиш, запись репетиции).

**Описание не участвует в поиске первой версии** — владелец решил «по имени, папке и типу»
(§2 п.3). Включить его — одна строка в `refresh_file_tsv` и триггер на `description`
(`db/init/046:182-224`); это отдельное решение, не молчаливое расширение.

**Что даёт.** У файла есть человеческое объяснение «что это», а не только имя `IMG_2931.pdf`.

**Цена.** Два поля описания в разных местах (загрузка и карточка) — одна ручка `PATCH`-подобного
вида на оба, иначе экраны разъедутся, как это уже было с кнопками папок до Ш-14.

### D3. Папка: одна ось — наше дерево; путь в Drive — метаданные, а не зеркало

**Решение.** Место файла в структуре задаёт **наше** дерево `folder` (корни `Хозяйство`,
`Соцсети`, `Документы`, `Спектакли` из `db/init/054`; личное — `Личное/{Мои документы, Фото,
Аудио}`, без сегмента с именем: `PERSONAL_ROOT` + `FOLDER_BY_KIND`, `files_store.py:65-66,240-249`,
личность задаёт `participant_id`; глубина ≤5). Связь — существующая `file_folder`, одна и та же
для `garage` и `drive`.

Папки внутри Drive **не зеркалируются** в `folder`. Путь Drive хранится текстом в
`drive_path` («Инфа СВОИ/Спектакли/Пурга») и показывается в карточке с честной подписью
«в Drive на момент регистрации». Это исполняет §D2 `185`: папки людей не переименовываются
и не раскладываются заново, поиск работает поверх существующих имён.

**Почему не зеркало.** Три причины, каждая проверяема:

1. `folder_scope_owner_check` знает только `personal|shared` (`db/init/046:57-61`); третий тип
   потребовал бы менять инвариант и добавлять ветку во все чтения дерева.
2. Зеркало тихо гниёт: люди переименовывают и переносят папки в Drive, бот об этом не узнаёт
   (webhook на Drive нет, `185` §D2 — «не реорганизует»), и в дереве появляется путь, которого
   в Drive уже нет.
3. Своё дерево и чужое дерево — две правды о «где лежит». Расхождение придётся объяснять
   человеку каждый раз.

**Следствие для поиска.** Фильтр «папка» ищет по двум путям: нашему `folder.path` (начало пути)
и `drive_path` (вхождение). Формулировка на экране одна — «папка», чтобы человек не выбирал
между двумя порталами (§D8).

**Цена.** Переехал файл в Drive — сохранённый путь устарел, и фильтр по нему промахнётся.
Истина в один клик: в карточке есть ссылка «Открыть в Drive». Обновление пути по кнопке
(«Обновить из Drive», SA — читатель) — вторая версия, не E4.

### D4. Тип файла: одно слово и один предикат из одного места

**Решение.** Ось «тип» — существующий `kind` (`text|image|audio|null`), новых значений не вводим.
Для ссылки Drive `kind` вычисляется по имени теми же множествами расширений, что у загрузки
(`TEXT_EXT`/`IMAGE_EXT`/`AUDIO_EXT`, `files_store.py:53-55`), но **без отказов** `detect_kind`:
ссылка на видео или архив допустима — байтов у нас нет, и такой файл получает `kind=null`
(слово «файл», виден только под «Все»). Ограничение `file_object_kind_check` (046:24-26) уже
разрешает `null`, менять его не нужно.

**Почему одного `kind` мало.** Человек различает четыре слова, а в БД три значения: `pdf` и `txt`
оба `kind='text'`. Слово сейчас считает JS-константа `kindWord` (`pages/files_actions.py:38-48`)
по расширению раньше, чем по `kind`, — иначе pdf назывался бы «текстом». Слова «документ» в БД
нет: `kind='document'` не существует, и ветка `if (kind === "document")` в `KIND_WORD` — мёртвый
защитный код; его надо удалить, а не поддерживать.

**Один помощник, два выхода.** В спецификации (E4-3) слово и фильтр переезжают в **один**
серверный модуль (`file_kind.py`): одни и те же множества расширений, две функции.

- `kind_word(kind, name)` — слово для плитки, карточки и чипа: `документ | текст | картинка | аудио | файл`.
- `kind_predicate(word)` — то же слово, переведённое в условие над `file_object`.

Два множества, больше нигде не повторяются (второе выводится из первого, а не переписывается):

```
PLAIN_EXT = {txt, md, csv}
DOC_EXT   = TEXT_EXT \ PLAIN_EXT      # pdf docx xlsx pptx odt ods rtf
```

| Чип | `kind_word` отдаёт слово, когда | `kind_predicate` (SQL) |
|---|---|---|
| Документы | расширение ∈ `DOC_EXT` | `file_ext(name) in DOC_EXT` |
| Текст | расширение ∈ `PLAIN_EXT`, либо `kind='text'` и расширение ∉ `DOC_EXT` | `file_ext(name) in PLAIN_EXT or (kind='text' and file_ext(name) not in DOC_EXT)` |
| Картинки | `kind='image'` и расширение ∉ `DOC_EXT ∪ PLAIN_EXT` | `kind='image' and file_ext(name) not in (DOC_EXT ∪ PLAIN_EXT)` |
| Аудио | `kind='audio'` и расширение ∉ `DOC_EXT ∪ PLAIN_EXT` | `kind='audio' and file_ext(name) not in (DOC_EXT ∪ PLAIN_EXT)` |
| Все | любой | условия нет |
| «файл» (не чип) | `kind is null` и расширение ∉ `DOC_EXT ∪ PLAIN_EXT` | виден только под «Все» |

`file_ext(name)` — функция из миграции 071: нижний регистр и `''` для имени без расширения
(не `null`, иначе `not in` даёт `NULL` и строка молча выпадает из фильтра). Согласованность
слов и предикатов держится на одном списке; её и закрепляет AC-11: `(text, Смета.pdf)` →
«документ» и под «Текст» не попадает, `(text, заметки.md)` → «текст», `(null, IMG_1.xyz)` →
«файл» и виден только под «Все».

**Почему предикат, а не `kind = value`.** Слово чипа — не значение колонки. `kind='документ'`
не существует, а `kind='text'` стоит и у «Документов», и у «Текста», поэтому сравнение слова
с `kind` вернуло бы одно и то же под двумя разными чипами — второй словарь, только переехавший
в SQL.

**Почему расширение считается в SQL.** Имя файла — единственное место, где различие
«документ/текст» вообще есть. Дублировать его в колонку `kind` значило бы менять инвариант
`file_object_kind_check` и все чтения вида; функция `file_ext` дешевле и живёт в одном месте
с `kind_word`. Индекс по ней не заводим: строк в dev 0, фильтр идёт вместе с `q`; понадобится —
отдельное решение.

Фильтр типов на экране: **Все · Документы · Текст · Картинки · Аудио**, отдельным переключателем
— **Ссылки (Drive)**. Расположение — не тип: «документ в Drive» должен находиться и как
документ, и как ссылка.

### D5. Загрузка: одно место, одна папка, одно описание

**Решение.** Экран загрузки получает три поля, которых у него нет:

```
Что загружаем:  (•) В студию (Garage)      ( ) Ссылка на Drive
Куда:           [дерево папок]  по умолчанию «Личное/<вид>»
Что это:        [описание, необязательное, одно на партию]
```

Порядок для Garage не меняется: `presign → PUT в хранилище → commit`, байты через сервер не идут
(`86` §5.1, FR-K3). Меняется то, что `commit` принимает `folder_id` и `description`, а
`save_committed` кладёт файл в указанную папку, а не всегда в `Личное/<вид>`.

**Файл в общей папке** получает `scope='shared'` и **не входит в личную квоту**: квота 2 ГБ —
про личное место человека (`86` §2.1), а файл студии — про общий потолок диска (FR-K15).
Кто имеет право грузить в общую папку — роль, и это E4-2; механика права уже есть
(`folders.can_manage`, `folders.py`).

**Цена.** `_insert_with_quota` придётся разделить на два случая (личное — с проверкой суммы,
общее — без), а `used_bytes` — научить не считать `scope='shared'`. Это правка в самом
загруженном месте файлового кода; без теста «общая папка не ест личную квоту» её нельзя
принимать.

### D6. Регистрация ссылки на Drive: короткий разбор адреса, без походов в Google

**Решение.** Ссылка регистрируется формой, а не загрузкой:

| Шаг | Правило |
|---|---|
| Принять адрес | Только `https`, хосты `drive.google.com` и `docs.google.com`; чужой хост — отказ словами |
| Разобрать `drive_file_id` | Четыре формы: `/file/d/<id>/…`, `/document/d/<id>/…`, `/spreadsheets/d/<id>/…`, `?id=<id>` |
| Папка Drive (`/drive/folders/<id>`) | Отказ в первой версии: «папку целиком не прикрепляю — прикрепите файл или выберите папку в дереве» (продуктовая развилка — V-121) |
| Имя | Из заголовка страницы или из имени файла в адресе; если не вышло — «Ссылка на Drive» и человек правит |
| Дубль | `drive_file_id` уже есть → «эта ссылка уже есть: <имя>», новая строка не создаётся |
| Квота, дедуп по `sha256`, холод, архив папки | Не участвуют: байтов у нас нет |
| Права в Google | **Не трогаем.** Бот не создаёт файлы, не переносит их и не выдаёт доступ (§D1 `185`, решение владельца) |

**Почему разбор адреса, а не запрос к Drive.** Запрос к Drive требует доступа SA к чужому файлу;
если файл не расшарен — регистрация падала бы на 403 у человека, который видит файл в браузере.
Разбор адреса не ходит в сеть и работает всегда. Метаданные (размер, MIME) подтягиваются, только
если SA и так имеет доступ, и их отсутствие не мешает сохранить ссылку.

**Цена.** Имя и размер могут быть неточными, пока файл не открыли. Это дешевле, чем отказ
«нет доступа» на файл, который человек только что открывал сам.

### D7. Выдача: два разных поведения, один экран

**Решение.** Карточка файла смотрит на `storage`:

| Расположение | Что показывает | Как открывается |
|---|---|---|
| `garage` | размер, вид, «Скачать», предпросмотр (картинка/аудио) | как сейчас: `GET /webapp/files/{id}/view`, `…/link` (presigned, 15 мин) |
| `drive` | вид, «в Drive», описание, путь в Drive на момент регистрации | `open_url` = сохранённый адрес, открывается `openLink`; **подписи нет**, скачивания нет |

Правило, которое нельзя нарушить молча: **строка `drive` не проходит через presigned-код**.
`webapp_file_view` для неё не подписывает ключ, не зовёт `cold.restore` и не отвечает 404
«файл не долетел», а отдаёт `{type: 'external', open_url, description}`.

### D8. Поиск первой версии: имя, папка, тип

**Решение.** Одна ручка на экран, параметры независимы:

| Параметр | Что сравнивается | Пример |
|---|---|---|
| `q` | имя: `ILIKE '%q%'`, плюс существующий FTS (`search_tsv`: имя + извлечённый текст + теги) для файлов Garage | `афиша` найдёт `Афиша Пурга.png` |
| `folder` | `folder.path` с начала пути **или** `drive_path` вхождением | `Спектакли/Пурга` |
| `kind` | слово чипа через `kind_predicate(word)` (§D4): «Документы» — расширения `DOC_EXT`, «Текст» — `PLAIN_EXT` или `kind='text'` без документа | `документ` находит `Смета.pdf`, `текст` — нет |
| `storage` | `garage` / `drive` (чип «Ссылки») | `drive` |

Правила:

- `kind` — это слово чипа, а не значение колонки: сравнение `kind = value` запрещено (§D4),
  потому что «Документы» и «Текст» в БД — одно `kind='text'`;
- пустой результат — «Ничего не нашлось» без подстановок и «возможно, вы имели в виду»;
- порядок — совпадение по имени выше, дальше по дате загрузки; сквозного ранга между
  расположениями в первой версии нет;
- выдача показывает `storage`, `description`, `kind_word`, путь папки (наш) и путь Drive;
- видимость — ровно та, что уже есть (`files.access` + правило `file_for_reader`); новых
  проверок прав в E4 нет;
- **не входит:** полнотекст по файлам в Drive, поиск по описанию, Яндекс.Диск, поиск по тегам
  на экране (теги остаются в `/search` бота).

**Что даёт.** Три вопроса «где афиша», «что в папке Пурга», «покажи все таблицы» отвечаются
без листания 273 файлов в Drive и без второго поисковика.

**Цена.** Фильтр по папке смешивает два пути (наш и Drive) — это осознанно, но в справке надо
написать одной строкой, иначе «почему нашлось» останется загадкой.

### D9. Учёт места: ссылка не ест квоту, общая папка — не личная

**Решение.** Три правила, каждое — тест:

1. `used_bytes` суммирует только `storage='garage'`. Без этого ссылка с `size_bytes` из Drive
   (5 ГБ видео) закрыла бы человеку загрузку навсегда.
2. Файл в общей папке (`scope='shared'`) не входит в личную квоту загрузившего; за местом следит
   общий потолок диска и алерт админу (FR-K15).
3. Холод (`cold.py`), дедупликация по `sha256`, ZIP папки и квота не видят `drive`-строк вовсе.

**Цена.** Вопрос «кто платит местом за файл в общей папке» становится видимым: раньше его не
было, потому что общей загрузки не существовало. Ответ по умолчанию — общий потолок; если
владелец захочет иначе (личная квота загрузившего) — это V-123.

### D10. Чего не делаем никогда (границы модели)

- Сервисный аккаунт Google не создаёт файлы, папки и не выдаёт доступ — ни при регистрации
  ссылки, ни при «обновить из Drive» (§D1 `185`).
- Бот не переносит и не переименовывает файлы в Drive и не раскладывает папки людей.
- Ссылка не становится «нашим файлом»: байты не копируются, скачивания нет.
- Публичные ссылки и шаринг наружу — вне модели (`86` §10).
- Второй поисковик по Drive (зеркало индекса) не заводим: см. §D3.

## 5. Структура папок: что остаётся и где код расходится с дизайном

**Остаётся как есть.** Дерево `054`: корни `Хозяйство`, `Соцсети`, `Документы`, `Спектакли`;
`Спектакли/<проект>/{тексты, партитуры, заметки, музыка, шумы}` создаётся триггером на `project`;
личное — `Личное/{Мои документы, Фото, Аудио}` (FR-K11: `PERSONAL_ROOT` + `FOLDER_BY_KIND`,
`files_store.py:65-66,240-249`, без сегмента с именем); глубина ≤5 и проверяется триггером.
Папки Drive не трогаем (`185` §D2).

**Три расхождения, которые надо закрыть в реализации** (факты §3, не мнения):

1. **Дерево и список — про разное.** Экран показывает дерево общих папок и список личных файлов.
   Человек видит папку, открывает её и получает пусто (или 404), потому что файлы лежат в
   `Личное/…`. Дизайн: открытие папки показывает **файлы этой папки**; «Мои файлы» остаётся
   отдельным разделом личного.
2. **Загрузка не спрашивает папку.** Все новые файлы падают в `Личное/<вид>` независимо от
   дерева; общую папку можно наполнить только переносом. Дизайн: папка выбирается при загрузке
   (§D5).
3. **Общая папка и квота.** `_insert_with_quota` пишет `scope='personal'` и считает личную сумму;
   для общей папки нужен второй случай (§D5, §D9).

**Почему это не «переделать дерево».** Ни один корень и ни одна подпапка не переименовываются;
меняется только то, что у файла появляется явное место, а экран перестаёт показывать два разных
мира одновременно.

## 7. Критерии приёмки

Проверяются на dev-БД и тестами; живые файлы Drive не участвуют.

1. **AC-1.** У каждой строки `file_object` заполнен `storage`; инварианты F11 и F12 зелёные,
   расхождение (garage без `object_key` или `bucket`, drive с `object_key`, `bucket`, `sha256`,
   `cold_at` или `last_access_at`) — красный тест.
2. **AC-2.** `used_bytes` считает только `storage='garage'`: ссылка Drive с `size_bytes` = 5 ГБ
   не уменьшает личную квоту и не блокирует загрузку.
3. **AC-3.** Регистрация ссылки принимает четыре формы адреса Drive/Docs; чужой хост и ссылка
   на папку получают отказ с понятным текстом, строка не создаётся.
4. **AC-4.** Повторная регистрация того же адреса отвечает «эта ссылка уже есть» и не создаёт
   вторую строку (существующий уникальный `drive_file_id`).
5. **AC-5.** Описание сохраняется при загрузке и при регистрации ссылки, показывается в карточке,
   правится владельцем файла; пустое допустимо; изменение — в `audit_event`.
6. **AC-6.** Загрузка спрашивает папку: файл появляется именно в выбранной папке, а не в
   `Личное/<вид>` по умолчанию; папка вне дерева — отказ.
7. **AC-7.** Файл, загруженный в общую папку, имеет `scope='shared'` и не входит в личную квоту;
   сумма личного места не меняется.
8. **AC-8.** Открытие папки из дерева показывает файлы этой папки (Garage и Drive вместе),
   а не «мои файлы»; пустая папка — пустое состояние словами, а не 404.
9. **AC-9.** `GET …/view` для `storage='drive'` отдаёт `open_url` без подписи, не зовёт хранилище
   и не отвечает «не долетел»; скачивания для такой строки нет ни на одном маршруте.
10. **AC-10.** Поиск: `q` по имени, `folder` по нашему пути и по `drive_path`, `kind` — слово
    чипа через `kind_predicate` (§D4), `storage` по чипу «Ссылки»; пустой результат — «Ничего
    не нашлось». Тест: `kind=документ` находит `Смета.pdf` и не находит `заметки.md`;
    `kind=текст` — наоборот; `kind=картинка` находит `Афиша.png`.
11. **AC-11.** Слово типа и фильтр — один модуль: `kind_word` приходит в ответе списка файлов,
    списка папки и карточки, JS-константы `kindWord` больше нет (`grep KIND_WORD` пуст).
    Свойство-тест на наборе пар `(kind, name)`: строка попадает ровно под один чип из четырёх,
    и это чип, чьё слово вернул `kind_word`; второй список расширений или второй словарь
    в SQL — красный тест.
12. **AC-12.** Квота, холод, дедупликация по `sha256` и ZIP папки не видят `drive`-строк.
13. **AC-13.** Ролевая матрица не изменилась: раздел по-прежнему `files.access`, видимость — по
    `scope`/папке, новые проверки прав в E4 не появились.
14. **AC-14.** В документе есть §6 «Ждёт анкеты», и ни одно правило видимости в коде не выведено
    из гипотезы (проверяется ревью кода вместе с E4-2).
