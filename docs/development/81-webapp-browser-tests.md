# 81. Браузерные тесты Mini App: Playwright, тема и токен

**Дата:** 30.10.2026
**Зачем:** ловить дефекты Mini App, которые не видит ни один серверный тест — тему,
вёрстку на узком экране, поведение протухшего токена, отрисовку ошибок валидации.
Поводом стал iPhone: «чёрный фон, не читаемо», «сессия истекла» на первом действии,
пустая анкета.

## 1. Что это

Отдельный набор `tests/webapp/`:

| Файл | Что делает |
|---|---|
| `server.py` | стенд: отдаёт настоящие страницы из `app.webapp_page`, `/webapp/tg.js`, `/webapp/shell.js` и детерминированные ответы API без базы |
| `conftest.py` | поднимает стенд на свободном порту, открывает страницу так, как это делает Telegram (initData в hash), задаёт схему light/dark |
| `test_miniapp_visual.py` | контраст темы, отсутствие горизонтальной прокрутки, приход данных, живучесть токена, читаемость ошибок |

Тесты по умолчанию **пропускаются** — нужен playwright с движками. Включаются явно.

## 2. Запуск

```bash
uv pip install --python .venv/bin/python playwright pytest-playwright
.venv/bin/python -m playwright install webkit chromium

SVOI_WEBAPP_TESTS=1 env -u PYTHONPATH .venv/bin/python -m pytest tests/webapp -q --browser webkit
SVOI_WEBAPP_TESTS=1 env -u PYTHONPATH .venv/bin/python -m pytest tests/webapp -q --browser chromium
```

Оба движка проходят за 8–10 секунд. WebKit — движок Safari, то есть iOS; Chromium —
WebView на Android и Telegram Web.

Посмотреть страницу глазами:

```bash
.venv/bin/python -m uvicorn tests.webapp.server:app --port 8765
# http://127.0.0.1:8765/webapp/days
```

Скриншоты прогона: `tests/webapp/screenshots/<движок>/<экран>-<тема>.png` (в git не попадают).

## 3. Что проверяется

- **Тема.** Для светлой и тёмной схемы: фон действительно светлый/тёмный и контраст
  текста ≥ 4.5. Отдельно — случай «iOS прислал только `bg_color`»: текст обязан стать
  светлым.
- **Вёрстка.** На вьюпорте 390×844 страница не уезжает вбок.
- **Данные.** Категории подставлены, неделя отрисована, анкета и карточка содержат имя.
- **Токен.** Старый токен в `localStorage` не должен давать «сессия истекла»: страница
  обязана тихо перевыпустить его через `initData` и повторить запрос.
- **Ошибки.** Ответ 422 со списком `detail` показывается текстом, а не `[object Object]`.

## 4. Что эти тесты уже нашли

1. **Страница анкеты падала целиком**: `/webapp` обращалась к `UI.hint`, но не объявляла
   `const UI = window.UI_TEXTS || {}`. В браузере это `pageerror: UI is not defined`,
   у человека — пустая анкета. Исправлено, добавлен тест «использует UI — объяви UI».
2. **Общий слой не видел токен, который записала страница.** Страницы хранят токен сами
   в `localStorage`, а обёртка `fetch` держала своё значение — из-за этого перевыпуск
   не срабатывал. Теперь источник истины — `localStorage`.
3. **Проверка темы была бы фиктивной**: `themeParams` в SDK — свойство только для чтения,
   подменить его из теста нельзя. Поэтому схема задаётся контекстом браузера, а
   `SVOI.applyTheme(params)` принимает параметры для проверки контраста.

## 5. Чего эти тесты не покрывают

- Настоящий `initData` и его подпись: стенд подпись не проверяет (это покрыто
  `tests/unit` для `webapp.py`, а живой вход проверяется в Telegram).
- iOS и Android как приложения: другой движок WebView, другие жесты. Здесь — браузерные
  движки, максимально близкие, но не те же.
- Сеть и задержки: стенд отвечает мгновенно.

Для настоящего мобильного прогона — см. `docs/reports/80-manual-testing-night.md`
(Desktop через computer_use) и варианты из обсуждения: iPhone Mirroring, эмулятор
Android с `adb`.

## 6. Профили устройств

Кроме одной ширины 390 px набор гоняется по профилям playwright — размер, плотность
пикселей, тач и user-agent берутся из описаний устройств. Движок у профиля свой,
поэтому команда запускается дважды, а пары чужого движка пропускаются.

| Профиль | Движок | Экран |
|---|---|---|
| iPhone 14 | WebKit | 390×664, dpr 3 |
| iPhone 15 Pro Max | WebKit | 430×739, dpr 3 |
| Pixel 7 | Chromium | 412×839, dpr 2.625 |
| Galaxy S9+ | Chromium | 320×658, dpr 4.5 — самый узкий |

Что проверяется на каждом профиле: нет горизонтальной прокрутки, страница не пустая,
тёмная тема читаема, а на 3G (задержка ответа API 700 мс) данные всё равно приходят.

Скриншоты: `tests/webapp/screenshots/<движок>/<устройство>-<экран>.png`.

Проверено 30.10.2026: на 320 px форма операции не ломается — переключатели
«Расход/Доход» и «План/Факт» остаются в две колонки, поля во всю ширину, кнопка
«Записать» не перекрывает содержимое.

Замечание: поле даты показывает формат по локали браузера (`10/30/2026` в headless),
на устройстве это нативный пикер Telegram. Это не дефект страницы, но при съёмке
эталонов формат нужно фиксировать локалью, иначе скриншоты будут «мигать».

## 7. Системные проверки после переработки (31.10.2026)

Появился отдельный набор `tests/webapp/test_miniapp_system.py`: на **каждом** экране
в ширинах 390 и 320 px проверяется то, что раньше держалось только на дисциплине —

* нет эмодзи в интерфейсе;
* нет горизонтального скролла — ни у страницы, ни у контейнеров;
* нет текста мельче 13 px;
* все цели нажатия не меньше 44 px;
* страница не падает с ошибкой JS.

`test_miniapp_hub.py` переписан под новую навигацию: «Главная» отвечает на «что требует
решения», вкладки — четыре слова, четвёртая «Управление» по правам, разделы админки
открываются своим адресом с шапкой «‹» и без ленты вкладок.

Стенд `tests/webapp/server.py` знает все актуальные адреса и отдаёт страницы с правами
администратора (подпись вкладки подменяется так же, как в бою).
