# 21. Каскад разбора: правила → модель → человек

> **n8n выведен из контура (V-026, 01.11.2026).** Где ниже n8n назван частью контура или
> источником разбора свободного текста, читать: `POST /tools/route` в tool-api
> (`services/tool-api/app/router_llm.py`); воркфлоу, публичный вебхук и переменные `N8N_*`
> удалены из деплоя. История контрактов — `docs/archive/29-n8n-scenarios.md`.

Решения заказчика от 26.10.2026: **порог уверенности 0.7**, новые категории утверждаются
человеком вручную, тексты в журнале храним **90 дней**.

Связанные документы: `docs/architecture/17` (алгоритмы), `docs/development/16` (тесты), `docs/development/19` (требования).

---

## 1. Задача

Раньше было два состояния: либо правила разобрали фразу, либо бот отвечал «не понял».
Модель подключалась вслепую и могла придумать категорию, которой нет в бюджете.

Нужно: не терять фразы, не портить справочник, и накапливать материал для доработки правил.

---

## 2. Каскад

```
1. Правила (словарь + стемы)         уверены → пишем, source=rules
2. Модель с ЗАКРЫТЫМ списком          ≥ 0.7 → пишем, source=llm
3. Кнопки человеку                    топ-5 категорий, source=buttons
4. Человек вводит новую категорию     → category_candidate, source=human_new
```

Три жёстких правила:

1. **Модель не придумывает категории.** Ей передаётся список из `category`; ответ вне списка
   не принимается, даже при уверенности 0.99.
2. **«Прочее» от модели — это не ответ.** Так модель говорит «не знаю», значит идём к человеку.
3. **Правила побеждают модель.** Если словарь уверен, ответ модели игнорируется: правила
   детерминированы, покрыты тестами и не меняются от версии модели.

## 3. Журнал (`intent_log`)

Пишется на каждый разбор:

| Поле | Смысл |
|---|---|
| `text` | исходная фраза |
| `intent_rules` / `intent_llm` | что решили правила и модель |
| `category_rules` / `category_llm` / `category_final` | категория на каждом шаге |
| `source` | `rules` · `llm` · `buttons` · `human_new` · `failed` |
| `confidence` | уверенность модели |
| `resolved` | записали операцию или нет |
| `tokens`, `latency_ms` | цена разбора |

Представления:
- `v_intent_gaps` — по дням: сколько разобрали правила, модель, человек, сколько потеряли;
- `v_top_unmatched` — топ-100 фраз, где правила молчат (очередь на новые синонимы).

**Хранение:** 90 дней. Чистка — `python scripts/intent_report.py --purge`.

**Агентные сессии (A-5, `docs/development/108`):** в ту же таблицу пишутся сессии
агентного режима — `steps` (шаги с инструментами и обезличенными аргументами),
`step_count`, `answer` и `agent_status` (`answer` · `proposal` · `refusal`). Миграция
`048_agent_observability.sql`. Строки каскада от них отличаются значением
`agent_status is null`; обе выборки выше (журнал и представления) этот признак
учитывают, чтобы «модель разобрала» не считала сессии, которые категорий не выбирают.
Чистка общая: строки старше 90 дней удаляются целиком, вместе с шагами.

## 4. Замыкание цикла улучшения

```
неделя → отчёт по v_top_unmatched
       → 5–10 новых синонимов
       → каждое правило + тест в tests/unit/test_rules_budget.py
       → прогон pytest
       → деплой
```

Метрики, которые смотрим:

| Метрика | Цель |
|---|---|
| Доля фраз, разобранных правилами | ≥ 80 % |
| Доля ручных правок после ответа модели | < 10 % |
| Фраз, не записанных вообще | < 2 % |
| Категорий-кандидатов в очереди | 0 после недельного разбора |

Если доля правил падает — словарь отстаёт от жизни. Если растёт доля правок после модели —
модель выбирает «похожее, но не то», нужен более узкий список в промпте.

---

## 5. Что человек видит

| Ситуация | Сообщение |
|---|---|
| Правила уверены | черновик: сумма · категория · дата |
| Модель уверена (≥ 0.7) | черновик + пометка «категория предложена моделью» |
| Модель не уверена | кнопки: топ-5 + «другая» |
| Модель недоступна | сразу кнопки, без «сервис недоступен» |
| Суммы нет | «Похоже на операцию, но не увидел сумму» + форма |

---

## 6. Кандидаты в категории

```
category_candidate(name, proposed_text, first_seen, seen_count, approved, approved_by)
```

- Новая категория от модели **не попадает в бюджет** — только в очередь.
- Человек раз в неделю смотрит список: `python scripts/intent_report.py --candidates`.
- Утверждение: `--approve "Название"` → категория появляется в справочнике и в следующем
  промпте модели; отказ: `--reject "Название"`.

## 8. Почему не «просто пусть модель отвечает»

Свободный ответ модели даёт красивые фразы и несравнимые цифры: через месяц в бюджете
будет «Реквизит», «Реквизит и декорации», «Бутафория» — три категории про одно и то же,
и отчёт по проекту перестанет сходиться. Закрытый список + кандидаты с утверждением —
единственный способ и использовать модель, и сохранить сопоставимость.
