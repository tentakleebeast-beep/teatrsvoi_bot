## 3. Модель данных

### 3.1. Колонки `file_object`

| Колонка | Тип | `storage='garage'` | `storage='drive'` |
|---|---|---|---|
| `storage` | `text not null default 'garage'` | `'garage'` | `'drive'` |
| `object_key`, `bucket` | уже есть | заполнены | `null` |
| `sha256`, `cold_at`, `last_access_at` | уже есть | как сейчас | `null` |
| `drive_url` | `text` | `null` | канонический адрес (§6.3) |
| `drive_file_id` | уже есть, `unique` | `null` | id из адреса |
| `drive_path` | `text` | `null` | путь в Drive, если человек его указал |
| `drive_mime` | `text` | `null` | `null`: MIME из Drive без сетевого запроса неизвестен |
| `description` | `text` | текст или `null` | текст или `null` |
| `size_bytes` | уже есть | размер из `head_object` | `null`: размер в Drive не запрашиваем |
| `uploaded_via` | уже есть | `webapp` / `human_telegram` / `bot` | `human_drive` |

`kind` для ссылки: `folder` у папки, иначе по расширению имени (`text|image|audio`), иначе
`null` («файл», виден только под «Все»). Ссылка на Google Docs (`/document/d/…`) расширения
не имеет, поэтому получает `kind=null` — это следует из правила «по имени», и на экране такая
строка живёт под «Все» и «Ссылки» (§4.2).

### 3.2. `kind`: добавляется одно значение

`file_object_kind_check` сейчас: `kind is null or kind in ('text','image','audio')`
(`db/init/046:25–27`). Становится `kind is null or kind in ('text','image','audio','folder')`
— дизъюнкция `kind is null` остаётся: `null` в `check` не «проходит», а отвергается, а
строки с `kind = null` («файл», §3.1, §4.2) обязаны вставляться.

Значение `folder` ставит **только** регистрация ссылки на папку Drive. Ни один другой путь
(`save_committed`, `detect_kind`, бот, агент) его не выставляет, и `detect_kind` по-прежнему
бросает `FileRejected` на всё, что не документ/картинка/аудио.

### 3.3. Инварианты F11–F13 (в `v_file_checks`, миграция 073)

```sql
-- F11: garage держит байты, а не ссылку
not exists (select 1 from file_object
             where deleted_at is null and storage = 'garage'
               and (object_key is null or bucket is null or drive_url is not null))

-- F12: ссылка не держит байтов
not exists (select 1 from file_object
             where deleted_at is null and storage = 'drive'
               and (drive_url is null or object_key is not null or bucket is not null
                    or sha256 is not null or cold_at is not null or last_access_at is not null))

-- F13: папка Drive — только ссылка
not exists (select 1 from file_object where kind = 'folder' and storage <> 'drive')
```

F1–F10 не меняются. F2 («файл знает, где его байты») остаётся как есть и продолжает ловить
строку, у которой нет ни `object_key`, ни `drive_file_id`.

`deleted_at is null` в F11 и F12 — не поблажка: мягко удалённая строка не видна ни в одном
списке (`list_files`, `folder_files`, `search`, `used_bytes`), и F2, из которого эти два
инварианта растут, считает так же. Без фильтра миграция краснила бы `check_invariants.py`
на legacy-строке «удалена и без ключа»: она проходит мимо F2 именно потому, что удалена.
Ветка «удалена, но ключ и байты на месте» остаётся видимой для F11 в любом случае.

### 3.4. Миграция: номер, порядок шагов, backfill

**Номер — 073** (в первой редакции спеки был 072; перенумеровано 23.11.2026 картой
t_92b8538e до мержа). Причина: номер 072 заняла E1-4 — `072_google_event_calendar.sql`
влита в `main` коммитом `e18c88c`, а ветка E4-4 держала под тем же номером свой файл.
Номер берётся как максимум + 1 по **всем** ветвям в момент работы, и проверять надо не
только `main`: невлитая ветка держит номер так же крепко. Проверка —
`git ls-tree -r --name-only origin/main origin/wt/* | grep db/init`, а не `ls` в своём
worktree.

Порядок шагов внутри файла — обязателен, иначе инвариант краснеет на собственной миграции:

1. `add column if not exists` для `storage`, `drive_url`, `drive_path`, `drive_mime`,
   `description` — **без** `not null` (колонка добавляется на непустой таблице).
2. **Backfill** — до ограничений:
   ```sql
   update file_object set storage = 'drive',
          drive_url = coalesce(drive_url,
                       'https://drive.google.com/file/d/' || drive_file_id || '/view')
    where drive_file_id is not null and object_key is null;
   update file_object set storage = 'garage' where storage is null;
   ```
   Адрес собирается по форме файла: заглушка `001` заводилась под файлы, папок в ней быть
   не могло. Строку, у которой есть и `object_key`, и `drive_file_id`, схема не запрещает
   (`ux_file_object_key` и `unique (drive_file_id)` — уникальность, а не взаимоисключение),
   но backfill её не трогает: в условии стоит `object_key is null`, такая строка остаётся
   `garage`, F11 у неё зелёный и F12 её не касается.
3. `alter column storage set default 'garage'`, `set not null`; `file_object_storage_check`
   (`in ('garage','drive')`); пересоздание `file_object_kind_check` с `folder`.
4. Функция `file_ext(text)` (§4.3) — до представления.
5. `create or replace view v_file_checks` с F11–F13.
6. Индекс `ix_file_object_storage on file_object (storage, created_at desc) where deleted_at is null`.
7. `NOTICE` с числом строк, перенесённых в `drive` на шаге 2 (`raise notice`).

**Замер (живая база, полная схема из `db/init`):**

| Проверка | Результат |
|---|---|
| Накат 073 (тогда 072) дважды | второй прогон — только `NOTICE ... already exists`, ошибок нет |
| F1–F13 на пустой базе | 13 строк, `ok = true` |
| Строка-заглушка (`drive_file_id` есть, `object_key` нет) до backfill | **F11 красная** («1 строк») — пропущенный backfill виден |
| Та же строка после backfill без адреса | **F12 красная** — поэтому адрес собирается в том же `update` |
| После backfill с адресом | F11 и F12 зелёные |
| `kind='folder'` + `storage='garage'` | **F13 красная** |
| `insert ... drive_file_id = <существующий>` | `duplicate key ... file_object_drive_file_id_key` — уникальность уже есть от `001`, второй индекс не нужен |

## 4. Тип файла: один модуль, два выхода

### 4.1. `app/file_kind.py` — новый модуль

Из `files_store.py` переезжают наборы расширений и `extension()`; там же появляются слово и
предикат. Второго списка расширений не остаётся ни в Python, ни в SQL, ни в JS.

```python
TEXT_EXT  = {".txt", ".md", ".csv", ".pdf", ".docx", ".xlsx", ".pptx", ".odt", ".ods", ".rtf"}
PLAIN_EXT = {".txt", ".md", ".csv"}
DOC_EXT   = TEXT_EXT - PLAIN_EXT          # pdf docx xlsx pptx odt ods rtf
IMAGE_EXT = {".png", ".jpg", ".jpeg", ".webp", ".gif", ".bmp", ".tif", ".tiff"}
AUDIO_EXT = {".mp3", ".wav", ".ogg", ".opus", ".flac", ".m4a", ".aac", ".wma"}

def extension(name: str) -> str            # как сейчас: нижний регистр, «.docx» — расширение
def kind_by_name(name: str) -> str | None  # text|image|audio|None, без отказов
def kind_word(kind: str | None, name: str) -> str   # документ|текст|картинка|аудио|папка|файл
def kind_predicate(word: str) -> tuple[str, list]   # (sql, params) для чипа
KIND_WORDS = ("документ", "текст", "картинка", "аудио")   # слова чипов, не считая «Все»
```

`files_store` импортирует отсюда `extension`, `TEXT_EXT`, `IMAGE_EXT`, `AUDIO_EXT`,
`kind_by_name`; `detect_kind` остаётся в `files_store` (он про отказы и сигнатуры), но
положительную ветку берёт из `kind_by_name`. `ARCHIVE_EXT`, `VIDEO_EXT`, `EXEC_EXT`,
`OFFICE_EXT` остаются в `files_store`: это про приём, а не про слово.

### 4.2. Слово и предикат — из одного списка

`kind_predicate` возвращает SQL-фрагмент над алиасом `f` и параметры-массивы (расширения
передаются как `= any(%s)`, а не вклеиваются в текст). Неизвестное слово — `ValueError`
(ошибка программиста; вход ручки проверяется до вызова, §6.6).

| Чип | `kind_word` отдаёт | `kind_predicate` (SQL над `file_object f`) |
|---|---|---|
| Документы | расширение ∈ `DOC_EXT` | `f.kind is distinct from 'folder' and file_ext(f.name) = any(DOC)` |
| Текст | расширение ∈ `PLAIN_EXT`, либо `kind='text'` и расширение ∉ `DOC_EXT` | `f.kind is distinct from 'folder' and (file_ext(f.name) = any(PLAIN) or (f.kind = 'text' and not (file_ext(f.name) = any(DOC))))` |
| Картинки | `kind='image'` и расширение ∉ `DOC_EXT ∪ PLAIN_EXT` | `f.kind is distinct from 'folder' and f.kind = 'image' and not (file_ext(f.name) = any(DOC ∪ PLAIN))` |
| Аудио | `kind='audio'` и расширение ∉ `DOC_EXT ∪ PLAIN_EXT` | то же с `f.kind = 'audio'` |
| Все | любой | условия нет |
| «папка» | `kind='folder'` — **слово, но не чип** | ни под одним чипом: видна под «Все» и «Ссылки» |

`f.kind is distinct from 'folder'` — не украшение: папка с именем `Смета.pdf` иначе попала бы
под «Документы», а папка `Афиши` — под «Все» с словом «документ» при расширении `.pdf`.

Проверено на живой базе (5 строк: `(text,Смета.pdf)`, `(image,Афиша.png)`,
`(null,Запись репетиции)`, `(folder,Пурга 2025)`, `(image,скрин.png)`): число чипов на строку —
**0 или 1**, у папки — 0.

### 4.3. `file_ext(text)` — одно правило на Python и SQL

```sql
create or replace function file_ext(p_name text) returns text
language sql immutable as $$
  select case
    when p_name is null or p_name = '' then ''
    when position('.' in p_name) = 0 then ''
    when p_name ~ '^\.[^.]*$' then lower(p_name)          -- «.docx»: ведущая точка — расширение
    else lower(substring(p_name from '\.[^.]*$'))
  end
$$;
```

Возвращает расширение **с точкой** (`'.pdf'`) и `''`, когда расширения нет — никогда `null`,
иначе `not in (...)` даёт `NULL` и строка молча выпадает из фильтра.

**Замер** (SQL против `files_store.extension`, 14 имён):

| Имя | Python | SQL |
|---|---|---|
| `Смета.pdf`, `Смета.PDF` | `.pdf` | `.pdf` |
| `заметки.md` | `.md` | `.md` |
| `.docx`, `.hidden` | `.docx`, `.hidden` | то же |
| `x.` | `.` | `.` |
| `архив.tar.gz` | `.gz` | `.gz` |
| `a.b.c` | `.c` | `.c` |
| `без расширения`, `Пурга 2025`, `''` | `''` | `''` |
| `..` | `..` | `.` |

Расхождение одно — имя из одних точек. Оба значения не входят ни в одно множество, то есть
слово и чип у такой строки одинаковы («файл», только «Все»); в критерии это записано явно,
чтобы тест-свойство не краснело на выдуманном различии.

## 5. Учёт места: личное, общее и ссылка

**Правило (V-125).** Личная квота 2 ГБ считает только файлы, которые (а) мои, (б) не удалены,
(в) лежат байтами (`storage='garage'`), (г) не являются скриншотом обращения, (д) **не лежат
ни в одной общей папке**. Всё остальное личного места не занимает: файл в общей папке, ссылка
на Drive, вложение обращения.

**Один SQL на оба места** — чтение (`used_bytes`) и вставку (`_insert_with_quota`), иначе
счётчик на экране и отказ по квоте снова разъедутся:

```sql
coalesce(sum(f.size_bytes), 0)
  from file_object f
 where f.participant_id = %(pid)s
   and f.deleted_at is null
   and f.storage = 'garage'
   and f.scope <> 'feedback'
   and not exists (select 1 from file_folder ff join folder fo on fo.id = ff.folder_id
                    where ff.file_id = f.id and fo.deleted_at is null and fo.scope = 'shared')
```

Вставка проверяет ту же сумму в том же `insert ... select` и под `select ... for update` на
строке участника — как сейчас, гонка двух подтверждений не возвращается. **При загрузке
в общую папку проверка не выполняется вовсе** (`quota=False`): файл 300 МБ должен проходить
при занятых 2 ГБ личного места, потому что личного места он не занимает.

**Почему по папке, а не по колонке `scope`.** Файл можно перенести (`POST /files/{id}/folder`)
и положить в две папки сразу (`FR-M7`, `file_folder` — many-to-many). Колонка `scope` при
переносе не меняется, поэтому «общий» по ней — ложь после первого же переноса. Правило «лежит
хотя бы в одной общей папке» имеет один смысл в любой момент и проверяется тестом на перенос
в обе стороны.

**Замер (живая база, 5 строк):**

| Правило | Сумма |
|---|---|
| Новое (§5) | `104 857 600` — только личный garage-файл 100 МБ |
| `used_bytes` сегодня | `5 683 281 920` — плюс 200 МБ из общей папки и ссылка Drive с `size_bytes` 5 ГБ |
| Сумма внутри `_insert_with_quota` сегодня | `5 691 670 528` — ещё плюс 8 МБ скриншота обращения |

Третья строка — **дефект, который закрывается этой картой**: проверка при вставке не исключает
`scope='feedback'`, хотя `used_bytes` исключает. Человек с заполненным личным местом получает
отказ «не помещается» на файл, который счётчик на экране считает свободным.

**Общий потолок диска (FR-K15) в коде отсутствует.** `grep -rn "disk_usage" services/` даёт
одно место — `cold.py:144` (место под холодный том), ни алерта на 80%, ни запрета на 92% нет.
Значит за общим местом сейчас не следит никто; в этой карте сторож не заводится (§14), вопрос
вынесен отдельной картой.

## 6. Контракты API

Общее для всех ручек раздела: вход — `core.webapp_actor`, право — **`files.access`**
(`core._webapp_require`), отказ без права — 403 `capability_required` словами (как сейчас).
Ни одна ручка не проверяет роли напрямую. Формат ошибки — общий конверт `docs/architecture/85`.

### 6.1. `POST /webapp/files/presign` — ссылка на загрузку

Тело: `{name, mime, size, folder_id?}`.

| Шаг | Правило |
|---|---|
| Тип | `detect_kind` как сейчас: видео, архив, исполняемое — отказ до загрузки мегабайтов |
| Размер | `size > MAX_MINIAPP_BYTES` (200 МБ) — 413 `file_too_large` |
| Папка | `folder_id` задан → папка существует и не закрыта (иначе 404 `folder_not_found`) и `folders.can_manage(who, folder)` (иначе 403 `folder_forbidden`, текст «В эту папку класть нельзя.») |
| Квота | папка общая → проверки нет, `quota_left_mb: null`; личная или не задана → как сейчас |

Ответ: `{ok, upload_url, object_key, expires_in, quota_left_mb, folder: {id, path, scope} | null}`.

### 6.2. `POST /webapp/files/commit` — подтверждение загрузки

Тело: `{object_key, name, mime, sha256?, folder_id?, description?}`.

- Ключ обязан начинаться с `p<id>/` — как сейчас (403 `file_key_foreign`).
- `folder_id` проверяется теми же двумя правилами, что в 6.1 (404/403, те же коды и тексты).
- `description`: `max_length=500`, обрезается по краям, пустая строка → `null`.
- Файл с `folder_id` получает связь `file_folder` с этой папкой вместо `Личное/<вид>`;
  `file_object.scope` = `folder.scope` (`shared` для общей папки).
- Дубль по `sha256` (только свои файлы, без `feedback`): строка не создаётся, байты удаляются,
  `duplicate: true`. Если `folder_id` при этом задан — **связь с этой папкой добавляется**
  (`add_to_folder`), иначе выбранная папка молча осталась бы без файла. Описание у найденной
  строки не перезаписывается.
- Ответ: `{ok, file: {id, name, kind, kind_word, storage, size_bytes, description, folder,
  folder_id, duplicate, duration_sec, quota_left_mb}}`.

### 6.3. `POST /webapp/files/link` — регистрация ссылки на Drive

Тело: `{url, name?, description?, folder_id?, drive_path?}`.

**Разбор адреса** (без сетевых запросов):

| Шаг | Правило |
|---|---|
| Схема | только `https`; `http://` — 400 `link_not_https` «Ссылка должна начинаться с https://» |
| Хост | `drive.google.com`, `docs.google.com` (ведущий `www.` отбрасывается); иначе 400 `link_host_not_allowed` «Ссылку можно добавить только из Google Drive — drive.google.com или docs.google.com.» |
| Форма | правило, а не список: `/file/d/<id>`, `/drive/folders/<id>`, `/drive/u/<n>/folders/<id>`, `/<вид>/d/<id>` где вид ∈ `document, spreadsheets, presentation, forms, drawings`, `open?id=<id>` и `?id=<id>` |
| id | `[A-Za-z0-9_-]{10,}`; не подошло — 400 `link_not_parsed` «Не понял адрес: скопируйте ссылку из Drive целиком — в ней есть «/file/d/…», «/document/d/…» или «/drive/folders/…».» |
| `drive_url` | канонический: файл — `https://drive.google.com/file/d/<id>/view`, папка — `https://drive.google.com/drive/folders/<id>`; форма `?id=` файл и папку не различает, поэтому считается файлом |
| `kind` | папка → `'folder'`; файл → `kind_by_name(имя)` (может быть `null`) |
| Имя | `name` из формы; иначе последний сегмент адреса, если похож на имя файла; иначе «Ссылка на Drive» / «Папка в Drive» |
| `drive_path` | из формы (необязательное поле «Где это в Drive»), обрезается; пустое → `null` |
| Остальное | `storage='drive'`, `uploaded_via='human_drive'`, `size_bytes=null`, `sha256=null`, `drive_mime=null`, `object_key=null`, `bucket=null` |
| Папка | `folder_id` необязателен; проверка та же (`can_manage`), `scope` = `folder.scope`. Без папки строка видна в «Без папки» — папка по умолчанию не выдумывается: ссылка может быть папкой фотографий, и «Мои документы» были бы ложью |
| Дубль | `drive_file_id` уже есть: своя строка или строка из общей папки → 409 `link_exists` «Эта ссылка уже есть: «<имя>».»; чужая закрытая → 409 `link_exists_other` «Эта ссылка уже добавлена в студию.» (имя не отдаётся — иначе `FR-K8` нарушен перебором адресов) |
| Аудит | `file.drive_link`, `after={name, drive_url, is_folder, folder_id}` |

Строка пишется прямой вставкой в `file_object`: `save_committed` не участвует, квота, дедуп по
`sha256` и разбор аудио/текста не вызываются — байтов у нас нет.

Ответ: `{ok, file: {id, name, kind, kind_word, storage, description, folder, folder_id,
drive_url, drive_path, size_bytes}}`.

### 6.4. `POST /webapp/files/{id}/meta` — название и описание

Тело: `{name?, description?}` — хотя бы одно поле.

- Только владелец строки. Чужой файл и несуществующий — 404 `file_not_found` (не 403: `FR-K8`).
- `name`: обрезка, 1…200 знаков; пустое — 400 `file_name_empty` «Название не может быть пустым.»
- `description`: обрезка, ≤ 500; пустая строка очищает поле (`null`); длиннее —
  400 `file_description_too_long` «Описание длиннее 500 знаков — сократите.»
- Не меняет `kind`, `storage`, связи с папками и `created_at`. Переименование garage-файла
  меняет слово и чип (расширение в имени) — это ожидаемо и покрыто тестом.
- Аудит `file.meta` с `before`/`after` только по изменённым полям.
- Ответ: `{ok, id, name, description, kind, kind_word}`.

### 6.5. `GET /webapp/files/list` — «Мои файлы» (изменения)

Контракт и видимость **не меняются** (только свои файлы, `scope <> 'feedback'`). В каждой
строке появляются поля: `kind_word`, `storage`, `description`, `drive_url`. Блок `quota`
остаётся личным: `{used, total, left}` по правилу §5.

### 6.6. `GET /webapp/files/search` — новая ручка поиска

Параметры: `q` (≤200), `folder` (≤200), `kind` (одно из `документ|текст|картинка|аудио`),
`storage` (`garage|drive`), `limit` (1…200, по умолчанию 100). Все необязательны и независимы.

| Параметр | Что сравнивается |
|---|---|
| `q` | `f.name ilike '%q%'` **или** `f.search_tsv @@ websearch_to_tsquery('russian', q)` (имя + извлечённый текст + теги — существующий индекс `046:182–228`) |
| `folder` | наше дерево: `fo.path = p` или `fo.path like p || '/%'` (с начала пути); **или** `f.drive_path ilike '%p%'` (вхождение) |
| `kind` | `kind_predicate(word)` (§4.2); неизвестное слово — 400 `kind_unknown` «Такого типа в фильтре нет: документ, текст, картинка, аудио.» |
| `storage` | `f.storage = %s` |

- **Видимость** — существующее правило `file_for_reader`, переведённое в предикат списка:
  `f.participant_id = :me` **или** файл лежит в общей папке. Грант `access_grant` поштучный и
  в список не попадает. Скриншоты обращений (`scope='feedback'`) не попадают никогда.
- Порядок: совпадение по имени (`f.name ilike`) выше, дальше `created_at desc`.
- Пустой результат — `data: []`, `count: 0`; текст «Ничего не нашлось» рисует экран (§8.3).
- Ответ: `{ok, data: [{id, name, kind, kind_word, storage, size_bytes, description, folder,
  folder_id, drive_url, drive_path, created_at}], count, query: {q, folder, kind, storage}}`.
- **Не входит:** поиск по описанию, полнотекст по файлам в Drive, Яндекс.Диск, отдельный
  интерфейс тегов.

Почему в выдаче есть файлы общей папки: их уже отдаёт экран папки (`file_for_reader`), и поиск,
который не находит файл, только что открытый человеком в папке, — это ложь. Ролей это не
касается: изменится правило видимости в E4-2 — изменится один предикат, контракт останется.

### 6.7. `GET /webapp/folder/{id}/files` — файлы папки (изменения)

В строки добавляются `kind_word`, `storage`, `description`, `drive_url`. Для `storage='drive'`
ссылка на прослушивание не подписывается: `url: ""`, `open_url` = `drive_url`. Порядок
(`position`, затем числовой префикс) не меняется.

### 6.8. `GET /webapp/files/{id}/view` — карточка файла

| Расположение | Ответ |
|---|---|
| `garage` | как сейчас (`url`, `expires_in`, `kind`, `mime`, `size_bytes`, `ext`, `folder`, `as_admin`, `cold_restored`) **плюс** `type: "garage"`, `kind_word`, `description` |
| `drive` | `{ok, id, type: "external", name, kind, kind_word, description, open_url, drive_path, folder, size_bytes: null, as_admin: false}` — без `url`, без `expires_in`, без `ext` |

Правило, которое нельзя нарушить молча: для `drive` ручка **не подписывает ключ, не зовёт
`cold.restore`, не обновляет `last_access_at` и не отвечает 404 «файл не долетел»** (сейчас
`webapp_file_view` падает именно на пустом `object_key`). Аудит `file.view` пишется с
`external: true`.

### 6.9. Скачивание: три маршрута, один отказ

`GET /webapp/files/{id}/link`, `GET /files/{id}/content`, `GET /files/{id}/link` для
`storage='drive'` отвечают 409 `file_external`:
«Это ссылка на Drive — файл открывается в Drive, копии у студии нет.» Байтов у нас нет,
и подписывать нечего.

Чат-контракты по форме не меняются: `GET /files/{id}` и `GET /files` отдают те же новые поля
(`storage`, `description`, `drive_url`), `GET /files/{id}/content` и `/files/{id}/link` —
409. Тексты карточки файла в чате (`services/tg-gateway`) в этой карте не правятся: если бот
покажет у ссылки Drive «0 Б» вместо «ссылка», это отдельная карта (§15).

### 6.10. `DELETE /webapp/files/{id}` и ZIP папки

- Удаление не меняется: только владелец, мягкая метка `deleted_at`, связи `file_folder`
  снимаются, байты не трогаются. Для `drive`-строки удаляется только запись — объектов нет.
- `GET /folders/{id}/zip`: `drive`-строки в архив не попадают (у них нет `object_key`),
  их имена уходят в `skipped` и в аудит `folder.zip`. Ответ остаётся ZIP-потоком; отдельного
  «частичного» статуса не вводим.

### 6.11. `GET /webapp/folders` — без изменений

Дерево общих и личных папок отдаётся как сейчас. Выбор папки при загрузке берёт **оба** списка
двумя вызовами (`scope=shared`, `scope=personal`) — новый параметр не нужен.

## 7. Права: на уровне права, не роли

| Действие | Проверка | Где живёт |
|---|---|---|
| Вход в раздел и в любой его экран | право **`files.access`** | `webapp.py:315–316`, `369–370`; `core._webapp_require` в теле ручки |
| Загрузка файла (presign/commit) | `files.access` + папка: `folders.can_manage` | `api/files.py` |
| Регистрация ссылки на Drive | `files.access` (сужение до отдельного права — E4-2) | `api/files.py` |
| Правка названия и описания | `files.access` + владелец строки | `api/files.py` |
| Поиск и чтение выдачи | `files.access` + правило `file_for_reader` (свой файл, общая папка, `feedback.triage` для вложения обращения, грант админа) | `files_store.py` |
| Удаление файла | `files.access` + владелец строки (404 на чужой) | `files_store.remove` |
| Чтение и правка папок | `files.access` + `folders.can_manage` (общая — admin/org, личная — владелец) | `folders.py` |

Права берутся из `v_participant_capabilities` (`core._caps_for`), а не из списка ролей. Ролевой
список `SHARED_ROLES = {"admin","org"}` в `folders.py:18` в этой карте **не расширяется и не
сужается** — его пересмотр это E4-2. `feedback.triage` проверяется как право, а не как роль
(так уже сделано в `file_for_reader`, `files_store.py:419–427`).

Новых прав в матрицу эта карта не вводит. Появится ли отдельное право «регистрировать ссылку»
или «грузить в общую папку» — решает E4-2 после анкеты.

## 8. Экран

Экраны остаются теми же тремя (`/webapp/files`, `/webapp/folder`, `/webapp/file`); новых
разделов в `SECTIONS` и `SCREEN_CAPS` нет.

### 8.1. Загрузка

```
Что загружаем:  (•) В студию        ( ) Ссылка на Drive
Куда:           [Личное — по виду файла ▾]     ← общие папки и свои личные, путями
Что это:        [textarea, ≤500]               ← подсказка под полем
```

- Первый пункт списка папок — «Личное — по виду файла» (значение пустое): поведение сегодняшнего
  дня, папку выбирает сервер по виду (`FR-K11`). Ниже — общие папки путями, затем личные папки
  человека.
- Поле описания одно на партию (V-124): текст уходит в каждый файл пачки, потом правится
  у каждого отдельно. Подсказка: «Необязательно. Поиск по описанию не идёт — ищет по имени,
  папке и типу.»
- Когда выбрана общая папка, под полосой места появляется строка «В общую папку: личное место
  не расходуется.» — иначе полоса личного места врёт про смысл действия.
- Переключатель «Ссылка на Drive» скрывает выбор файлов и показывает форму ссылки (§8.2).

### 8.2. Ссылка на Drive

```
Ссылка:          [url]
Название:        [input]           ← пусто = взять из адреса
Куда:            [тот же список папок, «Без папки» по умолчанию]
Где это в Drive: [input]           ← необязательно, подсказка «Спектакли/Пурга»
Что это:         [textarea, ≤500]
[Добавить ссылку]
```

- «Где это в Drive» — единственный источник `drive_path` (§2 п.3). Подсказка: «Необязательно.
  Если написать, файл найдётся фильтром по папке.»
- После успеха: тост «Ссылка добавлена: «<имя>».» и перерисовка списка.
- Отказ по дублю показывается текстом сервера (в форме, не тостом), поле не очищается.

### 8.3. Поиск и чипы

Над сеткой «Мои файлы»: поле `q` с подсказкой «Имя, папка или тип» и ряд чипов
**Все · Документы · Текст · Картинки · Аудио · Ссылки**.

- Любой активный фильтр (чип, `q`, папка) переводит сетку на `/webapp/files/search`; пустой
  набор фильтров возвращает `/webapp/files/list`. Над сеткой появляется подпись
  «Найдено: N» вместо «Мои файлы», чтобы разница в видимости (поиск видит и общие папки)
  не выглядела пропажей.
- Строка «Без папки» в дереве остаётся локальным фильтром сетки (`V-065`), в поиск не ходит.
- **Поиск внутри папки** — на экране папки: там же поле `q` и те же чипы, и каждый запрос идёт
  с `folder=<полный путь этой папки>`. Это и есть ответ на вопрос «что в папке Пурга»;
  дерево на «Файлах» продолжает открывать папку, а не фильтровать сетку.
- Пустой результат: заголовок «Ничего не нашлось», текст «Ищите по имени, папке и типу.
  Описание и содержимое файла в поиск не входят.» — без «возможно, вы имели в виду».
- Плитка: слово из `kind_word`; для `storage='drive'` вместо размера — «в Drive».

### 8.4. Карточка файла

| Что | `garage` | `drive` |
|---|---|---|
| Подпись под именем | размер · слово · папка | «папка в Drive» или «ссылка» · наша папка |
| Основное действие | «Открыть в браузере» + «Скачать» | **только** «Открыть в Drive» (primary) |
| Пояснение | как сейчас | «Это ссылка на Drive — файл открывается в Drive, копии у студии нет.» |

## 11. Критерии приёмки

Полный гейт — `env -u PYTHONPATH .venv/bin/python scripts/check_done.py`.

1. **AC-1.** Миграция накатывается на пустую базу (`alembic upgrade head`), повторный прогон
   SQL идемпотентен; `scripts/gen_alembic_revisions.py --check` — код 0;
   `tests/unit/test_migrations_registry.py` зелёный (70 файлов, голова `073_…`).
2. **AC-2.** `storage` — `not null default 'garage'`; `description`, `drive_url`, `drive_path`,
   `drive_mime` допускают `null`; `file_object_kind_check` принимает `folder` и по-прежнему
   отвергает `video`.
3. **AC-3.** F11, F12, F13 зелёные на пустой базе и на базе после backfill; нарушение каждого
   ловится отдельным тестом (garage без `object_key`; drive с `object_key`; `folder` с
   `storage='garage'`).
4. **AC-4.** Backfill: строка-заглушка (`drive_file_id` без `object_key`) становится
   `storage='drive'` с собранным `drive_url`; после миграции F11 и F12 зелёные; число
   перенесённых строк печатается `NOTICE`. Тест воспроизводит случай «до миграции».
5. **AC-5.** `kind='folder'` проходит, `kind='video'` падает по ограничению; `save_committed`
   и `detect_kind` значение `folder` не выставляют ни на одном пути.
6. **AC-6.** Квота по правилу §5: файл в общей папке не входит; ссылка Drive с
   `size_bytes = 5 ГБ` не входит; скриншот обращения не входит; перенос файла в общую папку
   выводит его из квоты, перенос обратно — возвращает; **вставка** использует то же правило
   (файл в общую папку проходит при заполненной личной квоте).
7. **AC-7.** `file_ext` совпадает с `file_kind.extension` на списке из 12 имён (включая
   `.docx`, `x.`, `Смета.PDF`, `архив.tar.gz`, `a.b.c`, имя без расширения); расхождение —
   красный тест. Имя `..` — известное расхождение, оба значения вне всех множеств, записано
   в docstring теста.
8. **AC-8.** Чипы: `(text,Смета.pdf)` → «документ» и не под «Текст»; `(text,заметки.md)` →
   «текст»; `(null,IMG_1.xyz)` → «файл», виден только под «Все»; `(image,Афиша.png)` →
   «картинка»; `(audio,трек.mp3)` → «аудио»; `kind='folder'` — ни под одним чипом;
   у каждой строки ровно 0 или 1 чип (свойство на наборе пар).
9. **AC-9.** Один список расширений: `grep -rn "docx" services/tool-api/app/pages/ services/tool-api/app/api/` — пусто;
   `grep -rn "KIND_WORD\|kindWord(" services/` — пусто; `TEXT_EXT|IMAGE_EXT|AUDIO_EXT|DOC_EXT|PLAIN_EXT`
   встречаются только в `app/file_kind.py` и `app/files_store.py` (импорт).
10. **AC-10.** Загрузка с `folder_id` кладёт файл именно в эту папку (`folder_id` в ответе и
    в `file_folder`), а не в `Личное/<вид>`; папка без прав — 403 `folder_forbidden`;
    несуществующая — 404 `folder_not_found`; без `folder_id` поведение прежнее.
11. **AC-11.** Загрузка в общую папку: строка получает `scope='shared'`, `used_bytes` не
    меняется; перенос этой строки в личную папку возвращает её в квоту (тест на оба перехода).

## 15. Границы

- **Кода и миграций здесь нет** — это спецификация.
- **Роли не проектируются** (§14).
- **В Google не ходим:** ни проверки доступа к файлу, ни чтения MIME/размера/заголовка.
  Следствие названо честно: имя и размер ссылки могут быть неточными, пока файл не открыли.
- **Ссылка не становится нашим файлом:** байты не копируются, скачивания нет.
- **Публичные ссылки и шаринг наружу** — вне модели (`86` §10).
- **Полнотекст по файлам в Drive, поиск по описанию, Яндекс.Диск** — не здесь.
- **Общий потолок диска (FR-K15) не реализуется:** в коде его нет, за общим местом сейчас
  никто не следит; сторож — отдельная карта. Объём риска: общая папка не ограничена ничем,
  кроме свободного места на диске.
- **Уборка брошенных загрузок (FR-K4) не делается:** `presign` без `commit` оставляет объект
  в Garage (до 200 МБ на попытку); механизма уборки нет — отдельная карта.
- **Зеркало папок Drive в наше дерево не заводится** (`189` §D3): путь Drive — метаданные.
- **`participant.drive_folder` не удаляется** (мёртвое поле, `189` §9): уборка — отдельная карта.
- **Новых прав в матрицу не вводится.**
- **Тексты карточки файла в чате не правятся:** форма контрактов чата не меняется (409 на
  скачивание ссылки), но подпись «0 Б» у ссылки Drive в карточке бота — отдельная карта.
