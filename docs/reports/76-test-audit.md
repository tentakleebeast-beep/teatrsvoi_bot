# 76. Аудит тестов: слияние вариантов и отчёт (Ш-51.2)

Дата: 28.10.2026. Продолжение Ш-51.1 (`docs/reports/72`, итерация 57). Задача — разобрать
крупные файлы тестов по правилу «оставить / слить / удалить» и зафиксировать результат
числами, а не намерениями.

## 1. Правило разбора

| Решение | Когда применяется |
|---|---|
| **оставить** | тест защищает деньги, права, данные или конкретный дефект; его падение означает реальную поломку |
| **слить** | несколько тестов проверяют **варианты одного правила** — сводятся в один параметризованный тест, покрытие не теряется |
| **удалить** | дубль уже проверенного, тест собственной реализации, устаревшее поведение |

Вариант одного правила — это разные значения на входе при одной и той же проверке на выходе
(например, «неизвестная политика» и «неизвестный режим»). Если у вариантов разные исходы
(просроченный код даёт `code_expired`, несуществующий — `code_not_found`), они остаются
параметрами одного теста, а не отдельными функциями.

Дубли, тесты собственной реализации и устаревшее поведение **не найдены** — ни один тест
не удалён. Сокращение достигнуто только слиянием вариантов, все проверяемые факты сохранены.

## 6. Правило, действующее с этого шага

**Новый тест без ID требования или дефекта в имени или docstring не принимается** —
`scripts/test_audit.py --strict` в проверках релиза. Варианты одного правила пишутся
параметрами одного теста, а не копией функции: сокращается не покрытие, а число повторов.
