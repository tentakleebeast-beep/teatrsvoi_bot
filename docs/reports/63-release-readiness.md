## 2. Блокеры раскатки (инфраструктура)

### R-1. Нет `requirements.txt`
`pyproject.toml` содержит только конфиг ruff/pytest, блока `[project]` с зависимостями нет.
Runbook (`docs/infrastructure/35`, шаг 2) делает `pip install -r requirements.txt` — на чистом
сервере команда упадёт. **Прод не поднимется по инструкции.**

Решение: зафиксировать зависимости (`uv pip freeze` → `requirements.txt`), добавить в CI
проверку «сервис импортируется на чистом venv».

### R-2. Dockerfile собирал плоскую раскладку — сервис падал при старте
`services/tool-api/Dockerfile` копировал `app` в `/app/app`, а код вычисляет
`Path(__file__).resolve().parents[3] / "bot" / "manifests"` — в контейнере это выше корня,
`IndexError: 3`. Сборка проходила, а сервис не поднимался.
Плюс `COPY requirements.txt` при отсутствующем `requirements.txt` (R-1) валил саму сборку.

Исправлено: оба Dockerfile повторяют структуру репозитория (`services/<svc>/app`, `bot/`, `config/`),
добавлены `requirements.txt` и healthcheck. Проверено: `docker build` обоих образов проходит,
контейнер tool-api отвечает `{"ok":true,...,"db":"postgres"}` на `/health` с реальной базой.

### R-3. `MODE=webhook` не реализован
`MODE` есть в `.env.example` и runbook (`polling | webhook`), но в коде не читается ни разу.
Caddy в runbook проксирует `/webhook/*` только в n8n; маршрута для гейтвея нет.
Фактически доступен только polling.

Следствие: на публичном домене придётся держать исходящий polling-процесс. Это работает,
но: при двух инстансах Telegram отдаёт `409 Conflict` (runbook это упоминает), а
масштабирование и health-проверка «снаружи» невозможны. Для релиза — приемлемо, для
роста — нет. Решение: либо честно убрать `MODE` из документации, либо реализовать webhook.

### R-4. Скриптов эксплуатации не было в репозитории (закрыто)
`scripts/backup.sh`, `scripts/watchdog.sh` описаны в `docs/infrastructure/35` (§8, §9),
но в репозитории их не было: инструкция предлагала создать их вручную на сервере,
то есть без версионирования и без проверки.

Сделано: `scripts/backup.sh` и `scripts/watchdog.sh` лежат в репозитории. Проверено:
бэкап снял дамп 224 КБ и проверил его `pg_restore --list`; watchdog молчит при норме
и возвращает exit 1 с перечнем проблем при недоступном n8n и отсутствии свежего бэкапа.

### R-5. Деплоя в CI нет
`.github/workflows/tests.yml` — только lint + compileall + pytest. Ни сборки артефакта,
ни публикации, ни smoke после выката. Обновление — руками по runbook §10.
