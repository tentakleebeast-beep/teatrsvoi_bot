## 3. Находки

### R-1. `tool-api/main.py` — 4173 строки, 86 маршрутов (высокий)
Файл смешивает HTTP-слой, доступ, расчёты назначения, бюджет, календарь, финансы и
админские операции. Любая правка — риск задеть соседний домен; навигация по нему уже
дороже, чем написание кода.
**Риск:** конфликты при параллельной работе, забытые ветки (в этом проекте повторялись дважды —
импорт занятости C-2, проверка входа L-004).
**Что делать:** вынести роутеры по домену — `budget.py`, `schedule.py`, `events.py`,
`admin.py`, `webapp_api.py`, `finance.py`, `people.py`; `main.py` оставить сборкой приложения
(создание `FastAPI`, зависимости, обработчики ошибок) до ~400 строк.

### R-2. `gateway/main.py` — 2930 строк, 82 обработчика (высокий)
Обработчики, тексты, клавиатуры, состояния и вызовы API в одном файле. Тексты уже
дублируются (три варианта «Мои взносы» сводили вручную), состояния соседствуют с логикой.
**Риск:** мёртвые обработчики (F-9), «кнопка живёт дольше состояния» (B-1…B-8), «кнопки меню
съедаются состоянием» (инцидент 28.10) — все три класса росли именно из этой плотности.
**Что делать:** `aiogram.Router` по домену (`menu`, `budget`, `availability`, `assign`,
`admin`, `feedback`, `intro`, `profile`) и отдельный `texts.py` со всеми строками.

### R-3. `webapp_page.py` — 1424 строки инлайн-HTML (средний)
Пять страниц собираются как Python-строки; общий JS-помощник `api()` скопирован 6 раз,
`auth()` — 3 раза. Правка одной страницы не видна в другой.
**Что делать:** шаблоны в `services/tool-api/templates/*.html` и статический `app.js`
(или хотя бы один общий блок `PAGE_JS`), проверка `node --check` сохраняется.

### R-4. Конфигурация читается на импорте (высокий)
16 `getenv` на уровне модуля в `tool-api`, 4 в гейтвее. Из-за этого тесты подменяют
`os.environ` до импорта, а новые модули ломают изоляцию; значение по умолчанию, забытое в
коде, незаметно уезжает в прод (так уже было с `WEBAPP_SECRET` и `idempotency_key`).
**Что делать:** один объект `settings` (dataclass/pydantic-settings), создаётся в фабрике
приложения и передаётся явно; `getenv` в модулях запрещается правилом линтера.

### R-5. 14 широких `except Exception` (средний)
Часть ловит внешние сбои и это правильно (Google, Telegram, fetch). Но там же маскируются
программные ошибки: опечатка в имени поля станет `ok:false` с текстом «недоступно»,
и дефект проживёт до пользователя (так было с `_participant_out`).
**Что делать:** ловить конкретные типы (`httpx.HTTPError`, `googleapiclient.errors.HttpError`,
`psycopg.OperationalError`), остальное — 500 и запись в `audit_event`.

### R-6. Дубли форматирования (средний)
`money()` есть в гейтвее и в `notifications.py`, у скриптов свои варианты; `api()`/`auth()`
по страницам. Разъезд форматов уже виден в рассылках и в чате.
**Что делать:** `services/shared/format.py` и один загрузчик окружения для скриптов.

### R-7. Нет проверки типов (средний)
CI: `ruff` + тесты + образы. `mypy`/`pyright` нет, хотя аннотации в проекте есть почти везде.
**Что делать:** пилот `mypy --strict` на пяти чистых модулях (`rules`, `slots`,
`window_policy`, `assign`, `subject`), потом расширять.

### R-8. Скрипты повторяют загрузку окружения (низкий)
Часть уже переведена на `run_service.build_env`; остальные — свои варианты с инлайн-комментариями
(` #`). Наивный сплит уже ронял запуск (`TZ_OFFSET_HOURS=4    # Самара`).
**Что делать:** `scripts/_cli.py` — корень проекта, `.env`, общие аргументы.

### R-9. Inline-JS без сборки (низкий)
Отмечено в отчёте 66: все пять страниц отдают один и тот же скрипт, интеграционных тестов
на поведение нет.
**Что делать:** `static/app.js`, e2e хотя бы на три сценария (сетка, профиль, поиск окон).

### R-10. Бизнес-константы рядом с HTTP (низкий)
Порог 100 000 ₽, рабочий день 08–23, «15 минут» — часть в `rules.py`, часть в `main.py`.
**Что делать:** все константы правил — в `rules.py`/`config/`, чтобы правило и его значение
жили в одном месте.

## 4. План рефакторинга (после релиза, по этапам)

| Этап | Что | Критерий готовности |
|---|---|---|
| A | `settings`-объект и запрет `getenv` в модулях (R-4) | нет `getenv` на уровне модуля; тесты не подменяют `os.environ` |
| B | Роутеры `tool-api` по домену (R-1) | `main.py` ≤ 400 строк, маршруты в `app/api/*.py`, все тесты зелёные |
| C | Роутеры гейтвея + `texts.py` (R-2) | `main.py` ≤ 500 строк, тексты в одном модуле, обработчики по домену |
| D | Общие `format.py`/`_cli.py`, страницы в шаблоны (R-3, R-6, R-8) | нет дублей `money`/`api`, шаблоны вне Python |
| E | `mypy` на чистых модулях, узкие `except` (R-5, R-7) | CI с `mypy`, нет широких `except` вне адаптеров |

Порядок именно такой: A и B безопасны (не меняют поведение), C — после них, D/E — мелочи
по ходу. Никаких «перепишем с нуля»: каждый этап заканчивается зелёными проверками.

## 5. Что не трогаем

- Схему БД и миграции — рефакторинг кода не повод трогать данные.
- `db/init` как источник схемы — переезд на alembic не даст ничего при текущем размере.
- Состояния FSM (aiogram) — они простые; выносить в библиотеку не нужно.
