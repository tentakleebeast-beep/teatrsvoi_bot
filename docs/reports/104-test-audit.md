# 104. Аудит тестов после рефакторинга: 1762 случая, которые не ловят баги

Дата: 01.11.2026. Запрос владельца: «тестов почти полторы тысячи, а баги пролезают —
сколько на самом деле рабочих функций, все ли используются и работают, по каким
принципам появилось столько тестов, нужен ли тестировщик в канбане».

Снимок измерений: коммит `4f23d71` (репозиторий **двигался во время аудита** — 11
коммитов от `ce7fd85`, поэтому числа ниже — снимок, а не вечная истина; расхождение
по числу тестовых функций внутри одного аудита: 1257 → 1302).

## 1. Как воспроизвести

```bash
cd "~/repos/Projects/teatrsvoi_bot Project"
# сбор без запуска: сколько случаев реально собирается
env -u PYTHONPATH .venv/bin/python -m pytest --collect-only -q -p no:warnings
# основной прогон с покрытием (браузерные не входят: они идут отдельным job)
env -u PYTHONPATH .venv/bin/python -m pytest -p no:warnings --ignore=tests/webapp \
    --cov=services --cov=scripts --cov-report=term-missing
# дисциплина «у теста есть ID требования/дефекта»
env -u PYTHONPATH .venv/bin/python scripts/test_audit.py --strict; echo $?
```

`env -u PYTHONPATH` обязателен: глобальный `PYTHONPATH` перебивает пакеты проекта.

## 5. Четыре дефекта процесса (с доказательствами)

### 5.1 Браузерные тесты гоняются только на Chromium

`tests/webapp/conftest.py:130` — `if engine != current: pytest.skip(...)`. В CI
(`.github/workflows/tests.yml`, job `webapp`) стоит `--browser chromium`, значит все
профили iPhone (WebKit) **скипаются**: `test_miniapp_devices.py` — 4 профиля, 3 экрана,
половина случаев не выполняется. iOS — ровно там, где владелец поймал наложение текста —
в гейте не проверяется вообще.

### 5.2 JS проверяется на синтаксис, а не на поведение

576 строк JavaScript живут внутри python-констант (`app/pages/*.py`, `webapp_page.py`).
`tests/unit/test_webapp_pages_js.py` — это `node --check`: «файл парсится». Отсюда
дефекты вида «форма пишет в несуществующую функцию» (`ef9e5cf`), «хаб падает с
`KeyError: 0`» (`12e4517`) — синтаксис цел, поведение сломано.

### 5.3 Тест проверял наличие, а не доставку

`/webapp/ui.css` и `/webapp/shell.js` отдавали 500 при зелёном наборе: тест видел
`<link href>` в разметке и не запрашивал файл (`test_static_contract.py` появился уже
после дефекта, `docs/reports/104`-предшественник — коммит `3d9816a`). Плюс список
`LEGACY` в `test_miniapp_system.py` — **15 экранов** исключены из проверок дизайн-системы
(эмодзи, шрифт, цели 48 px, горизонтальный скролл).

### 5.4 Правило «тест без ID не принимается» сгнило

`docs/development/26` и `docs/reports/76` объявили `scripts/test_audit.py --strict`
частью релизных проверок. Сейчас:

```
ИТОГО  1302 функции  118 без обоснования  →  exit 1
```

И в CI скрипта нет: job `lint` запускает только `ruff` и `compileall`, локальный
pre-commit хук — `ruff` по staged-файлам и `check_invariants.py`, но не `test_audit.py`.
Правило, которого никто не проверяет, перестаёт существовать: 118 тестов уже не отвечают
на вопрос «что я защищаю».

Отдельно: `docs/development/58-regression-test-plan.md` (27.10) устарел — «полный прогон
одной командой `pytest -q`» молча скипает 236 браузерных случаев; в матрице нет раскола
роутеров, каталога кодов ошибок, двух движков и проверки статики.

## 7. Нужен ли тестировщик в канбане

Цифры доски (`scripts/kanban_metrics.py --board teatrsvoi`, 7 дней):

| Метрика | Значение |
|---|---:|
| Закрыто карт | 21 |
| Медиана цикла | 1.4 ч |
| Прогонов на карту | 2.28 |
| **Доводок ревью** | **1 (0.05 на карту)** |
| **Хвостов после закрытия** | **11 (0.52 на карту)** |
| Авралы (таймаут / падение) | 4 / 3 |
| В очереди | 14 |

Это и есть ответ: ревьюер сейчас практически не возвращает работу (0.05 доводки на
карту), а половина карт (0.52) требует хвоста уже после `done`. Дефекты вылезают не на
ревью, а после него — в WebView, в нажатиях, в отдаче статики.

Рекомендация — не «тестировщик на каждую карту» (это удвоит прогоны при медиане 1.4 ч и
не покроет то, что уже покрыто), а три вещи:

- **P0. Дыры закрыть проверками в CI, а не ролью.** Второй браузерный job с WebKit;
  `test_audit.py --strict` и `check_invariants.py` в job `lint`; запуск браузерных
  тестов не только на Chromium. Это дешевле любого бота и не даёт правилу зарасти.
- **P1. Профиль `worker-test` по риску.** Отдельный воркер поднимается не на каждой
  карте, а на картах, трогающих Mini App/JS, статику, токены и авторизацию, контракт
  ошибок. Его работа: два движка, проверка отдачи каждого подключённого ассета,
  репро-тест на каждый дефект, запрет «done» без воспроизведения в браузере.
- **P2. Ревьюеру — правило «нет теста на поведение — не done»** и обязательное
  приложение вывода полного гейта к карте (сейчас доводок 0.05 — ревью формально).

Отдельный постоянный тестировщик на каждую карту не нужен: узкое место — не роль, а
проверки без владельца и отсутствие второго движка.
