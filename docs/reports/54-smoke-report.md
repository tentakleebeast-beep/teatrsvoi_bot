## 2. Блокирующие

### D-1 — админские команды физически не отвечали

`/invite`, `/grant`, `/role` падали с `TelegramBadRequest: can't parse entities`.
Причина: глобальный `parse_mode=HTML` и тексты с «сырыми» угловыми скобками —
`/grant <имя> <возможность> on|off`.

Задевало ровно те команды, которыми выдаются права. В логах — два трейсбека, апдейты
помечены «не обработано».

**Исправлено.** Тексты без угловых скобок, у двух сообщений `parse_mode=None`.
Добавлен тест `tests/unit/test_gateway_html_safe.py`: он сканирует все строки,
уходящие в Telegram, и падает при появлении сырого тега.

### D-2 — роль `student` не удалена на уровне схемы

Миграция `017` поправила одно ограничение из трёх. Вставка `student` по-прежнему
проходила в `participant`, `participant_role` и `invite_code` — то есть инвариант
«роли только admin/org/troupe» держался на коде, а не на базе.

**Исправлено** миграцией `030`: все три ограничения сужены, существующие коды и роли
`student` переведены в `troupe`.

## 3. Важные

### S-2 — «предпросмотр» назначения писал в базу

`POST /tools/events/preview` создавал строку `slot_proposal` при каждом вызове.
Проверка «покажи, что получится» оставляла мусор: за прогон появились три заявки.

**Исправлено:** по умолчанию предпросмотр ничего не пишет. Заявка создаётся только
с `persist=true` — так делают бот и форма, потому что им нужен `proposal_id` для
подтверждения. Тест проверяет оба режима.

### S-1 — отрицательный `min_hours` давал «нет окон» вместо ошибки

Запрос с `min_hours: -5` возвращал `200` и пустой список. Клиент не мог отличить
«свободного времени нет» от «запрос бессмысленный».

**Исправлено:** `min_hours` ограничен 1…12, `days` — 1…90, `day_start/day_end` — 0…24,
`limit` — 1…20. Валидация на уровне pydantic, ответ `422`.

### M-1 — сетка принимала нерабочие часы

Валидация пропускала `from_hour: 2`, а лист рисует только 8–23. Отметка записывалась,
но была невидима: день выглядел частично пустым. В данных при этом есть 425 строк
с `hour = 0` — след старого импорта.

**Исправлено:** запись разрешена только в 8–24. Старые данные не удалялись: они
участвуют в расчёте окон, но в интерфейсе не показываются. Нужна политика ретенции
(см. §6).

## 5. Что проверено и работает

- Авторизация: без токена `401`, мусорный `401`, неизвестный актор `403`, верный — данные.
- Права считаются по capability, а не по роли.
- Все 4 страницы Mini App: `200`, ключевые элементы, JS без синтаксических ошибок,
  ошибок в консоли нет.
- Цикл отметки в сетке: запись → чтение → откат.
- Вёрстка 390px: горизонтального скролла `body` нет, широкие таблицы скроллятся внутри.
- Инварианты: 8 проверок, код выхода 0.
- Педагоги связаны с дисциплинами, роли привязаны к проектам, осиротевших записей нет.

## 7. Вывод

Система работоспособна: сквозной путь от занятости до уведомлений проходит,
ни один эндпоинт не дал `500`, данные сходятся с инвариантами.

Главный урок: **тесты ловили логику, но не контракт с внешним миром**. Падение
`/grant` видел только Telegram, `student` в схеме — только `psql`, невидимые часы
сетки — только браузер. Поэтому в набор добавлены проверки: тексты бота на HTML,
ссылки документации, синтаксис JS страниц.
