## Как исполнять

0. В конце тика увеличь счётчик **Итерация** в шапке этого файла на 1 и используй его
   номер в краткой сводке админу. Сводка — ровно три строки, без подробностей:
   `Итерация N` / `Сделано: …` / `Дальше: …`, не длиннее 300 символов.
   **Исключение — финальный тик:** когда закрыт последний шаг и открытых вопросов нет,
   в сводку добавляется четвёртая строка сверх лимита, дословно:
   `БОТ ТЕАТРА ГОТОВ К РЕЛИЗУ!!!`

1. Взять **первый шаг со статусом `[ ]`**, сделать только его, не забегая вперёд.
2. Проверить: `env -u PYTHONPATH .venv/bin/python -m pytest -p no:warnings -o addopts="" -q`,
   `.venv/bin/ruff check .`, `env -u PYTHONPATH .venv/bin/python scripts/check_invariants.py`,
   `env -u PYTHONPATH .venv/bin/python scripts/check_registers.py`.
3. Закоммитить один коммит на шаг с ID дефекта/требования и `(INT-002)` или `(INT-003)`.
4. В этом файле заменить `[ ]` на `[x]` и дописать хеш коммита, затем закоммитить файл.
5. Остановиться и написать короткий отчёт: что сделано, что дальше.
6. **Обратная связь — не шаг этого плана** (V-024, 30.10.2026). Разбор ведёт отдельное
   задание «teatrsvoi: разбор обратной связи» каждые 10 минут через
   `scripts/feedback_queue.py`: оно отвечает автору и пишет журнал `feedback_answer`,
   нерешаемое уходит в `docs/reports/74-questions.md` (`V-NNN`). Этот тик обращений не
   читает и не отвечает на них, чтобы два задания не спорили за одно обращение. Перед
   объявлением готовности полный аудит входящих всё равно обязателен: каждое обращение —
   либо закрыто, либо в плане, либо в «После релиза», либо `V-NNN`.
7. **Новая задача, найденная по ходу, становится шагом только если это блокер релиза**
   (деньги, потеря данных, сценарий, из-за которого бот молчит или врёт). Всё остальное —
   в раздел «После релиза» ниже, одной строкой, без номера шага. Так план сходится,
   а не удлиняется на каждом тике.
8. Когда все шаги `[x]` — удалить задание планировщика «teatrsvoi: возобновление работ».
9. **Канал сводок (V-011, 29.10.2026).** Полный текст сводки — только в Telegram через
   `scripts/notify_admin.py`; в чат Hermes — одна строка «итерация N готова». Интервал
   задания — 7 минут (V-012), отдельного частого задания по обращениям не заводим.
10. **Правила качества работы** (подробно — `docs/development/26-process-and-git.md` §7a):
   найденный дефект чинится классом, а не точкой — проверить соседние ветки; каждый новый
   тест получает в имени или docstring ID требования или дефекта (`scripts/test_audit.py`);
   ссылки только на существующие файлы; сервисы — только через `scripts/start_services.py`;
   сводки — только через `scripts/notify_admin.py`; зависимость шага от другого отмечать
   словами «после Ш-NN».

Сервисы после правок перезапускать одной командой (Ш-29):

```
env -u PYTHONPATH .venv/bin/python scripts/start_services.py
```

Скрипт сам читает `.env` (инлайн-комментарии отрезаются, как в консоли: иначе
`int()` на `TZ_OFFSET_HOURS` падает), чистит `PYTHONPATH`, перезагружает
launchd-агентов с `--takeover` и ждёт готовности фактами: `/health` отвечает
`ok: true`, поллер `tg-gateway` ровно один и держит замок. Код выхода 0 — сервисы
готовы, 1 — печатает проблемы. `--direct` — поднять процессами без launchd,
`--service gateway` — только один сервис, `--json` — машинный вывод.

Запуск через оболочку с флагом команд и heredoc с шебангом в тике **не работают**:
политика одобрений режет их как «shell command via flag» и «shell execution via
heredoc». Поэтому рецепт — только скрипт из репозитория; правки документов из тика —
временным `.py`-файлом в scratch.
