## Тексты

Тексты собраны в `texts.py`; повторяющиеся формулировки стали константами
(`TITLE_DUES`, `BTN_CANCEL`, `STATUS_DONE`, `PREFIX_TARIFF`, …). Проверка скриптом
по AST: до работы 54 пользовательские строки встречались в двух и более модулях,
после — 0. «Мои взносы» теперь одна константа `texts.TITLE_DUES` (ещё одно
упоминание — в докстринге функции `dues_text`).

Строки не переписывались: замена — литерал → константа с тем же значением.
`config/ui-texts.yaml` по-прежнему переопределяет подписи меню поверх умолчаний.

## Поведение

* Набор и порядок обработчиков сверены с исходным файлом автоматически: 94 из 94,
  внутри каждого роутера порядок исходный, catch-all `on_text` остаётся в первом
  роутере (`menu`), как и раньше.
* Остаточное отличие: обработчики разных доменов в исходнике были перемешаны
  (например, `slots_more` объявлен раньше `menu_item_cb`), а роутеры подключаются
  блоками. Инверсии возможны только между обработчиками с разными фильтрами;
  регрессионные тесты порядка (`test_gateway_routing`, `test_text_routing`,
  `test_assign_routing`) зелёные.
* Роутеры подключены в порядке первых обработчиков в исходнике:
  menu → availability → budget → feedback → profile → admin → assign → files →
  agent → intro → fallback.
* `build_dispatcher()` кэширован: роутеры — модульные объекты, подключить их
  можно только к одному `Dispatcher` за процесс (иначе aiogram бросает
  «Router is already attached»).

## Найденные и исправленные по ходу дефекты

1. `_bot` был глобалом `main.py`, а использовался из обработчика регистрации и
   `main()`; вынесен в `runtime.py` (иначе после разреза — два разных бота).
2. Параметр `texts` в `keyboards.help_text` перекрывал модуль `texts` —
   `texts.MENU_HELP` читался у словаря. Параметр переименован в `ui_texts`.
3. Локальный словарь `texts` в `routers/menu.py` (`on_text`, ветка кода
   регистрации) так же перекрывал модуль — переименован в `code_texts`.
4. `logging.basicConfig(...)` был вызовом на уровне модуля и при разрезе терялся;
   перенесён в `config.py` (импортируется раньше остальных).

## Тесты

Гейтвей в unit-тестах грузился файлом `main.py` и брал из него функции и тексты.
После разреза добавлен `tests/unit/gateway_modules.py`:

* `namespace()` — плоский вид всех модулей: `gw.dues_text` находит функцию в
  `texts`, `gw.error_code` — в `errors`; `monkeypatch.setattr(gw, "api", ...)`
  уходит в `core`, то есть туда, откуда её читают роутеры;
* `source()` — исходники модулей подряд для тестов, которые проверяют код
  текстом (порядок обработчиков, наличие кнопки, обработчик `av_time_text`).

Тесты правились только в местах загрузки модуля и точки подмены: утверждения о
поведении не ослаблялись. `test_settings_single_source` теперь проверяет, что
настройки берёт `config.py` (в гейтвее `main.py` больше не читает окружение).
