# 184. Сводный журнал изменений: v0.11.0 → v0.12.0

Диапазон: тег `v0.11.0` (`b327e55`) → `v0.12.0` (`2b4d7c6`), 15.11–22.11.2026.
Объём: 174 коммита (122 без мержей), 293 файла, +30 178 / −5 564 строки, пять миграций.
Источник: `CHANGELOG.md` по разделам версий плюс `git log` диапазона.

## Опросы

- **v0.11.1** — организатор получил `poll.manage` (миграция `066`): создаёт опросы сам, без
  администратора (V-088). Конструктор без `poll_id` теперь проверяет право — закрыта дырка D2.
- **v0.11.2** — вопрос с ответом текстом или числом получил кнопку «Ответить сообщением»:
  раньше человек упирался в «Пропустить»/«Дальше». Состояние ожидания сбрасывается на
  закрытом опросе, приглашение из очереди несёт ту же кнопку.
- **v0.11.3** — экран «Мои опросы» в Mini App: активные сверху, пройденные со статусом
  «пройден», вход — строка на Главной с маркером непройденных; экран открыт адресату без
  права `poll.manage` (V-094 «а»). Экран ответа: пять типов вопросов, «назад»/«пропустить»/
  свободный ввод, позиция живёт в БД и переживает рестарт. Отложенное приглашение отменяется,
  когда человек начал или закончил прохождение (V-096).
- **v0.11.4** — экспорт результатов: «CSV» и «Markdown» — подписанная ссылка на 15 минут через
  `tg.openLink` (обращение №44, раньше `no_webapp_token` вместо файла). Черновик и копирование
  опросов (E8-D5): копия всегда черновик, число ответивших у источника не меняется.
  Миграция `067` — черновик анкеты оргсостава, 46 вопросов.
- **v0.12.0** — анкета раскладывается четырьмя черновиками 12/12/11/11, по блоку на роль,
  общие вопросы один раз (V-098). Миграция `069`.

## Приглашения, роли, права

- **v0.11.5** — инструкция получателю в сообщении о выпуске кода (E9): готовая инструкция
  на 18 строк, `INVITE_INSTRUCTION`, сборка через «+» без `.format`. Документ 174 и
  AC-1…AC-16. Выкат стал накатывать миграции сам: шаг `db --migrate` в `deploy.yml` идёт до
  сверки схемы (runbook 35).
- **v0.11.6** — пункт меню «Приглашения» действительно выпускает код: сравнение подписи
  переведено на `texts.TITLE_INVITES`, оба входа идут в `admin.send_invite`.
- **v0.11.7** — роль «Педагог» выпускается из Mini App: третий сегмент, тело
  `POST /webapp/admin/invite` принимает `master` и требует `discipline_code` (E10).
  Организатор больше не обрабатывает заявки: миграция `068` снимает у `org`
  `registration.approve`. Группа меню «Админ» переименована в «Управление».
- **v0.11.8** — выпуск кода педагогу падал с 422: тело объявляло `Literal["org","troupe"]`.
  Новый тест сравнивает набор ролей Mini App и бота (`WebAppInviteIn` против `InviteIn`).
- **v0.11.9** — выпуск кода из Mini App присылает админу инструкцию в чат отдельным
  уведомлением `invite_instruction`; код остаётся на экране, дубля нет, тихие часы действуют.

## Онбординг (E13, v0.12.0)

- Код приглашения стал персональным: `invite_code.participant_id`, админ выбирает человека на
  экране «Приглашения», кнопка «Новый участник» создаёт запись без Telegram. Миграция `070`.
- Заявки убраны целиком: нет сценария бота, экрана «Заявки», права `registration.approve`,
  уведомления админу и счётчика; `/webapp/admin/t/pending` отдаёт 404 на проде (проверено).
- Знакомство — три вопроса (имя, короткое имя, телефон), остальные шесть — по кнопке
  «Знакомство» в группе «Профиль»; памятка бота — по `/help`.
- Подписи: «Труппа» → «Актёр», в сегментах разделители и общий кегль 14 px / поля 6 px,
  ряд не подрезается на 320 px; при роли «Педагог» — строка про дисциплину при регистрации.
- Тексты инструкции и памятки учитывают уже известные поля (E13-5, docs/182).

  15 представлений), 173 (рабочее место прототипов), 179, 181–183 (E12/E13).
  Инвентарь действий 117 пересобран: 262 маршрута, 55 без права, 30 без интерфейса.
- Убраны мёртвые адреса экрана «Заявки» из `scripts/ux_audit.py` и образца в `home.py`
  (коммит `11c8827`); проверка графа экранов даёт 0 битых ссылок.
