## 2. Целевая схема прода

```
                    Telegram
                       │  long polling (исходящие)
                       ▼
        ┌──────────────────────────────┐
        │  VPS 2 vCPU / 4 ГБ / 60 ГБ   │
        │                              │
        │  Caddy (443, TLS авто)       │
        │   ├─ /webhook/* → n8n:5678   │
        │   ├─ /api/*     → tool-api   │
        │   └─ /app/*     → Mini App   │
        │                              │
        │  tg-gateway (systemd)        │
        │  tool-api (systemd, 127.0.0.1:8000) │
        │  n8n (docker, 127.0.0.1:5678)│
        │  Postgres 16 (docker, 5432, только localhost) │
        └──────────────────────────────┘
                       │
              Google Drive / Sheets / Calendar
```

Почему так:

- **polling вместо webhook** для Telegram: не нужен публичный порт под бота, проще и надёжнее.
  Webhook понадобится только для Mini App (там нужен HTTPS-домен).
- **сервисы на 127.0.0.1**, наружу смотрит только Caddy — меньше поверхности атаки.
- **Postgres в Docker на том же сервере** — до первого реального роста нагрузки этого хватает;
  управляемая БД (managed Postgres) стоит денег и нужна, когда данных станет больше 5–10 ГБ.

## 3. Что арендовать

| Вариант | Конфигурация | Ориентир по цене | Когда выбирать |
|---|---|---|---|
| Timeweb Cloud / Selectel | 2 vCPU, 4 ГБ, 60 ГБ SSD | 700–1 500 ₽/мес | российские данные, оплата в рублях, поддержка на русском |
| Yandex Cloud | 2 vCPU, 4 ГБ + диск | 1 500–2 500 ₽/мес | нужна управляемая БД и Object Storage сразу |
| Hetzner (Германия) | CX22: 2 vCPU, 4 ГБ, 40 ГБ | 4–5 €/мес | дешевле всего, но оплата картой не РФ и данные за границей |

**Моя рекомендация:** Timeweb Cloud или Selectel, 2 vCPU / 4 ГБ / 60 ГБ SSD.
Причина: личные данные студийцев (имена, телефоны в записной книжке) — лучше держать в РФ;
плюс рублёвая оплата и русскоязычная поддержка, что важно не-DevOps-владельцу.

Отдельно понадобится:

- **домен** (`.ru` или `.theatre`) — 200–900 ₽/год, нужен для Mini App и вебхука n8n;
- **TLS** — бесплатно через Caddy/Let's Encrypt;
- **резервные копии** — Google Drive (уже есть) + локальный диск на 20 ГБ.

Итого ориентир: **1 000–2 000 ₽/мес** за сервер и домен.

## 4. Что настроить при переезде (пошагово)

### 4.1 Сервер

```bash
# пользователь без root, ключи вместо пароля
adduser svoi && usermod -aG sudo,docker svoi
# ufw: только 22, 80, 443
ufw allow 22/tcp && ufw allow 80,443/tcp && ufw enable
# fail2ban на ssh
apt install -y fail2ban
```

### 4.2 Код и окружение

```bash
git clone git@github.com:<аккаунт>/teatrsvoi-bot.git /opt/svoi
cd /opt/svoi && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && chmod 600 .env      # заполнить на сервере, не копировать из чата
scp secrets/google-sa.json svoi@server:/opt/svoi/secrets/ && chmod 600 ...
```

### 4.3 База

```bash
# локально
pg_dump -h 127.0.0.1 -p 5433 -U svoi -Fc svoi > svoi.dump
# на сервере
createdb svoi && pg_restore -d svoi svoi.dump
# миграции применяются по порядку из db/init — на чистой базе они сами создадут схему
```

### 4.4 Сервисы

`systemd`-юниты `svoi-tool-api.service` и `svoi-gateway.service` с `Restart=always`,
`EnvironmentFile=/opt/svoi/.env`, `WorkingDirectory=/opt/svoi`.

`Caddyfile`:

```
svoi.example.ru {
    handle /webhook/* { reverse_proxy 127.0.0.1:5678 }
    handle /api/*     { reverse_proxy 127.0.0.1:8000 }
}
```

### 4.5 n8n в прод

Сейчас n8n хранит данные в SQLite. На проде:

- перевести n8n на **Postgres** (`DB_TYPE=postgresdb`, отдельная база `n8n`), иначе при перезапусках
  есть риск потерять воркфлоу;
- задать `N8N_HOST`, `WEBHOOK_URL=https://svoi.example.ru/`, `N8N_PROTOCOL=https`;
- включить basic-auth или ограничить доступ к редактору по IP;
- воркфлоу держать **в git** (`n8n/workflows/*.json`) и импортировать скриптом — не править
  только в UI, иначе git и реальность разойдутся.

### 4.6 Проверка после переезда

```
1. /health → ok, tz_offset 4.0, db postgres
2. кнопка «Бюджет» → цифры совпадают с локальными
3. «сколько у нас денег?» → тот же ответ
4. запись расхода → строка в Google Sheets появилась
5. календарь: /tools/calendar/health → оба календаря доступны
6. n8n: curl -X POST https://.../webhook/router → {"ok":true}
```

## 5. Что должно быть настроено в проде (чек-лист)

**Безопасность**

- [ ] пароль по SSH выключен, только ключи; root-логин запрещён
- [ ] `.env` и `secrets/` — 600, не в git, отдельные от локальных
- [ ] Postgres не смотрит наружу (`127.0.0.1:5432`)
- [ ] n8n-редактор закрыт паролем или по IP
- [ ] `TOOL_API_TOKEN` перевыпущен (локальный токен в прод не тащим)
- [ ] бэкап-скрипт проверен восстановлением, а не только созданием

**Надёжность**

- [ ] `Restart=always` у сервисов, автозапуск после ребута
- [ ] ежедневный `pg_dump` в 03:00 + ротация 14 дней + копия в Google Drive
- [ ] логи в journald с ротацией, `logrotate` настроен
- [ ] внешний аптайм-монитор (Uptime Kuma или healthchecks.io) на `/health`

**Эксплуатация**

- [ ] Telegram-алерт админу при падении сервиса (cron-проверка раз в 5 минут)
- [ ] инструкция «что делать, если бот молчит» на одной странице
- [ ] известен и записан порядок отката: `git checkout <тег> && systemctl restart`

## 6. Мониторинг: что и чем мерить

| Слой | Что смотрим | Инструмент | Порог тревоги |
|---|---|---|---|
| Доступность | `/health` отвечает | Uptime Kuma, раз в 60 с | 2 провала подряд |
| Ошибки | 5xx в tool-api, исключения gateway | journald + grep в cron | > 5 за 10 минут |
| Данные | инварианты `check_invariants.py` | cron раз в сутки | любой FAIL |
| Сверка | файл против БД | `reconcile.py --report` раз в сутки | расхождение итогов |
| LLM | доля ответов модели, ошибки OpenRouter | `v_intent_gaps` + лог n8n | ошибок > 10 % |
| Диск | свободное место | node_exporter или `df` в cron | < 15 % |
| Бэкапы | файл бэкапа свежее 26 часов | скрипт-проверка | нет файла |

Начинать стоит с трёх: **uptime `/health`**, **инварианты раз в сутки**, **проверка свежести бэкапа**.
Этого достаточно, чтобы не узнать о проблеме от студийцев.

## 7. Порядок переезда (чтобы не сломать живое)

1. Поднять сервер и БД, залить дамп, применить миграции.
2. Запустить `tool-api` на сервере, **не включая gateway** — проверить `/health` и чтение данных.
3. Остановить локальный gateway, запустить серверный (один токен — один потребитель!).
4. Проверить весь чек-лист §4.6 на живом боте.
5. Переключить n8n-вебхук на новый адрес (`N8N_BASE_URL`).
6. Только после этого включать cron-задачи и мониторинг.
7. Локальный контур оставить как песочницу: там `ENV=dev`, отдельная база, отдельный бот.

**Чего делать нельзя:** запускать два gateway одновременно (Telegram отдаст `409 Conflict`),
тащить в прод локальный `TOOL_API_TOKEN`, копировать `.env` через мессенджер.
