## 1. Прямой ответ: чат-бот в VK есть, и это не Mini App

Да, аналог Telegram-бота в VK существует и устроен проще, чем Mini App. Бот — это
**сообщество**, **сервер** и **ключ доступа сообщества**; ни приложения, ни домена, ни
модерации для работы в сообществе документация не требует.

Цитата по смыслу (`/ru/api/bots/getting-started`, шаг «Подготовьте сообщество»): для
подключения чат-бота можно использовать любое сообщество ВКонтакте; работа бота
включается в `Управление → Сообщения → Настройки для бота → Возможности ботов`, а приём
сообщений — там же галочкой «Сообщения сообщества».

Что это даёт по фактам:

| Возможность | Как в документации | Ограничение |
|---|---|---|
| Приём событий | Callback API (вебхук на наш сервер, ответ `ok` на каждое событие) или Bots Long Poll (мы сами опрашиваем сервер VK) — `/ru/api/bots/getting-started`, шаг 5 | для чатов версия API не ниже 5.80 |
| Отправка от имени сообщества | `messages.send` с ключом сообщества — `/ru/api/community-messages/getting-started` | не более 100 получателей в одном вызове, `random_id` от повторов |
| Клавиатура под полем ввода | `keyboard`, `inline: false` — `/ru/api/bots/development/keyboard` | до 40 кнопок, до 10 рядов по 5 |
| Inline-клавиатура | `inline: true` | до 10 кнопок, до 6 рядов по 5 |
| Кнопки-действия | `text`, `location`, `vkpay`, `open_link`, `open_app`, `callback` — `/ru/api/bots/development/keyboard/key-types` | `label` до 40 символов, `payload` до 255 символов и всегда проверять на сервере: пользователь может его подменить |
| Ответ на нажатие без сообщения | callback-кнопка → событие `message_event` → `messages.sendMessageEventAnswer` с `show_snackbar`, `open_link` или `open_app` — `/ru/api/bots/development/keyboard/callback-keys` | на кнопке виден индикатор ожидания; ответ нужен обязательно |
| Меню-навигация без «болтовни» | там же: нажатие кнопки меняет клавиатуру и редактирует сообщение | — |
| Карусель (карточки) | шаблон `template` в `messages.send`, 1–10 элементов, до 3 кнопок в элементе — `/ru/api/bots/development/messages/user-content` | у старых клиентов недоступна, нужен запасной текст |
| «Горячие» клавиатуры | такого класса в документации VK **нет**: есть ровно два вида — под полем ввода и inline. Постоянная клавиатура получается через `one_time: false` | — |
| Разные клиенты | `client_info` в событии `message_new`: `keyboard`, `inline_keyboard`, `carousel`, `button_actions` — `/ru/api/bots/getting-started` | старые и сторонние клиенты умеют не всё; если клавиатуры нет — дублировать варианты текстом |

Предел, который важнее всех остальных: **бот не может написать первым**. По
`/ru/api/community-messages/getting-started`: чтобы отправлять пользователю сообщения от
имени сообщества, пользователь должен разрешить их получение; если он написал сообществу
первым, это приравнивается к согласию. Там же прямо сказано: через API нельзя получить
список всех, кто разрешил сообщения, — его нужно хранить и синхронизировать у себя
(события `message_allow` и `message_deny`).

Лимиты (`/ru/api/bots/development/messages`, `/ru/api/api-requests`): 20 запросов в
секунду с ключом сообщества; количественные лимиты на однотипные методы не публикуются —
при превышении метод временно недоступен или требует капчу, ошибка `6 Too many requests
per second`.

Правила (`/ru/bots-rules`): нельзя делать работу бота зависимой от подписки, лайка и
репоста; обещанное действие — в течение суток; рекламные рассылки — не чаще раза в семь
дней, с интентами `promo_newsletter`, `bot_ad_invite`, `bot_ad_promo` и кнопкой отписки;
реклама в многопользовательские беседы запрещена; за нарушения сообществу отключают
сообщения. Модерации перед запуском бота в сообществе нет — правила действуют, проверки
заранее нет.

## 2. Чего стоит Mini App: регистрация, домен, политика, модерация

| Требование | Формулировка и источник |
|---|---|
| Регистрация приложения | «Размещение» — заполнение формы `dev.vk.ru/ru/admin/create-app`, следствие — `APP_ID` (`/ru/mini-apps-rules`, определения) |
| Свой хостинг разрешён | «Вы также можете выбрать любой хостинг, который поддерживает протокол HTTPS»; хостинг VK — только статика, без серверного кода (`/ru/mini-apps/development/hosting/overview`) |
| HTTPS во всех браузерах | Приложение должно корректно работать по HTTPS в Chrome, Firefox, Opera, Яндекс Браузере без плагинов (`/ru/mini-apps-rules`, п. 2.3.10) |
| Проверка подписи обязательна | Приложение обязано авторизовывать пользователей по параметрам запуска и валидировать подпись (`/ru/mini-apps-rules`, п. 1.2.2) |
| Пользовательское соглашение и политика конфиденциальности | Указать в панели управления и пускать только принявших (`/ru/mini-apps-rules`, п. 1.1.4) |
| Разработчик — оператор персональных данных | Правомерная обработка, согласие, конфиденциальность, прекращение обработки, ответ администрации в 7 календарных дней (`/ru/mini-apps-rules`, п. 1.1.5–1.1.7) |
| Лимиты на запросы пользователя | Приложение должно ограничивать частоту и объём запросов на сервер (п. 1.2.6) |
| Ссылки наружу | Только через `https://vk.ru/away.php?to=…` (п. 2.5.4) |
| Поддержка | Ответ пользователю не позднее 7 календарных дней; модератору — 3 дня (п. 2.4.1, 4.1.7) |
| Состояние для пользователей | «Отключено» — сразу после создания приложение доступно только администраторам по прямой ссылке `https://vk.com/app{id}`; «Включено» — «Мини-приложение ВКонтакте станет доступно по ссылке всем пользователям» (`/ru/mini-apps/settings/general/placement`, прочитано 04.11.2026) |

Модерация и сроки (`/ru/mini-apps/catalog/moderation`):

* вся процедура от заявки до публикации в каталоге — **минимум 3 дня**;
* модератор может отправить на бета-тестирование: старт каждый понедельник и четверг в
  18:00 по Москве, **минимум 3 дня**;
* во время модерации новые функции добавлять не рекомендуют;
* массовые уведомления требуют прохождения модерации, проверку просят присылать за 7
  рабочих дней до запуска;
* снятие из каталога: не отвечает пользователям больше 7 дней, модератору — больше 3 дней,
  висит или падает и не чинится 30 дней; вернуться можно только через новую модерацию.

Причины отказа (`/ru/mini-apps-rules`, п. 4.1.6): нет уникальных и качественных механик
или приложение копирует/дублирует функциональность сайта; «заглушка» из ссылок и кнопок;
коммерческое объявление; слишком сложное и неудобное; иное несоответствие правилам.
Администрация вправе отказать без объяснения причин (п. 4.1.1).

Важно: модерация нужна для каталога, push, платежей и площадки ОК. Запуск по прямой
ссылке — отдельное состояние: по `/ru/mini-apps/settings/general/placement` в состоянии
«Включено» приложение «станет доступно по ссылке всем пользователям» ВКонтакте без
модерации. То есть «нет модерации» и «нет канала» — разные вещи: Mini App по ссылке
открыть можно, а писать участнику первым он не умеет.

Отдельно: п. 4.1.8 запрещает переводить аудиторию опубликованного приложения на версии
вне платформы — то есть «опубликуем в VK, а работать будут у нас на сайте» правилами не
предусмотрено.

## 3. Платежи и взносы: нам они не нужны, и это упрощает

`/ru/mini-apps/monetization/payments`: пока мини-приложение не прошло проверку, все
платежи идут в тестовом режиме; чтобы принимать настоящие, нужно зарегистрироваться в
кабинете выплат и пройти модерацию. Виртуальные ценности продаются только за голоса и
ОКи; физические и цифровые товары за деньги — через одобренные способы; вывод — на счёт
или кошелёк в зависимости от статуса (самозанятый, ИП, юрлицо).

Для нас это неактуально: бот ведёт **учёт** взносов, а не принимает деньги, эквайринга
нет и не планируется. Значит платежный блок Mini App не нужен, а кнопка `vkpay` в чате
(тип кнопки из `/ru/api/bots/development/keyboard/key-types`) — тоже. Прямое следствие:
приём денег платформа не блокирует и не требует, но и не помогает.

## 4. Авторизация: `sign` против Telegram `initData`

Параметры запуска (`/ru/mini-apps/development/launch-params`): VK передаёт их как
URL-параметры на адрес приложения; для входа нужен `vk_user_id`, рядом идут `vk_app_id`,
`vk_platform`, `vk_language`, `vk_ts` (время генерации подписи), `vk_are_notifications_enabled`,
`vk_viewer_group_role` и другие. Подпись — `sign`.

Алгоритм (`/ru/mini-apps/development/launch-params-sign`), дословно по шагам:

1. взять только параметры с префиксом `vk_`, отсортировать по имени, склеить в строку
   `ключ=значение` через `&`; значения — в URL-кодировке (запятая как `%2C`, пробел `%20`);
2. посчитать HMAC-SHA256 этой строки с **защищённым ключом** приложения
   (`Разработка → Ключи доступа → Защищённый ключ`);
3. закодировать результат в base64, затем привести к base64url: `+` → `-`, `/` → `_`,
   убрать `=` в конце;
4. сравнить с `sign`. Не совпало — параметры подменены.

Документация даёт готовые примеры проверки на PHP, Java, Python, Node.js и ссылку на
`github.com/VKCOM/vk-apps-launch-params`. В питоновском примере две ловушки, видимые в
тексте: `urlencode(..., doseq=True)` по словарю, отсортированному заранее, и обрезка
хвостового `=` после base64 — `hash_code.decode('utf-8')[:-1]`.

**Чем это отличается от нашего Telegram-входа** (`services/tool-api/app/webapp.py`,
`validate_init_data`):

| | VK `sign` | Telegram `initData` |
|---|---|---|
| Что подписывается | все параметры `vk_*`, отсортированные | все поля, кроме `hash`, отсортированные |
| Разделитель в строке | `&` | `\n` |
| Ключ подписи | защищённый ключ приложения, напрямую | сначала `HMAC-SHA256(key="WebAppData", msg=bot_token)`, потом этим ключом — данные |
| Формат результата | base64url без `=` | hex-строка |
| Срок жизни | в подписи нет; есть только `vk_ts` — время генерации. Проверку «не старше N» платформа не описана, её надо делать самим | `auth_date`, у нас `MAX_AUTH_AGE = 3600`: старше часа не принимаем |
| Идентификатор | `vk_user_id` | `user.id` из JSON-поля `user` |

Практический вывод: наш `validate_launch_params` — это второй вход в тот же
`webapp.py`, отдельная функция на 20–30 строк, без новой зависимости. Проверку свежести
(`vk_ts`) придётся добавить самим: аналога `auth_date` и `MAX_AUTH_AGE` у VK нет.

Но чтобы получить `sign`, пользователь должен запустить именно **приложение** VK. Ссылка
из чата на наш домен в браузере параметров запуска не несёт — значит вне Mini App
идентичность придётся выдавать самим (одноразовый вход по ссылке из бота), а это
отдельная работа, не входящая в «второй фронт».

## 5. Уведомления: у Mini App три канала, у чата один и бесплатный

| Канал | Что нужно | Лимиты по частоте | Источник |
|---|---|---|---|
| Сообщения сообщества (чат) | пользователь разрешил получение или написал первым | лимитов частоты в документации нет; правила ботов ограничивают рекламные рассылки — раз в 7 дней, с интентами и отпиской | `/ru/api/community-messages/getting-started`, `/ru/bots-rules` |
| Разовые уведомления Mini App (push и «колокольчик») | пройденная модерация (каталог не обязателен), разрешение `VKWebAppAllowNotifications`, у пользователя включены уведомления от игр и приложений | 1 в час и не более 3 в день одному пользователю; два подряд с одинаковым текстом нельзя | `/ru/mini-apps/promotion/social-mechanics/notifications/single` |
| Массовая рассылка Mini App | публикация в каталоге, заявка на проверку (просить за 7 рабочих дней) | не чаще 1 раза в 3 месяца, до 3 уведомлений одновременно, продолжительность до 14 дней | `/ru/mini-apps/promotion/social-mechanics/notifications/mass` |
| Уведомления неактивным | публикация в каталоге | — | `/ru/mini-apps/development/notifications` |

Дополнительно: отправка разовых уведомлений идёт с сервисным ключом через
`notifications.sendMessage` **только с сервера**; проверять разрешение — методом
`apps.isNotificationsAllowed` (`/ru/mini-apps/promotion/social-mechanics/notifications/single`).
Правила требуют, чтобы пользователь мог отключить уведомления в самом приложении и чтобы
текст был не длиннее 250 символов (`/ru/mini-apps-rules`, п. 2.7.3, 2.7.5).

Для наших напоминаний (взнос, «заполни занятость», «завтра репетиция») это значит: в
чате VK канал тот же, что в Telegram — сообщение от сообщества, при условии что человек
однажды нажал «Начать»/написал; push Mini App — 3 в день максимум и только после
модерации.

## 6. Хранение: на платформу свою базу не переложить

| Что | Ограничение | Источник |
|---|---|---|
| VK Storage (ключ-значение на пользователя) | до 1 000 переменных и до 1 000 вызовов в час на пользователя; значение — первые 4 096 символов; хранится бессрочно; ошибки `103` (лимит ключей) и `9` (flood control) | `/ru/bridge/VKWebAppStorageSet` |
| Хостинг VK | только статика, до 24 загрузок в сутки, до 10 production и 100 staging версий; аудио и видео размещать нельзя; URL меняется после каждой загрузки | `/ru/mini-apps/development/hosting/overview` |
| Файлы приложения | свой хостинг с HTTPS — без ограничений платформы | там же |
| Персональные данные | разработчик — оператор ПД: политика, согласие до входа, прекращение обработки, ответ администрации в 7 дней | `/ru/mini-apps-rules`, п. 1.1.3–1.1.7 |

Практически: VK Storage годится только для мелочей между сессиями (последний экран), а
наши данные — участники, взносы, занятость — живут в нашей Postgres, как и сейчас.
Персональные данные участников платформа не хранит и не защищает за нас: публикация
приложения в каталоге добавляет обязательства (политика, согласие), которых у чат-бота
сообщества нет.

## 7. Сравнение трёх вариантов

Числа по нашему коду (замер на ветке `wt/t_eef4f64d` от `origin/main` `c48cc03`, 04.11.2026):
страницы Mini App — `services/tool-api/app/pages/*.py`, 36 файлов, 6 338 строк; транспорт

## 8. Рекомендация: чат-бот в сообществе, экраны — по кнопке-ссылке

**Выбранный вариант — (б), чат-бот в сообществе VK, без регистрации Mini App.**

Почему так, по фактам выше:

1. Аналог бота есть и покрывает то, ради чего мы вообще делали бота в Telegram:
   сообщения, клавиатуры, callback-кнопки, меню без «болтовни», карусели. Бизнес-логику
   переписывать не нужно — `tool-api` уже HTTP-сервис; транспорт при этом переписывается
   целиком, см. цену в §7.
2. Модерация не мешает запуску, но не даёт главного. По
   `/ru/mini-apps/settings/general/placement` состояние «Включено» делает Mini App
   доступным по ссылке всем пользователям ВКонтакте без модерации; модерация нужна для
   каталога, push, платежей и площадки ОК. То есть запустить Mini App по ссылке можно,
   но **написать участнику первым он всё равно не может**, а push ограничен 1 в час и
   3 в день. Напоминания — то, ради чего нужен канал вне Telegram, — остаются за
   сообщениями сообщества.
3. Не нужны домен под приложение и политика конфиденциальности как обязательное условие
   входа: у чат-бота сообщества этих требований нет. Домен у нас есть, но он не
   становится условием работы фронта.
4. Напоминания работают тем же способом, что в Telegram, и без лимита «3 в день»:
   ограничение платформы на частоту есть только у push-уведомлений Mini App.

**Честная цена варианта (б):** 5 169 строк в 30 файлах, из них 3 099 — роутеры на
`aiogram`, то есть 3–5 недель агента, а не 1–2. Это не отменяет выбора: без (б) нет
канала, который сам пишет участнику, а (а) этого не умеет ни с модерацией, ни без неё.

Минимальный объём, который надо сделать, чтобы вариант заработал:

* сообщество VK и ключ доступа сообщества — действие владельца, не агента;
* приём обновлений: **Bots Long Poll** (исходящие запросы к VK, публичный вебхук и
  сертификат не нужны) — предпочтительнее Callback API на первом шаге;
* команды: `/start` (меню), расход, доход, занятость, мои взносы, бюджет, расписание,
  помощь — те же имена, что в Telegram, чтобы тексты и правила остались одни;
* клавиатура меню (до 40 кнопок хватает с запасом, `one_time: false`) и callback-кнопки
  для подтверждений вместо `answerCallbackQuery`;
* таблица `vk_subscriber(vk_user_id, allowed_at, denied_at)` — потому что список
  разрешивших через API не получить, а без него нет напоминаний;
* экраны — кнопкой `open_link` на наш домен с **одноразовым входом по ссылке из бота**
  (свой токен, срок жизни 15 минут, привязка к `vk_user_id`), а не через `open_app`:
  `open_app` требует `app_id`, то есть регистрации приложения; для нашей задачи
  регистрация и модерация не нужны, поэтому `open_link` дешевле.

Если позже понадобятся именно push-уведомления VK или размещение в каталоге — это
отдельное решение и отдельная карта: сначала модерация, потом каталог. По документации
это не блокирует работу чата, а лишь добавляет к нему.

Что этим решением **не** решается: VK-чат не заменяет экраны для таблиц и сводов (бюджет,
сводное расписание) — там нужен экран, и он уже есть. Гибрид «чат как вход, экраны как
рабочее место» — не компромисс, а прямое следствие ограничения «бот не пишет первым»,
которое заставляет держать разговор коротким и кнопочным.
