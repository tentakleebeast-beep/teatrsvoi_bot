# 18. Telegram Mini Apps: меню, админ-панель, формы


Решение: сложные формы и таблицы отдаём в **Mini App**, простые действия остаются кнопками
в чате. Бот остаётся единственным входом, `tool-api` — единственным источником данных.

---

## 1. Что уходит в Mini App, а что остаётся в чате

| Сценарий | Где | Почему |
|---|---|---|
| Меню, «что дальше» | чат (кнопки) + Mini App | кнопки быстрее; Mini App — для наглядности |
| Расход/доход | **Mini App** | нужны дата-пикер, выпадающий список категорий, поле «основание», чек-лист |
| Занятость | **Mini App** | сетка «дни × часы» нативно не собрать кнопками |
| Админка (участники, права, заявки) | **Mini App** | таблицы, фильтры, массовые действия |
| Отчёты | Mini App + ссылки на Google | превью и переход в таблицу |
| Вопрос ассистенту | чат | диалог в чате естественнее |
| Подтверждение записи | чат (кнопка) | одно нажатие, привычно |

Обратная совместимость: **всё, что есть в Mini App, доступно кнопками и текстом** —
Mini App ускоряет, но не становится единственным путём (иначе часть людей отвалится).

---

## 2. Техническая схема

```
Telegram
  │  кнопка «Открыть» (InlineKeyboardButton с web_app)
  ▼
Mini App (SPA, HTTPS)                ← Telegram WebApp SDK, initData в заголовке
  │  POST /auth/telegram  {initData}
  ▼
tool-api
  │  1) проверка подписи initData (HMAC-SHA256 с токеном бота)
  │  2) auth_date не старше 5 минут
  │  3) chat_id берётся ТОЛЬКО из initData, не из тела запроса
  │  4) выдаёт короткоживущий session-токен + список capabilities
  ▼
дальнейшие вызовы /api/* с session-токеном → те же правила RBAC, что и в боте
```

Ключевое: Mini App — это ещё один транспорт. Права, инварианты, аудит и запись живут в
`tool-api`; фронт не считает деньги и не решает, что можно.

### Проверка initData (обязательно на сервере)

```python
secret = hmac.new(b"WebAppData", BOT_TOKEN.encode(), hashlib.sha256).digest()
check  = hmac.new(secret, data_check_string.encode(), hashlib.sha256).hexdigest()
assert check == received_hash
```

Дополнительно: `auth_date` в пределах 300 секунд, `user.id` обязан присутствовать,
повторное использование старого `initData` отклоняется.

## 3. Экраны (MVP)

1. **Главная.** Кто я, мои роли, быстрые действия: расход, доход, занятость, взносы.
2. **Форма расхода.** Сумма (числитель), категория (поиск + список), дата (по умолчанию сегодня),
   основание (свободный текст + подсказки из прошлых), проект, чек-лист «что приложить»
   (чек, фото, договор), кнопка «Записать» → `POST /api/budget/commit`.
3. **Занятость.** Сетка: строки — 7 дней, колонки — 08…23; тап по ячейке переключает
   свободно/занято; массовое «весь день»; сохранение → `POST /api/availability/bulk`.
4. **Админка.** Вкладки: участники (роли, блокировка), заявки (подтвердить/отклонить),
   права (матрица ролей и личных исключений), квоты (лимиты AI), журнал (последние события).
5. **Отчёты.** Месяцы бюджета и занятости: мини-таблица + ссылка на Google-лист.
6. **Помощник.** Поле ввода → router → ответ; история в памяти на сессию.

---

## 4. Где хостить

| Контур | Как | Комментарий |
|---|---|---|
| Локальная разработка | `cloudflared tunnel --url http://localhost:8080` | Telegram требует HTTPS; временный домен подходит для теста |
| Прод | VPS + nginx + Let's Encrypt, тот же домен, что у `tool-api` | `https://bot.example.ru/app` |
| Кнопка в боте | `setChatMenuButton` (menu button) + inline `web_app` | после деплоя задаётся один раз |

Переменные окружения:

```env
MINIAPP_URL=https://bot.example.ru/app
MINIAPP_SESSION_SECRET=<32+ символов>
BOT_USERNAME=teartsvoi_bot
```

---

## 5. Безопасность

1. Подпись `initData` проверяется **на сервере**; фронту не доверяем ни в чём.
2. `chat_id` и `user_id` — только из подписанных данных.
3. Session-токен живёт 15 минут, привязан к `chat_id`, лежит в памяти вкладки.
4. Никаких секретов в JS: ни токена бота, ни ключей Google.
5. CORS: только `MINIAPP_URL`; CSP без `unsafe-eval`.
6. Все действия → `audit_event` с `source='mini_app'`.
7. Квоты AI проверяются те же, что и в чате.

---

## 6. Совместимость и деградация

- Нет поддержки WebApp (старый клиент) → бот показывает текущие кнопки и формы.
- Mini App не открылся (нет сети/домена) → то же самое, сообщение «откройте кнопкой в чате».
- Сессия истекла → экран «Обновите, откройте заново», без потери введённого (локальный черновик).

## 7. План реализации

| Этап | Объём | Результат |
|---|---|---|
| M1 | `/auth/telegram` + сессия + экран «Главная» | открывается из бота, видно имя и роли |
| M2 | Форма расхода + запись в бюджет | замена текущей формы суммы/категории |
| M3 | Сетка занятости + `availability/bulk` | люди закрывают неделю за минуту |
| M4 | Админка: участники, права, заявки | отказ от команд `/grant`, `/role` |
| M5 | Отчёты и помощник | ссылки на листы, чат с моделью |

Каждый этап заканчивается тестами из `docs/development/16` (§3.1 — изоляция, §4.7 — router/LLM).
