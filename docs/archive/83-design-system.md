# 83. Дизайн-язык Mini App

> **Заменено 31.10.2026 дизайн-системой v2 — `docs/development/91-design-system.md`.**
> Документ оставлен как история: в версии 1 файл стилей существовал, но экраны его
> не использовали (разбор — `docs/development/90-ui-review.md`, П-1).

Основание: заказчик 31.10.2026 — «UX и UI не интуитивные и не человеческие»;
решение по порядку работ: **сначала дизайн-язык и компоненты, потом переверстка
всех экранов на нём**.

## 1. Зачем отдельный слой

Двенадцать экранов писались по отдельности: каждый со своими отступами, размерами
шрифта и цветами. Из-за этого одинаковые вещи выглядели по-разному, а любая правка
требовала обойти все файлы.

Дизайн-язык — один файл `services/tool-api/app/static/webapp-ui.css`, отдаётся как
`/webapp/ui.css` и подключается через `shell.js` на всех страницах. Он состоит только
из классов `.ui-*`, ни один старый селектор не тронут: страницы переводятся по одной,
вид остальных не меняется.

Справочник элементов — `/webapp/ui`: живая страница со всеми компонентами. По ней
сверяются и люди, и тесты.

## 2. Токены

| Токен | Значение | Зачем |
|---|---|---|
| `--ui-bg`, `--ui-surface` | из темы Telegram, `#ffffff` / `#f4f4f5` | светлая и тёмная схема работают без отдельного кода |
| `--ui-fg`, `--ui-muted` | `--tg-theme-text-color` / `--tg-theme-hint-color` | текст и подсказки |
| `--ui-accent`, `--ui-on-accent` | `--tg-theme-button-color` | главное действие совпадает с кнопками Telegram |
| `--ui-ok`, `--ui-warn`, `--ui-danger` | `#1f8f4e`, `#b26a00`, `#c0392b` | состояние передаётся словом и цветом |
| `--ui-s1…s6` | 4, 8, 12, 16, 24, 32 | весь ритм кратен 4 — вёрстка не «дышит» случайно |
| `--ui-radius` / `--ui-radius-sm` | 14 / 10 | карточки и элементы управления |
| `--ui-tap` | 44 | минимальная площадь нажатия (палец в дороге) |

## 3. Компоненты

| Класс | Что это | Правило |
|---|---|---|
| `.ui-screen` | каркас экрана | сверху вниз: шапка → содержание → действие |
| `.ui-top` | шапка: «‹ назад» и название | закреплена сверху, всегда на месте |
| `.ui-card` | поверхность с заголовком | одна мысль на карточку |
| `.ui-list` / `.ui-list__row` | список | строка = одно действие, вся строка нажимается |
| `.ui-tile` | плитка хаба | название + подсказка, минимум 92 px высоты |
| `.ui-btn` (`--primary`, `--ghost`, `--danger`, `--block`) | действие | на экране одно главное действие |
| `.ui-field`, `.ui-input`, `.ui-select`, `.ui-textarea` | ввод | подпись сверху, ошибка — под полем словами |
| `.ui-chip` | выбор из 2–3 состояний | выбранное состояние видно и цветом, и заливкой |
| `.ui-badge` | счётчик | только число, расшифровка рядом текстом |
| `.ui-empty` | пустое состояние | заголовок + что сделать дальше |
| `.ui-alert` (`--ok`) | ошибка или успех | причина и следующее действие, без кодов |
| `.ui-skeleton` | загрузка | вместо пустого экрана и «Считаю…» |
| `.ui-table` | таблица | только в админке, где без строк не обойтись |
| `.ui-tabs` | вкладки | лента с горизонтальной прокруткой, активная центрируется |
| `.ui-amount` | сумма | главное число экрана, разряды не прыгают |

## 4. Правила, которые решают «нечеловечность»

1. **Один экран — одна задача.** Если на экране два равноправных действия, это два экрана.
2. **Действие — глаголом.** «Записать», «Отменить», «Вернуть». Не «ОК», не «Далее».
3. **Состояние — словом.** «Занят», «Оплачено», «Осталось 3 000 ₽». Цвет только помогает.
4. **Опасное — двойным нажатием** и с названием объекта: «Точно отправить 14 людям?».
5. **Ошибка говорит, что делать — и одинаково на всех экранах.** Оборванный запрос везде
   называется словами «Сайт недоступен, попробуйте ещё раз.»: так же говорит баннер
   оболочки (он появляется через 10 с ожидания или на ответ 5xx), так же — статус экрана.
   «Проверьте сеть» не говорим: виноват может быть и сервер, а не человек. Уточнение
   добавляется через тире, а не второй причиной: «Сайт недоступен, попробуйте ещё раз —
   запись не ушла».
6. **Пусто — не тупик.** В пустом состоянии написано, как его заполнить.
7. **Никаких модальных окон** (`alert`/`confirm`/`prompt`): их блокируют WebView.
8. **Нажатие ≥ 44 px**, отступ между целями ≥ 8 px.
9. **Текст без кодов** (`category_direction`, `401`) и без эмодзи вместо слов.
10. **Ничего не «прыгает»**: сумма, статус и время — с табличными цифрами.

## 5. Порядок переверстки экранов

| Шаг | Экран | Почему в этом порядке |
|---|---|---|
| 1 | `/webapp/days` — занятость | самый частый ежедневный сценарий студийца |
| 2 | `/webapp/home` — хаб | первое, что видит человек |
| 3 | `/webapp/dues` — взносы | деньги — второй по частоте вопрос |
| 4 | `/webapp/tx` — расход/доход | ввод данных организатором |
| 5 | `/webapp/broadcast` — рассылка | опасное действие, нужен понятный предпросмотр |
| 6 | `/webapp/admin/t/*` — панель | 8 экранов по одному образцу |
| 7 | `/webapp/notifications`, `/webapp/feedback`, `/webapp/slots`, `/webapp/profile` | реже используются |

После каждого экрана: скриншот до/после в `docs/reports/screens/`, проверка в Playwright
(iPhone 14 и 320 px, светлая и тёмная схема), тест на размер целей и горизонтальную прокрутку.

## 6. Проверки

- `/webapp/ui` — эталон компонентов; браузерный тест проверяет, что все цели ≥ 44 px
  и страница не шире экрана;
- подключение через `shell.js` — новые экраны получают стиль без правок HTML;
- `tests/unit/test_webapp_pages_js.py` — JS каждого экрана парсится, модалок нет,
  страница меняет `initData` на токен.
