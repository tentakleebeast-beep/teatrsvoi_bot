# 42. Строгость окон: аренда, показ, репетиция, тренинг

Дата: 27.10.2026. Развивает `docs/architecture/40` (алгоритм) и `docs/architecture/41` (роли и субъект).
Здесь — почему одно и то же окно подходит для тренинга и не подходит для показа.

---

## 1. Идея

Раньше поиск окон был один на все случаи: «все свободны в этот час». В жизни
требования разные, и разница не в цифрах, а в **цене ошибки**:

| Тип события | Что важно | Чем можно пожертвовать |
|---|---|---|
| Аренда зала | свободен зал | занятостью труппы вообще не важно |
| Показ | все занятые в спектакле с начала | нельзя опаздывать, нельзя отсутствовать |
| Репетиция | обязательные с начала | факультативные подходят позже |
| Тренинг | пришло достаточно людей | кто-то просто пропустит |
| Встреча | большинство | опоздания допустимы |

Поэтому введено понятие **политики окна** (`app/window_policy.py`).

---

## 2. Дорога до театра

Всегда добавляем к занятости от 30 до 60 минут на дорогу. В коде — целые часы,
по умолчанию один.

```
занят до 19:00  →  в театре к 20:00
занят до 20:00  →  в театре к 21:00
свободен с утра →  уже на месте, дорога не добавляется
```

Это важная деталь: без неё окно «19:00–21:00» выглядело бы рабочим, хотя человек
физически не успевает.

Пример из практики: четверо заняты до 19:00, двое до 20:00. С дорогой:
первые свободны с 20:00, вторые с 21:00. Значит репетицию можно ставить на 20:00 —
начнут четверо, двое подключатся в 21:00. Это нормальный кейс, а не компромисс.

## 3. Политики

```python
POLICIES = {
  "rental":    ignores_people=True,  travel_hours=0,
  "show":      allow_late=False, allow_absent=False, min_present_share=1.0,
  "rehearsal": allow_late=True,  allow_absent=False, min_present_share=1.0,
  "training":  allow_late=True,  allow_absent=True,  min_present_share=0.6,
  "meeting":   allow_late=True,  allow_absent=True,  min_present_share=0.7,
}
```

| Поле | Смысл |
|---|---|
| `ignores_people` | аренда: людей не смотрим вовсе |
| `allow_late` | можно начинать без части участников, они подойдут позже |
| `allow_absent` | кто-то может не прийти совсем |
| `min_present_share` | какая доля должна быть, чтобы событие имело смысл |
| `travel_hours` | дорога до театра (в политике — значение по умолчанию) |

## 4. Как строится окно

```
1. Для каждого человека: с какого часа он реально может (с учётом дороги).
2. Перебираем час начала.
3. Обязательные должны быть в начале окна.
   Не могут и allow_late=нет  → окно отбрасывается.
   Не могут и allow_absent=да → попадают в «не смогут», проверяем долю.
4. Факультативные: кто не успевает к началу — попадает в «подойдут позже».
5. Длина окна = пока все обязательные на месте.
6. Отбрасываем короче минимума.
```

Сортировка результатов (детерминированная):

1. меньше отсутствующих;
2. меньше опаздывающих;
3. длиннее окно;
4. вечер;
5. более ранняя дата.

Смысл: **сначала полный состав, потом компромиссы.** Репетиция, где один из трёх
подходит к концу, хуже репетиции на час позже, но в полном составе.

## 5. Примеры

**Показ, все занятые обязательны**

```
a: занят до 18:00 → в театре с 19:00
b: занят до 19:00 → в театре с 20:00
→ окно с 20:00; вариант «19:00» отбрасывается, хотя a уже на месте
```

**Репетиция с факультативным**

```
ядро: свободны 19:00–23:00
третий: занят до 20:00 → подойдёт к 21:00
нужен блок 4 часа → окно 19:00–23:00, «подойдёт позже: Новиков»
```

**Тренинг**

```
5 человек, двое заняты весь вечер
→ окно 18:00–22:00, «не смогут: Морозова, Соколов» (3 из 5 = 60 % — проходит)
4 человека, один занят
→ окна нет: 3 из 4 = 75 %, но требование считается по всем участникам списка
```

**Аренда**

```
все заняты → окно всё равно есть: зал сдаётся, занятость труппы не важна
```

## 6. Что в боте

Тип события определяется по фразе (`detect_event_kind`):

| Слова | Политика |
|---|---|
| аренда, сдаём зал | `rental` |
| показ, спектакль, премьера, выступление | `show` |
| тренинг, тренировка, мастер-класс | `training` |
| репетиция, прогон, сбор труппы | `rehearsal` |

Ответ:

```
Окна для «репетиция» (минимум 2 ч, дорога 1 ч):

1. вт 24.11 20:00–23:00 (3 ч), позже подойдут: Новиков Виктор
```

Если тип не назван — берётся репетиция как самый частый случай, но в ответе
тип указан явно, чтобы ошибка была видна.

## 8. Что осталось

| Задача | Почему не сейчас |
|---|---|
| Дорога по человеку (у кого-то 20 минут, у кого-то полтора часа) | поле `travel_minutes` в `participant` есть, но заполняется вручную |
| Разные требования внутри одного события (роль обязательна для показа, но не для читки) | решается через `event_plan.participant_ids` + признак обязательности |
| Пол часа вместо часа | данные занятости приходят по часам, дробить нечего |
| Модель для определения типа события | правила покрывают основные формулировки |

Границы дня у политики те же, что у остального поиска: сетка `app/rules.py`,
часы 08:00…23:00 (`docs/architecture/40` §2). Своих констант политика больше не держит:
до 04.11 они расходились, и одно и то же окно считалось по-разному.

Занятость зала (аренда как событие) считается отдельно — `docs/architecture/46`
и `47`: у зала своя занятость, у людей своя, и встречаются они только в аренде
с персоналом.

## 9. Уточнения по ролям (27.10.2026)

Требования заказчика, которые учтены в модели:

1. **У одной роли может быть несколько названий** — «Няня», «Нянюшка», «Бабушка».
   Реализовано: несколько строк `person_alias` с `alias_kind='role'` для одного человека.
2. **У одного актёра может быть несколько ролей** — в одном спектакле и в разных.
   Реализовано: произвольное число ролей на человека, каждая со своим `project_id`.
3. **Одна роль в разных спектаклях** — «Сэм» в двух постановках.
   Реализовано после миграции `023`: уникальность не глобальная, а в пределах
   (псевдоним + вид + проект). Раньше глобальный `unique(alias)` это запрещал.

Что это меняет при поиске: если в фразе назван спектакль, роли других спектаклей
не рассматриваются. Если спектакль не назван, а роль встречается в двух — бот
переспросит, а не выберет наугад.

## 10. Уточнения 27.10.2026 (вторая итерация)

### 10.1. Дорога нужна всегда

Раньше было: «свободен с утра — уже на месте». Неверно. Человек, свободный с 18:00,
всё равно едет в театр. Теперь дорога применяется к началу любого свободного отрезка.

Исключение одно: если в предыдущий час он **был в театре** (аренда, хоз.работы,
сопровождение) — дороги нет, он уже там.

### 10.2. Время в пути индивидуальное

`participant.travel_minutes` (по умолчанию 60). Перевод в часовую сетку:

| Минут в пути | Сдвиг |
|---|---|
| 0–30 | 0 часов (успевает внутри часа) |
| 31–90 | 1 час |
| больше 90 | 2 часа |

Данные о занятости часовые, точнее дробить нечего — это осознанное упрощение.
Пример: у Виктора 60 минут, у Даины 15. Если оба свободны с 18:00, окно начнётся
в 19:00 — по тому, кто едет дольше.

### 10.3. Аренда бывает двух видов

| Вид | Что важно | Политика |
|---|---|---|
| Самостоятельный арендатор | только зал | `rental` — люди игнорируются |
| С персоналом театра (сопровождение, администратор события) | зал + свои люди | `rental_staff` — люди обязательны |

Правило выбора: если при аренде перечислены участники — считается, что это персонал,
и он должен быть свободен. Если список пуст — смотрим только зал.

### 10.4. Несколько ролей в одном спектакле

Один актёр может играть несколько ролей в одной постановке. Модель это допускает:
несколько строк `person_alias` с одинаковым `project_id`, разными `alias` и
`alias_kind='role'`. Ограничение уникальности — (псевдоним + вид + проект),
поэтому «Сэм» и «Стражник» у одного человека в одном спектакле не конфликтуют.
