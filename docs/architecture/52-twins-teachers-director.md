# 52. Тёзки, педагоги и режиссёр

Дата: 27.10.2026. Уточнения заказчика к назначению события.

---

## 1. Три Вити: неоднозначность решается выбором

В студии несколько Викторов, и все они «Витя». Бот не угадывает — он показывает
варианты и просит выбрать.

```
назначь репетицию с Витей в четверг в 20:00
→ Уточните, кого имели в виду — витей: Новиков Виктор, Крылов Виктор
[Новиков Виктор] [Крылов Виктор] [Отмена]
```

В форме Mini App на этом месте будут **чекбоксы** — по одному на кандидата,
с полным именем и пометкой, почему человек подходит (имя, короткое имя, роль).

### Как определяется неоднозначность

1. Ищем совпадения по псевдонимам: полное имя, короткое, фамилия.
2. Если совпало несколько **разных людей на одном уровне** (два «Вити») — это
   неоднозначность, а не выбор «лучшего».
3. Если совпал один человек и одна роль другого — имя важнее роли (docs/architecture/41).

Выбор запоминается в заявке: `POST /tools/events/choose` пересобирает карточку
с уже сделанным уточнением, заново объяснять боту ничего не нужно.

### Важное следствие для схемы

Раньше псевдоним был уникален глобально: два «Вити» в базе были невозможны.
Это противоречило реальности. Миграция `028`:

| Было | Стало |
|---|---|
| уникальность `(alias, alias_kind, project_id)` | роли уникальны внутри спектакля, имена — нет |
| `unique(participant_id, alias)` | осталось: у одного человека псевдоним не повторяется |

## 2. Педагоги и режиссёр

| Человек | Роль в студии | Правило |
|---|---|---|
| Виктор Крылов | режиссёр и педагог по актёрскому мастерству | тренинг — обязателен, репетиция и показ — по желанию |
| Светлана Попова | педагог по музыке | тренинг — обязательна |

Реализовано в `participant.is_teacher` / `is_director` / `specialty`
(миграция `027`) и в правилах состава при предпросмотре:

```
тренинг   → педагоги добавляются в состав автоматически,
            в карточке помечены как «педагог»;
репетиция → режиссёр не добавляется, но показывается:
            «Может войти: Крылов Виктор (режиссёр)»;
показ     → то же, что репетиция.
```

Проверено на живой базе:

```
тренинг 03.11 19:00–21:00
→ участники: Орлова Александра, Попова Света, Крылов Виктор
→ добавлены правилом: Попова Света, Крылов Виктор
```

### Почему педагог обязателен, а режиссёр нет

Тренинг без педагога — это не тренинг, а сбор: теряется смысл события.
Репетиция без режиссёра возможна: актёры отрабатывают сцены самостоятельно.
Правило заложено в код, а не в голову организатора — иначе про него забудут.

## 3. Что появилось в API

| Метод | Что делает |
|---|---|
| `POST /tools/events/preview` | принимает `chosen: {"витя": 16}`; возвращает `ambiguity`, `staff_required`, `staff_optional` |
| `POST /tools/events/choose` | `{proposal_id, participant_id}` — уточняет, кто из тёзок, и пересобирает карточку |

Ошибка `ambiguous_names` блокирует назначение: пока не выбрали человека,
событие создать нельзя. Предупреждение при этом остаётся читаемым — в нём
перечислены варианты.

## 5. Что осталось

| Задача | Почему не сейчас |
|---|---|
| Чекбоксы в форме Mini App | интерфейс поиска окон — следующий шаг; API уже отдаёт список вариантов |
| Несколько неоднозначностей в одной фразе | поддержано структурно (`chosen` — словарь), но интерфейс спросит по одному |
| Свои инструкции и интерфейсы для педагогов и режиссёра | заказчик: «заложим на потом, прежде чем пускать в прод» |
| Замещение педагога (болезнь, отпуск) | нужна таблица замещений; пока правило жёсткое |
| Учёт занятости педагога в поиске окон | педагоги уже в `availability_hour`, отдельной логики не требует |
