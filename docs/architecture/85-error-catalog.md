Дата: 31.10.2026. Контракт для клиентов `tool-api` (гейтвей, Mini App, скрипты).
Введён вместе с единым конвертом ошибок (`services/tool-api/app/errors.py`, docs/reports/84).

**Что здесь контракт, а что нет.** `code`, `status`, `retryable` — стабильны, по ним можно
ветвиться. `title` и `detail` — человеческий текст, он может меняться без предупреждения;
показывать его пользователю можно, разбирать кодом — нельзя.

## 1. Конверт

Любая ошибка (4xx и 5xx) приходит одним телом, медиатип `application/problem+json`:

```json
{
  "type": "https://svoi.local/errors/slot_taken",
  "title": "Конфликт состояния",
  "status": 409,
  "detail": "slot_taken",
  "instance": "/tools/events/assign",
  "code": "slot_taken",
  "retryable": false,
  "request_id": "4fa789adc68d43bb86c857fb7fe2cd87",
  "ok": false
}
```

Правила:

1. `status` — по смыслу; тело ошибки не приходит с `200` (исключение — переходный период
   для `/webapp/auth`, см. §5).
2. `request_id` дублируется в заголовке `X-Request-ID` на всех ответах, включая успешные.
   Клиент может прислать свой `X-Request-ID` — сервер примет его, если он формата
   `[A-Za-z0-9._-]{8,64}`, иначе выдаст новый. Этот id пишется в лог при 5xx.
3. `retryable` — можно ли повторять запрос без изменений. Для 429 и 503 сервер также
   отдаёт `Retry-After`.
4. Валидация pydantic: `code = validation_failed`, `detail` и `errors` — список
   `{loc, msg, type}` (так было и раньше, клиенты читают `detail`).
5. 5xx не раскрывают внутренний текст: клиенту — `internal_error`, текст исключения — в лог.

## 3. Коды 5xx и служебные

| Код | HTTP | Когда | Повторять |
|---|---|---|---|
| `internal_error` | 500 | необработанное исключение; текст — только в логе | да, но сначала сообщить `request_id` |
| `llm_error` | 502 | LLM-провайдер вернул ошибку | да, после `Retry-After` |
| `llm_unavailable` | 503 | LLM не настроен или недоступен | да, после `Retry-After`; если не помогает — к администратору |
| `upstream_unavailable` | 502/503 | недоступен внешний сервис (календарь, Google, LLM) | да, после `Retry-After` |
| `validation_failed` | 422 | вход не прошёл pydantic | нет |
| `invalid_value` | 422 | кривая дата/число в запросе | нет |
| `http_error` | 4xx/5xx | HTTPException с нестроковым `detail` | по статусу |
| `method_not_allowed` | 405 | метод не поддержан | нет |

`retryable = true` для 408, 425, 429, 502, 503, 504; для остальных — `false`.

## 4. Где коды живут в коде

| Источник | Как получается код |
|---|---|
| `raise HTTPException(status, "slot_taken")` | из текста до `:` (`code_of`) |
| `raise HTTPException(status, "bad service token")` | таблица `CODE_ALIASES` |
| `raise ApiError(status, str(exc), code="init_data_invalid")` | явный код |
| `ValueError` | `invalid_value` |
| `RequestValidationError` | `validation_failed` |

падает, если `raise` в `main.py` даёт код, которого здесь нет.

## 5. Частичный успех: `200` с ошибкой внутри

Тринадцать маршрутов отвечают `200`, даже когда операция выполнена не полностью или
диалог ждёт следующего шага. Это **не транспортная ошибка**: статус говорит «сервер жив,
запрос понят», а результат — в теле. Клиент обязан смотреть `ok` и поля, а не только статус.
В OpenAPI такие методы помечены `x-partial-success` с пояснением.

| Маршрут | Что значит `200` с ошибкой | Поле |
|---|---|---|
| `POST /tools/route` | модель не ответила или текст пуст — gateway уходит в кнопки | `ok`, `error` |
| `POST /tools/participants/register` | шаг диалога: `need_name`, `already_registered`, `code_not_found/expired/exhausted` | `status`, `error` |
| `POST /tools/participants/check_code` | код не подошёл — ответ диалога | `error` |
| `POST /tools/participants/attach` | привязка не удалась | `error` |
| `POST /tools/events/preview` | проверка карточки не прошла | `errors`, `ok:false` |
| `POST /tools/profile/intro-parse` | ввод не разобран | `error` |
| `POST /tools/budget/sheet-retry` | часть строк не дописана | `failed`, `remaining` |
| `POST /tools/availability/template/from-week` | нет отмеченных дней | `error` |
| `POST /webapp/availability/template/from-week` | нет отмеченных дней | `error` |
| `GET /tools/availability/sheet/mismatches` | в листе есть расхождения | данные |
| `POST /tools/availability/reconcile` | правки не применены | `applied`, `mismatches` |
| `GET /tools/calendar/health` | часть календарей не настроена | `calendars[*].ok` |
| `GET /tools/calendar/events` | календарь недоступен | `error` |

Правило для нового маршрута: если операция уже что-то записала, а внешний сервис подвёл —
это `200` с полем ошибки, а не `5xx`. Если не записано ничего и это не шаг диалога — `4xx/5xx`
с конвертом из §1.
