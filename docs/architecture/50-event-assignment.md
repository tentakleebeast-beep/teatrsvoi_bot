# 50. Назначение события: шаг, которого не было

Дата: 27.10.2026. Найден на чекпоинте `docs/reports/49`: процесс не замыкается.
Поиск окон работает, но между «нашёл окно» и «люди знают» — пустота.

---

## 1. Дыра в процессе

```
заполнение занятости → свод в БД → поиск окон → [?] → событие в календаре → уведомления
```

На месте `[?]` сейчас человек: организатор получает список окон и дальше вручную
создаёт событие в календаре, вручную пишет в расписание, вручную напоминает людям.

Почему это плохо:

1. **Теряется связь.** Событие, созданное руками, не содержит `svoi_participant_ids` —
   значит при следующем поиске окон оно никого не блокирует (см. `docs/architecture/45`).
   Один пропущенный шаг ломает всю цепочку занятости.
2. **Двойной ввод.** Одно и то же событие вводится в двух местах.
3. **Забывается уведомление.** Люди узнают о репетиции из разговора, а не от бота.

---

## 2. Что должно происходить

### Шаг 1. Выбор окна

После ответа на «найди окна» под каждым вариантом — кнопка **«Назначить»**.

```
пт 06.11 18:00–21:00 (3 ч)
[Назначить] [Другое время]
```

### Шаг 2. Карточка события

```
Репетиция — Жизнь насекомых
пятница, 6 ноября, 18:00–21:00
Участники: Орлова Александра, Новиков Виктор
Помещение: Сцена
[Подтвердить] [Изменить время] [Отмена]
```

Поля по умолчанию: тип — `rehearsal`, название — из запроса или проекта,
участники — те, для кого искали, помещение — сцена.

### Шаг 3. Проверка перед записью

Повторно проверяем, что окно ещё свободно: между поиском и подтверждением
могли пройти минуты, и событие могло появиться.

| Что проверяем | Если занято |
|---|---|
| занятость участников | предупреждение, но запись разрешена — решает человек |
| событие в календаре на это время | отказ `slot_taken` с ближайшими свободными |
| зал (для аренды) | отказ с объяснением |

### Шаг 4. Запись

1. Запись в расписание — `POST /tools/events/assign`: `event_plan`, а затем событие
   в календарь с `svoi_kind`, `svoi_project_id`, `svoi_participant_ids`, `svoi_venue`,
   `colorId` по палитре (бывший `POST /tools/calendar/event` удалён, Ш-06).
2. Ссылка на `gcal_event_id` в `event_plan` — календарь правится по ней.
3. Аудит: кто, когда, из какого окна.

### Шаг 5. Уведомление

Каждому участнику — запись в `notification` (очередь уже есть, `docs/infrastructure/36`):

```
Вам назначена репетиция «Жизнь насекомых»
пятница, 6 ноября, 18:00–21:00
Сцена. Начало через 2 дня.
```

Правила: тихие часы 20:00–08:00, лимит 3/час, дедупликация по `dedupe_key`
(`event:<id>:<participant>:<offset>`). Напоминание за день — отдельная запись
с другим ключом.

## 3. Требования

| ID | Требование |
|---|---|
| FR-H10 | Кнопка «Назначить» под каждым найденным окном |
| FR-H10a | Карточка события с типом, названием, датой, временем, участниками, помещением |
| FR-H10b | Повторная проверка окна перед записью, отказ `slot_taken` |
| FR-H10c | Событие пишется в календарь с `svoi_*` свойствами и в `event_plan` |
| FR-H10d | Чужое окно не назначается: право `schedule.write` |
| FR-H11 | Участники получают уведомление через очередь, без дублей |

## 4. Права

| Действие | Кто |
|---|---|
| искать окна | `schedule.read.all` |
| назначать событие | `schedule.write` (org, admin) |
| менять чужое событие | `schedule.write` (разделение «своё/чужое» — будущая работа) |
| отменять событие | автор или admin |

## 6. Оценка

| Шаг | Время |
|---|---|
| Кнопки и карточка в gateway | 2 часа |
| `POST /tools/events` (событие + `event_plan` + уведомления) | 3 часа |
| Проверка занятости перед записью | 1 час |
| Тесты (6–8 штук, включая полный путь) | 2 часа |

Итого — примерно день. Это следующий шаг после переделки листа занятости.

## 7. Открытые вопросы

1. **Нужно ли писать событие в боевой календарь сразу** или сначала в черновой?
   Сейчас всё пишется в черновой (`CALENDAR_ID_DRAFT`) — безопасно для обкатки,
   но люди смотрят боевой. Решение: на бете — черновой, после релиза — боевой,
   переключатель в `.env`.
2. **Кто получает уведомление, кроме участников?** Организатору — подтверждение,
   админу — сводка за день. Пока только участники.
3. **Что если участник не зарегистрирован в боте?** Сейчас `pending`-люди есть.
   Уведомление ставится в очередь, но не доставляется. Нужен список «кому не ушло»
   для организатора.
