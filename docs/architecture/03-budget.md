# 03. Бюджет: регламент разбора и работа с файлом

Исходные условия: платёжных интеграций нет; бюджет ведётся человеком вручную в файле; бот должен принимать сообщения вида «расход 3000 на фотосъёмку Зайцева», применять регламент и сам формировать запись о транзакции, а также уважать ручные правки в файле.

---

## 1. Что где лежит

Google Sheets, один файл `Бюджет театра`, доступ через service account.

| Лист | Пишет бот | Назначение |
|---|---|---|
| `Транзакции` | ✅ да (append + правка своих строк) | журнал операций, единственный источник истины |
| `Справочники` | 🟢 читает | категории, проекты, контрагенты, участники |
| `Взносы` | ✅ да (отметка оплаты) | начисления и оплаты студийцев |
| `Свод` | ➖ **никогда** | формулы, читаются только значения (`valueRenderOption=UNFORMATTED_VALUE`) |
| `Ручные заметки` | ➖ никогда | произвольный текст человека |

Жёсткое правило: бот пишет **только** в `Транзакции` и `Взносы`, и только в строки/колонки, которые создал сам либо которые описаны контрактом листа. Лист `Свод` не трогается никогда — иначе сломаются формулы.

### Колонки `Транзакции` (контракт; первая строка — заголовки)

| Кол. | Поле | Кто заполняет |
|---|---|---|
| A | `tx_id` | бот (у ручных строк — пусто) |
| B | `Дата` | бот / человек |
| C | `Тип` | `расход` \| `доход` \| `перевод` |
| D | `Сумма` | бот / человек |
| E | `Категория` | бот (по регламенту) |
| F | `Проект` | бот / человек |
| G | `Контрагент` | бот / человек |
| H | `Назначение` | бот (из текста) |
| I | `Способ` | `наличные` \| `карта` \| `перевод` \| пусто |
| J | `Кто внёс` | бот (`Имя (бот)`), человек — руками |
| K | `Основание` | бот: ссылка на сообщение `tg://…` |
| L | `Ревизия` | бот: 1, 2, 3… |
| M | `Статус` | `подтверждено` \| `отменено` |

Новые колонки человек может добавлять правее M — бот их не читает и не перезаписывает. Если человек меняет **порядок** первых 13 колонок — это ломает контракт: при старте бот сверяет заголовки и при расхождении пишет админу, не записывая ничего.

## 2. Регламент разбора сообщения (конвейер)

```
текст → нормализация → извлечение слотов → правила регламента → проверка суммы/категории
      → черновик → [подтверждение?] → запись в Sheets → audit → ответ
```

### 2.1 Обязательные слоты

| Слот | Обязателен | Дефолт | Пример |
|---|---|---|---|
| тип | да | — | «расход», «потратили», «заплатили», «приход», «взнос» |
| сумма | да | — | «3000», «3 000 ₽», «3к», «1,5 тыс» |
| назначение | да (может быть = контрагент) | — | «фотосъёмка» |
| дата | нет | сегодня | «вчера», «12.10», «за прошлую пятницу» |
| категория | нет | по словарю | из `budget-rules.yaml` |
| проект | нет | «общий» | «Гамлет», «курс-осень» |
| контрагент | нет | из назначения | «Зайцев» |
| способ | нет | `unknown` | «налом», «с карты» |
| кто внёс | да | автор сообщения | — |

### 2.2 Правила (приоритет сверху вниз)

1. **Тип определяется глаголом/словом-маркером**, а не знаком суммы. «Отдали 3000», «оплатили», «купили» → расход. «Пришло», «поступило», «сдали взнос» → доход. «Перевели с карты на карту» → перевод.
2. **Категория берётся из словаря синонимов** (`budget-rules.yaml`). Совпадение по нормализованной строке, затем по подстроке, затем по стеммингу. Побеждает самое длинное совпадение.
3. **Если категория не найдена** — `категория = "прочее"` **и** обязательное подтверждение у автора: «Отнести к „прочее“ или укажите категорию?» с кнопками 5 самых частых.
4. **Если найдено 2+ равнозначных совпадения** («ремонт костюмов» → *костюмы* / *ремонт помещения*) — один уточняющий вопрос, показываем варианты кнопками.
5. **Сумма любая** — крупная пишется так же, как мелкая, прямо в файл: второго подтверждения
   нет, порог `confirm_above` из проекта убран 30.10.2026 (`docs/architecture/25` §4).
6. **Сумма отсутствует или непарсируема** — не пишем ничего, спрашиваем сумму. Никогда не угадывать.
7. **Дата в будущем** или **старше 12 месяцев** — предупреждение и подтверждение.
8. **Дубль**: та же сумма + категория + назначение за последние 10 минут → «Похоже, это уже записано… Всё равно записать?».
9. **Два и более факта в одном сообщении** («аренда 40к и реквизит 5к») → разбивается на две записи, показываются обе в одном черновике.
10. **Вопрос вместо факта** («сколько мы потратили на фото?») → это не запись, а запрос чтения (см. §5).

### 2.3 Формат подтверждения (всегда перед записью)

```
Записываю расход:
  Сумма:      3 000 ₽
  Назначение: Фотосъёмка (Зайцев)
  Категория:  Фото/видео
  Дата:       25.10.2026
  Проект:     общий

[Записать]  [Изменить]  [Отмена]
```

Прежняя настройка «писать без подтверждения» отклонена: цена ошибки в деньгах выше, чем экономия одного тапа. Подтверждение убирается **только** для сверхуверенных кейсов: сумма есть, категория найдена однозначно, период — сегодня, автор — `org`. И даже тогда в ответе остаётся кнопка «Отменить» на 15 минут.

## 3. Запись в файл: как не сломать ручные правки

Алгоритм записи (выполняет `tool-api`, не n8n и не LLM):

1. `values.get` диапазона `Транзакции!A1:M{last}` — читаем актуальное состояние (никакого кэша строк).
2. Сверяем `header_checksum` с ожидаемым. Не совпал → стоп, алерт админу.
3. Проверяем уникальность `(source_chat_id, source_message_id)` и `tx_id` → нет дубля.
4. `values.append` в конец листа (`insertDataOption=INSERT_ROWS`, чтобы не перетереть ручную строку, вставленную внизу).
5. Перечитываем добавленную строку, сохраняем `sheet_row`, `checksum`.
6. `audit_event(action='budget.tx.create', after=строка)`, `tool_call_log`.
7. Ответ: «Записал: 3 000 ₽, Фото/видео, строка 214».

### Ручные правки (главное требование заказчика)

| Сценарий | Поведение |
|---|---|
| Человек исправил сумму в строке бота | Ночная реконсиляция видит расхождение `value_mismatch`, обновляет зеркало, пишет `budget_recon`. Бот **не перезаписывает** — правка человека приоритетна |
| Человек отменил строку бота («Статус=отменено») | Бот читает статус при следующем обращении, помечает `reversed` в зеркале |
| Человек удалил строку бота | Реконсиляция: `row_only_in_db` → строка помечается `rejected`, в счётчики не входит |
| Человек добавил строку руками | `row_only_in_sheet`, `origin='manual'`, индексируется, попадает в отчёты |
| Человек изменил лист `Свод` | Не наше дело: не читаем и не пишем |
| Человек вставил строку в середину | Наши ссылки всегда по `tx_id`, а не по индексу → ничего не рвётся |

Реконсиляция — джоба `budget.reconcile` раз в сутки + по требованию `/sync`. После конфликта бот всегда пишет админу одну строку-сводку, а не молчит.

### Отмена и исправление

Запись бота не редактируется на месте: создаётся новая строка `ревизия=2`, `статус` старой → `отменено`, в `Основании` ссылка на исходную. Ответ: «Исправил: было 3 000 → стало 3 500, строка 215».

## 4. Взносы

- Лист `Взносы`: `Участник | Период | Начислено | Оплачено | Дата | tx_id | Статус`.
- Сообщение «сдал взнос за октябрь 5000» → запись дохода в `Транзакции` (категория «Взносы студийцев») + обновление строки в `Взносы`.
- Задолженность не хранится как число — она **вычисляется**: `Σ начислено − Σ оплачено` по периодам. Так ручные правки в файле сразу отражаются в ответах.
- Персональные суммы видит только сам участник и `org`/`admin` (см. матрицу).

## 5. Чтение и аналитика

Все ответы — из файла либо из зеркала с явным `source`.

| Запрос | Что делает `tool-api` |
|---|---|
| «сколько потратили на фото за 3 месяца» | агрегат по `Транзакции` с фильтром категория+период, `origin` любой |
| «сколько у нас денег» | читает `Свод`, конкретную ячейку по имени метрики — **если** метрики нет, честно: «в своде нет такой строки» |
| «кто должен за октябрь» | вычисление по `Взносы` |
| «покажи последние 10 операций» | хвост журнала |
| «сколько потратили на Гамлета» | фильтр по проекту |

Формат ответа всегда содержит источник: `Источник: Транзакции, строки 180–214, прочитано 25.10.2026 14:02`.

---

## 6. Границы (что бот не делает)

- Не редактирует `Свод` и формулы.
- Не удаляет строки из листа (только помечает статус).
- Не угадывает суммы, категории и даты — при нехватке данных задаёт вопрос.
- Не читает банковские выписки (следующий этап).
- Не считает налоги/зарплату — только учёт по факту.
