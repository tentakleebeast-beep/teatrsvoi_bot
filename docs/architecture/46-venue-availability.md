# 46. Занятость зала и аренда

Дата: 27.10.2026. Продолжение `docs/architecture/45`: события занимают людей, а зал занимается
событиями. Для аренды это единственное, что важно.

---

## 1. Зачем отдельный расчёт

Аренда — единственный случай, где люди не главное. Зал сдаётся независимо от того,
кто из труппы занят, а иногда наоборот: зал свободен, но нужен свой администратор.

| Вид аренды | Что проверяем |
|---|---|
| Самостоятельный арендатор | только зал |
| Аренда с персоналом (сопровождение, администратор) | зал **и** эти люди |

Раньше аренда была «слепой»: бот отдавал любое окно 08:00–10:00, потому что
занятости зала у него не было вовсе.

---

## 2. Откуда берётся занятость зала

`freebusy` — единственный подходящий инструмент Google Calendar: он отдаёт
занятые интервалы календаря, не раскрывая содержимого событий.

```
POST /freebusy  {timeMin, timeMax, items: [{id: CALENDAR_ID_VENUE}]}
→ {"calendars": {"<id>": {"busy": [{start, end}, ...]}}}
```

Календарь зала задаётся в `.env`:

```env
# если не задан — используется CALENDAR_ID_READ (боевой календарь студии)
CALENDAR_ID_VENUE=
```

По умолчанию пусто: в боевом календаре уже есть аренды, показы и репетиции,
то есть он и есть календарь зала. Отдельный id понадобится, если появится
второй зал или площадка.

---

## 3. Правила расчёта

`app/venue.py`, чистые функции:

1. **Склейка интервалов.** 12:00–14:00 и 13:00–15:00 → 12:00–15:00. Иначе
   между ними нашлось бы «окно» в 14:00–15:00.
2. **Час занят, если пересекается частично.** Аренда 19:30–20:30 занимает
   часы 19 и 20. Округление в пользу безопасности — как в событиях.
3. **Границы дня** 08:00–23:00, как у людей: ночью зал не сдаём.
4. **Минимальная длина** — из запроса (`min_hours`).
5. **Пересечение с людьми.** Если нужен персонал, окна зала пересекаются
   с окнами этих людей: годится только то, где свободно и то и другое.

---

## 4. Что возвращается

Аренда без персонала:

```json
{
  "mode": "venue",
  "policy": "rental",
  "windows": [{"day": "2026-12-22", "from_hour": 8, "to_hour": 12, "hours": 4}],
  "text": ["вт 22.12 08:00–12:00 (4 ч)"],
  "venue": {"calendar": "venue-1", "busy": 1, "applied": true}
}
```

Аренда с персоналом — то же, но `policy: "rental_staff"` и окна уже пересечены
со свободным временем людей.

В боте к ответу добавляется строка:

```
Зал проверен по календарю: занятых интервалов 1.
```

или, если календарь не подключён:

```
Календарь зала не подключён — свободное время нужно сверить вручную.
```

---

## 5. Деградация

| Ситуация | Поведение |
|---|---|
| `CALENDAR_ID_VENUE` пуст | используется `CALENDAR_ID_READ` |
| Оба пусты | аренда без проверки зала, честное предупреждение |
| freebusy вернул ошибку | `venue.applied = false`, поиск продолжается |
| Зал занят весь день | пустой список окон, а не «любое время» |

Ошибка календаря не должна превращаться в «зал свободен» — это самый опасный
вид тихой ошибки: арендатору пообещали зал, а там показ.

## 6. Тесты

`tests/unit/test_venue.py` — 9 тестов: разбор ответа freebusy, ошибка календаря
(= нет данных), склейка пересекающихся интервалов, окна между занятостью,
минимальная длина, занятый весь день, частичный час, пересечение с людьми,
пустое пересечение.

`tests/integration/test_venue_api.py` — 3 теста: аренда без персонала = окна зала,
аренда с персоналом учитывает и зал и людей, без freebusy аренда работает
как раньше.

Всего 12 тестов.

---

## 7. Что осталось

| Задача | Почему не сейчас |
|---|---|
| Второй зал / площадка | нужен отдельный календарь на каждый зал и выбор зала в запросе |
| Учёт буферов между арендами (уборка, перестановка) | нужно поле «буфер» у зала: 15–30 минут |
| Запись аренды в календарь одной командой | после появления формы аренды в Mini App |
| Цена аренды и доход | бюджет уже умеет, но связки «событие → операция» нет |
| Проверка пересечения с показами студии | сейчас показы и аренды лежат в одном календаре и уже мешают друг другу — это работает |

## 8. Как проверить руками

```bash
# аренда на неделю: должны прийти окна, где зал свободен
curl -s -X POST http://127.0.0.1:8000/tools/schedule/slots \
  -H "Authorization: Bearer $TOOL_API_TOKEN" \
  -H "X-Actor-Chat-Id: $ADMIN_CHAT_ID" \
  -H 'Content-Type: application/json' \
  -d '{"policy":"rental","date_from":"2026-11-02","date_to":"2026-11-08","min_hours":3}' \
  | python3 -m json.tool | head -30
```

В ответе смотреть `venue.applied` — если `false`, календарь зала не подключён
и окна не проверены.
