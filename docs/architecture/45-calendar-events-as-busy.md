# 45. События календаря как занятость

Дата: 27.10.2026. Закрывает разрыв из `docs/infrastructure/44` §4.1: раньше показ в календаре
не мешал боту предлагать репетицию на тот же вечер. Теперь мешает.

---

## 1. Проблема

До этого занятость жила в двух несвязанных местах:

```
availability_hour (БД)   — «могу / не могу» по часам
Google Calendar          — «показ 5 декабря, заняты Орлова и Новиков»
```

Поиск окон смотрел только в базу. Человек мог не отметить занятость, а событие
в календаре было — и бот предлагал невозможное время.

---

## 2. Мост: `extendedProperties`

Календарь не умеет хранить «кто занят» — `attendees` работает по email, а у нас
люди из Telegram. Единственное место для машинных данных — `extendedProperties.private`.

Соглашение (контракт):

| Ключ | Значение | Пример |
|---|---|---|
| `svoi_kind` | тип события | `show` |
| `svoi_project_id` | спектакль | `3` |
| `svoi_participant_ids` | кого занимает, через запятую | `12,16,30` |
| `source` | кто создал | `tool-api` |

Правило: **событие без `svoi_participant_ids` никого не блокирует.** Аренда
чужого мероприятия занимает зал, но не людей. Это то же разделение, что
в политиках окон (`docs/architecture/42` §10.3).

---

## 3. Как считается занятость

`app/calendar_blocks.py`:

```
событие 19:00–21:30 → часы 19, 20, 21
```

Час 21 включён, потому что в 21:00 человек ещё на показе. Округление всегда
**в пользу безопасности**: лучше не предложить окно, чем предложить невозможное.

| Случай | Поведение |
|---|---|
| Событие с участниками | часы вычитаются у этих людей |
| Событие без участников | никого не блокирует |
| Событие на весь день | блокирует часы 08:00–23:00 у участников |
| Событие после полуночи | часы после 00:00 не учитываются: рабочий диапазон 08–23 |
| Событие у человека без отметок | человек всё равно считается занятым в эти часы |

Последний пункт важен: люди не всегда заполняют занятость, но показ в календаре —
факт, а не отметка.

---

## 4. Деградация

Календарь — внешняя система, и он может быть недоступен. Правило разное для двух
областей (`docs/architecture/40` §4):

```
календарь недоступен → у людей поиск идёт по availability_hour (окна менее точные)
календарь недоступен → у аренды окон нет: «занятость зала неизвестна»
```

Для людей ошибка не роняет поиск, а пишется в лог и в `meta.events = 0`: отсутствие
событий лучше, чем отсутствие ответа. Для субаренды наоборот: «зал свободен» без
данных о зале — это утверждение, которого мы не можем сделать.

Отключить блокировку можно параметром `block_events=false` — нужно для отладки
и для случаев, когда календарь заведён с ошибками.

## 5. API

### Создание события с свойствами

Событие создаётся одним путём — `POST /tools/events/assign`, право `schedule.write`
(карточка назначения; чат и экран Mini App зовут его же). Бывший
`POST /tools/calendar/event` удалён как дубль (Ш-06).

```json
{
  "card": {
    "kind": "show",
    "title": "Жизнь насекомых",
    "date": "2026-12-20",
    "from_hour": 19,
    "to_hour": 22,
    "project_id": 3,
    "participants": [{"id": 12}, {"id": 16}],
    "venue": "stage"
  }
}
```

Что делает:

1. собирает название по маске: `Показ - Жизнь насекомых`;
2. ставит `colorId` по палитре (показ — 11, репетиция — 9, аренда — 10);
3. пишет `extendedProperties` с типом, проектом и людьми;
4. если конец выходит за полночь — обрезает до `23:55` (правило календаря);
5. проверяет тип и границы времени до записи (`unknown_kind`, `bad_time_range`);
6. пишет событие в черновой календарь, а при его отсутствии — только в расписание;
7. фиксирует действие в аудите (`event.assign`).

### Поиск окон

`POST /tools/schedule/slots` теперь принимает `block_events` (по умолчанию `true`)
и возвращает в `meta`:

```json
{"events": 12, "blocked_hours": 48}
```

`events` — сколько событий прочитано, `blocked_hours` — сколько часов занятости
добавлено из календаря.

## 7. Что это меняет в поведении

Было:

```
«найди окна для всех на неделю»
→ среда 19:00–22:00 — все свободны
(а в это время идёт показ, где заняты трое из десяти)
```

Стало:

```
«найди окна для всех на неделю»
→ четверг 18:00–21:00 — все свободны
(среда исключена: показ занимает троих)
```

## 9. Порядок работы с событиями

1. Событие создаётся ботом (`POST /tools/events/assign` — карточка назначения) или руками в календаре.
2. Если руками — нужно заполнить `extendedProperties`, иначе событие никого
   не блокирует. Это ограничение честнее, чем угадывать участников по названию.
3. Поиск окон читает события за запрошенный период и вычитает занятость.
4. Расхождений не сверяем: календарь — источник истины по событиям,
   `availability_hour` — по личной доступности.
